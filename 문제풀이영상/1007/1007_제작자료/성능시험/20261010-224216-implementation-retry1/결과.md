# 문제풀이 영상 렌더 설정 구현 검증

생산 render_master에 workers=2/6을 전달한 실제 P10.72 240.667초/7,220프레임 시험이다. HyperFrames 0.8.137, FFmpeg 9.0.2, 현재 Apple M5/10코어/16GiB 환경을 사용했다.

| 범위 | 작업자 2 | 작업자 6 | 시간 감소 |
|---|---:|---:|---:|
| 사전 check와 PCM mux/마스터 검사 포함 | 263.67초 | 155.39초 | 41.1% |
| 파트 렌더 + 규격 검사 | 200.18초 | 105.07초 | 47.5% |

모두 CPU 인코딩/브라우저 GPU auto/fast_capture=false이며 로그에서 screenshot 캡처와 실제 workerCount=2/6을 확인했다. 두 마스터 MP4 SHA256은 a029a69b505a24924ddd9d1ea336a85620dd2aa4b9eae7374d4260339794ac7b로 같다. 전체 framemd5 7,220개, narration.wav, 복사한 AAC 데이터가 일치했다. 1920×1080/30fps, mono 24kHz를 확인했고 시험 전후 동결 파일 86개 해시가 모두 그대로다. result.json, source-hashes-before/after.json, workers-N.framemd5와 각 RUN의 verification/render-receipt.json에 증거가 있다.

기존 RUN 경로가 동시 체크아웃 변경 후 없어져 Git eeec3d5에서 기존 기록의 67개 파일 해시와 audio.json에 기록된 WAV 19개 해시를 대조해 scratch로 복원했다. 첫 시험의 WAV 누락 오류는 렌더 전에 발생했으며 앞선 시험 폴더의 failed-attempt.log에 보존했다. 원본 체크아웃/기존 완성 영상을 복원하거나 수정하지 않았다.

최종 회귀: 전체 Python 209개 실행, 3개 명시적 opt-in skip, 실패 0. 미디어 회귀 15/15, Node 동작 5/5. 실제 성능 수용검사는 3/3(실제 렌더 포함) 통과했다. 유료 요청과 게시 0. 사전/전체 디코드 검증 시간은 렌더 성능 수치에 포함시키지 않은 경우를 표에서 구분했다. 렌더러 내부 check는 첫 행에 포함하며 전체 framemd5 생성은 두 행 모두 제외한다. 단일 문항에서 각 설정 한 번씩 재확인한 결과이며 다른 기기/문항/부하로 일반화하지 않는다. 기술 검증이고 새 교육 의미/실제 음성 청취 승인이나 게시가 아니다.

독립 리뷰에서 복구 실패 또는 Ctrl+C 때 복구 사본이 삭제되는 오류를 발견했다. 실제 파일 교체 fault test 세 개를 RED→GREEN으로 수정하고, 복구 불가 시 사본 보존/경로 안내 및 재시도 덮어쓰기 차단을 추가했다. 수정 후 전체 회귀검사 209개가 실패 없이 완료됐다(3개 명시적 opt-in skip). 렌더 실측은 교체 실패 처리 보완 전이며, 정상 교체는 수정 후 15개 미디어 회귀검사로 재확인했다. 이 수정은 캡처·인코딩·PCM 생성 설정을 바꾸지 않는다.
