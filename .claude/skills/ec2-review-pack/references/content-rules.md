# 섹션 작성 규칙

## 작성자 브리프 (메인 에이전트가 섹션마다 1명, 병렬, model: opus / lite: sonnet; GPT에서는 sol / luna)

---
전자회로2 정리노트의 섹션 `<sid>`(`<섹션 title>`)를 쓴다.

- 개인 명세(필수 읽기): `<REPO>/docs/learning/solution-style.md`의 현재 바이트와 `<RUN>/manifest.json`의 `learning_style` snapshot(path·sha256·rule_ids). 메인이 실제 REPO 절대 경로로 채운다. 이 명세는 설명 순서·표기를 정하고, 원문 조건과 회로 정확성은 자료로 확인한다.
- 회로 계약: 개인 명세 `CIRCUIT-02`를 읽고 측정 조건 → 단순화 근거 → 노드 관계 → 첫 식을 보인다. $G_m$은 출력 단락선·접지·전류 방향, $R_{out}$은 입력 영점·출력 시험원을 실제 그림에 넣는다. 입력은 왼쪽, 축퇴 저항은 이미터/소스 노드 아래에 두고 병렬쌍은 전류원 왼쪽/$r_o$ 오른쪽으로 둔다. 노드 관계는 선택 모델에서 유도하고 생략 가지와 근사 조건을 붙인다. 유한 β·$r_o$가 필요하면 유지한다. formal에서 선택 모델의 상세 유도를 보존하고 모델 차이를 설명한다. $R_{out}$ 정확 전체 모델은 아래 예외가 아니면 내부 검산에만 둔다. why-circuit에는 기존대로 소신호 회로를 넣지 않는다.
- 출력 배치 필수: 입력은 왼쪽, 출력 단자·출력 라벨·출력 시험원/단락 접속은 오른쪽에 둔다. 회로로 유입하는 시험전류는 오른쪽에서 왼쪽으로 그리며, 내부 제어 전류원의 방향·전압 극성·실제 접속은 유지한다. 전기적으로 같은 노드라는 이유로 출력 접속을 왼쪽이나 중앙에 두지 않는다. 핵심·상세·HTML·PDF에서 각각 확인한다.
- 병렬 가지 순서 필수: 제어 전류원과 $r_o$가 병렬이면 반드시 **제어 전류원 왼쪽 → $r_o$ 또는 병렬 합성 저항 오른쪽 → 출력 접속 맨 오른쪽** 순서로 그린다. 입력은 그 왼쪽, 이미터/소스 축퇴 저항은 해당 노드 아래에 둔다. $r_o$를 생략한 축약 모델에는 없는 저항을 추가하지 않는다. 그 모델의 제어원 위치를 병렬쌍의 배치 규칙으로 일반화하지 않는다. 핵심·상세의 모든 SVG와 답안 PDF에서 소자·단자 전체 배치를 대조하고, 전기적 등가성만으로 위치 불일치를 승인하지 않는다.
- 노드 점과 시험 표기 필수: 접지 표기만 하는 비분기 단자와 접지 기호의 직접 접속점을 제외하고, 입력·출력·시험 노드와 이름을 붙인 전압 노드에는 연결 위치가 분명한 눈에 보이는 점을 찍는다. 출력 시험전압 노드의 점은 출력 도선의 실제 맨 끝이자 가장 오른쪽 단자에 둔다. 점 오른쪽으로 도선(ink)이 더 이어지거나 연장된 도선 중간에 점이 놓이면 안 된다. 시험 노드 전압 $V_t(+)$는 그 끝점 위에 둔다. 유입 시험전류는 오른쪽에서 왼쪽으로 흐르며, 왼쪽을 향하는 $i_t$ 화살표는 $V_t$ 점 왼쪽의 도선 구간에 둔다. $i_t$ 라벨도 점 왼쪽에서 그 화살표 아래나 곁에 둔다. 화살표 전체가 점 왼쪽에 머물고 점을 덮지 않도록 화살표 꼬리와 점 사이에 작은 간격을 남긴다. 화살표나 전류 라벨을 점 오른쪽에 놓지 않는다. 다른 시험 기호($v_x/i_x$ 등)를 쓰면 같은 배치와 정의를 적용한다. 선 교차만 있고 연결되지 않은 곳에는 점을 찍지 않는다. 라이트·다크 HTML과 실제 답안 PDF에서 점·라벨·화살표의 분리와 가시성을 각각 확인한다.
- 회로 안 글자와 점의 정돈: SVG 안에는 소자 이름·값·제어 전류원 라벨(예: $g_mv_\pi$), 노드 이름·극성·방향처럼 실제 회로를 읽는 표기를 남긴다. 분석용 $G_m$ 제목·측정 조건 문구·유도 설명은 그림 아래 figcaption이나 수식 문단에 둔다. 출력 단락·입력 영점의 실제 연결은 그림에 보존한다. 접지 입력 위의 독립 제목 `Rout`처럼 불필요한 제목은 옮겨 중복하지 않고 삭제한다. 가까운 노드 관계는 유도 설명이 아니고 겹치지 않을 때만 남길 수 있다. 접지 표기만 하는 비분기 단자·접지 기호의 직접 접속점은 제외하고 입력·출력·시험 단자, 이름 붙인 내부 전압 노드, 실제 분기 접속점의 점은 유지하되 이름도 분기도 없는 직선 도선 중간의 장식 점은 없앤다. 모든 도선에 점을 추가하라는 규칙이 아니다. $V_{out}(+)$·$V_t$ 등 라벨은 아래첨자까지 포함한 실제 글리프 경계상자가 도선에서 최소 0.6em(보통 화면에서 약 8px) 떨어지게 배치한다. 텍스트 기준선 간격만 확인하지 않는다. 필요하면 라벨을 옮기고 viewBox 위쪽 여백을 늘린다. 핵심·상세의 모든 SVG를 열거하여 라이트·다크 HTML과 실제 답안 PDF의 보통 보기 크기에서 이 간격·클리핑·겹침을 확인한다. 병렬 제어원 왼쪽/$r_o$ 오른쪽/출력 맨 오른쪽, 맨 끝 $V_t$ 점 오른쪽 도선 없음, 점 왼쪽의 왼쪽 방향 $i_t$와 라벨 배치도 유지한다.
- 접지·전압 라벨·노드 색 대응: 접지 기호에 직접 닿는 점과 접지만 표시하는 비분기 입력 단자의 점은 생략한다. 접지로 이어지는 회로라도 별도의 실제 분기 접속점·이름 있는 비접지 노드는 유지한다. $v_e$ 등 전압 이름은 다른 소자나 저항 옆으로 멀리 밀지 않고 해당 노드 바로 곁에 둔다. 아래첨자·극성을 포함한 실제 글리프 경계로 도선과 최소 0.6em 간격을 확보하면서 가능하면 0.6–1em 정도의 가까운 간격을 목표로 한다. 혼잡 때문에 더 벌리면 배치 이유를 검토에 기록한다. 노드 점과 해당 전압 이름·극성은 같은 파랑 또는 빨강으로 묶는다. 주요 신호 경로를 따라 파랑·빨강을 교대하고 가까운 전압 라벨끼리 최대한 다른 색을 쓴다. 같은 전기적 노드는 다른 위치의 점도 같은 색이며, 모든 인접 노드를 반대색으로 만드는 그래프 채색을 강제하지 않는다. 접지 표기·도선·소자/제어원 라벨·전류 화살표/라벨·본문 수식의 색은 이 노드 색 규칙으로 바꾸지 않는다. 색 없이도 노드 이름과 극성으로 구분되어야 한다. SVG에는 대응 노드 식별자와 색을 명시하고, HTML 테마와 PDF에서 실제 계산된 색이 파랑/빨강인지 확인한다. PDF의 문항 종류별 초록/주황 `--kind`를 노드 파랑의 대체값으로 사용하지 않는다. 모든 핵심·상세 SVG와 MD에 참조된 같은 그림, 라이트·다크 HTML 및 실제 답안 PDF에서 접지 점 생략·가까운 라벨·점/전압 색 일치를 검토한다.
- 출력저항 표시/검산 경계: $R_{out}$은 처음부터 유효한 근사식으로 시작하고 조건과 $\approx$를 유지한다. 이 규칙은 생성하는 핵심·상세(start/solve/verify·formal/보충 포함) HTML·요약·동반 MD·답안 PDF 모두에 적용한다. 정확식 → 근사식 유도나 정확식과 수치 비교를 학습 본문에 추가하지 않는다. 정확한 $R_{out}$의 전체 모델·유도·수치/극한 대조는 내부 독립 검산 evidence에만 둔다. 원문이 정확식·유한 β 전체 결과를 명시적으로 요구하거나 근사 조건이 성립하지 않으면 예외 이유를 짧게 밝히고 필요한 모델과 결과를 제시한다. 유한 β 또는 $r_o$가 있다는 사실만으로 예외를 선언하지 않는다. 이 제한은 $R_{out}$에 한정하며 다른 개념의 필요한 상세 유도를 줄이지 않는다.
- 첫 설명 계약: 회로 역할과 핵심 관계 → 작은 예시 → formal의 상세 정의·중간 식·유도. why·eli5·formal·prof·warn·supp·sum의 기존 범위와 상세 설명을 유지한다.
- 개인화 보고: 토픽 ID별 적용 규칙 ID와 HTML 위치·적용 내용, 비적용 규칙의 이유를 보고한다. 메인/리뷰어가 실제 의미 검토 후 감사에 기록한다.
- 읽기: `<SKILL>/references/content-rules.md`(이 파일 전체), 위젯이 있으면 `<SKILL>/references/widget-rules.md`
- 위젯: <위젯> (메인 에이전트가 정한 것만 만든다. "위젯 없음"이면 이 섹션에는 위젯을 넣지 않는다)
- 뒤 섹션 토픽: <뒤 섹션 토픽 id·제목 목록> (섹션 `why` 작성자에게만 채운다. 다른 섹션은 "해당 없음")
- 계약: `<RUN>/manifest.json`의 섹션 `<sid>` — 토픽 id·제목·`required_terms`·`layers`·`supp`가 정확히 여기 적힌 대로여야 한다.
- 링크: manifest `links` 중 `topic`이 이 섹션에 있는 항목 `<이 섹션의 links 목록>`을 모두 그 토픽 안에 `<a href="…">`로 넣는다. `href`는 글자 그대로 복사(`%20` 포함). 복습문제 PDF 링크만은 `{{PROBLEM_PDF}}`, `{{ANSWER_PDF}}`로 써도 된다(조립 뒤 실제 파일명이 되어 검사를 통과한다).
- 근거: `<RUN>/summaries/stt-*.md`(해당 날짜), `<RUN>/slides.txt`, 필요하면 Razavi `<RUN>/repo/교과서/마이크로전자회로/<N>장.pdf` <쪽>과 그 장 문제 md(`<RUN>/repo/교과서/마이크로전자회로/chNN/`, 수치·그림 확인용)
- 출력: `<RUN>/sections/<sid>.html` **한 파일만**. `<section>`/`<h2>`는 쓰지 않는다(조립기가 감싼다). 임시 파일은 아래 규칙.
- 임시·보조 파일(스크립트, 초안, 그림 생성 폴더)은 `<RUN>/work/` 아래에만 둔다. 저장소(`STT/`, `강의노트/`, `교과서/`, `복습노트/`)와 scratchpad 루트, `/tmp`에는 아무것도 쓰지 않는다. 한글(NFD) 파일명은 복사하거나 이름을 바꾸지 말고 Python `os.listdir` + `unicodedata.normalize('NFC', …)`로 찾아 그 경로로 연다.
- 자기 검사(끝내기 전): 토픽별로 `required_terms`가 모두 문자 그대로 들어갔는지, `$` 짝, `links` 항목이 해당 토픽 안에 있는지, 금지어 `<forbidden 목록>`이 없는지. 금지어는 예고 토픽 `<preview_topic>` 안에서만 허용된다 — 이 토픽에는 예고 제목을 빠뜨리지 말고 쓴다. eli5 레이어마다 문장 수(figcaption 포함)가 3 이하이고, 필요한 용어는 짧게 풀었는지 확인한다. 아래 "이해되는 설명의 순서"에 따라 첫 설명과 작은 예시만으로 다음 상태를 예측할 수 있는지 자기 검사한다. 긴 식·유도는 formal 레이어로 옮긴다. 조각 어디에도 이모지를 쓰지 않았는지. `layers`가 빈 목록이 아닌 토픽마다 마지막에 `<div class="sum" hidden>`이 있고, 그 식·용어가 본문과 같은 표기인지. 그림 설명(글, `aria-label`)이 SVG 클래스의 실제 모양(채움/윤곽)과 맞는지.

## 범위
- 요약의 슬라이드 대조표에서 "다룸/일부"인 내용만 쓴다. "예고만/안 다룸"은 `s<N>-next`에 제목만.
- 수업에서 말한 모든 개념, 칠판 유도, 교수님 비유와 강조 발언을 빠짐없이 싣는다(잡담 제외). 다만 $R_{out}$의 정확식 → 근사식 전개는 위 표시/검산 경계에 따라 내부 evidence에만 보존한다. 원문이 정확 결과를 명시적으로 요구하거나 근사가 성립하지 않을 때만 이유를 짧게 밝히고 필요한 결과를 싣는다.
- STT 오인식과 말실수는 올바른 형태로 쓴다. 식이 틀렸던 경우만 각주 한 줄로 "(수업 중 X로 적었다가 정정)".

## 토픽 마크업 (이 순서)
```html
<article class="topic" id="…"><h3>…</h3><div class="tags"><span class="tag date">MMDD 수업</span><span class="tag slide">L0X sN</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">무엇이 어떻게 바뀌는지 직접 말하는 한 문장</p> …그림… </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span> …정의·수식·단계별 유도(ol.steps)… </div>
  <div class="layer prof"><span class="layer-title">교수님 말씀</span> …비유·일화, 원문은 blockquote… </div>
  <div class="layer warn"><span class="layer-title">꼭 기억해요</span> …원문 인용 + (MMDD MM:SS)… </div>   ← 강조 발언이 있을 때만
  <div class="layer supp"><span class="badge supp">보충 · 수업에서 유도하진 않았어요</span> … </div>             ← manifest supp=true만
  <div class="sum" hidden>…페이지 요약(아래)…</div>                                                    ← layers가 빈 목록이 아닌 토픽만, 맨 끝
</article>
```
- 레이어 제목과 배지 글자는 위와 글자 그대로 쓴다. 이모지, 장식 기호(★, ↗ 같은 아이콘; 상태 변화의 순서를 나타내는 →는 허용), "아래를 보세요" 같은 안내 문장은 쓰지 않는다.
- 템플릿이 토픽 하나를 한 화면에 보여 준다. 토픽은 그것만 읽어도 이해되게 쓰고, "위에서 본 것처럼"처럼 앞 토픽의 위치에 기대는 말 대신 `<a href="#토픽id">토픽 제목</a>`으로 잇는다.
- 요약·예고 섹션: 치트시트는 표(`<div class="table-wrap"><table>`), 예고는 `<ul>`, 링크는 `<ul><li><a>`.
- 복습문제 PDF 링크는 `href="{{PROBLEM_PDF}}"`(문제), `href="{{ANSWER_PDF}}"`(답안)로 쓴다(조립기가 실제 파일명으로 바꾼다). 링크 글자는 "복습문제 N개 (PDF)", "답안 (PDF)"처럼 쓴다. 문제가 0개인 팩은 링크 대신 "이번 범위에는 workbook 문제가 없어요." 한 줄을 쓴다. 다른 링크는 manifest `href`를 글자 그대로.

## 왜 쓰는가 페이지 (`why-circuit`)
노트를 열면 표지 다음에 처음 보이는 화면이다. 이번 범위의 회로를 **왜 쓰는지**만 말하고, 자세한 내용은 뒤 토픽으로 보낸다.
- formal 레이어는 이 4단계를 순서대로 쓴다. 단계마다 그 내용을 자세히 다루는 뒤 토픽으로 `<a href="#토픽id">토픽 제목</a>`을 건다.
  1. **풀고 싶은 문제**: 무엇이 필요했나(예: 더 큰 이득, 잡음에 강한 입력).
  2. **단순한 해법과 그 한계**: 가장 쉬운 회로로 하면 어디서 막히나. 식은 1~2줄만.
  3. **핵심 아이디어**: 이번 회로가 그 한계를 넘는 방법 한 문장.
  4. **대가와 쓰이는 곳**: 무엇을 내주나(헤드룸, 소자 수, 전력 등), 실제로 어디에 쓰나.
- 범위에 회로가 여럿이면 회로마다 1~4를 짧게 반복하거나, 하나의 문제에서 다음 회로로 이어지는 흐름으로 쓴다. 한 토픽 안에 모두 담는다.
- 유도, `ol.steps`, 소신호 등가회로는 쓰지 않는다. 그건 링크한 토픽의 몫이다.
- eli5 레이어: 문제 → 단순한 해법의 한계 → 이번 회로로 이어지는 흐름도 SVG(id `fig-why`) 1개. 비유는 흐름을 이해하는 데 도움이 될 때만 쓴다.
- 근거 우선순위: 요약의 `## 동기 발언` > 강의 슬라이드 첫 장 > Razavi 장 도입부. 교수님 발언은 prof 레이어에, 수업에서 말하지 않은 동기는 supp 레이어(manifest `supp: true`)에 싣는다.
- 링크는 `<a href="#토픽id">`로 쓴다. 마크다운 `[글자](#id)`는 화면에 그대로 찍히므로 `check_html.py`와 `insert_why.py`가 막는다.
- 위젯과 `<script>`는 넣지 않는다. 맨 끝에 `.sum`을 둔다(아래).

## 페이지 요약 (`.sum`)
화면 오른쪽 "페이지 요약" 패널에 그 토픽의 핵심만 보여 준다. 템플릿이 토픽의 **직계 자식** `.sum`을 패널로 옮기므로 토픽 안 맨 끝에, 레이어 밖에 둔다. `hidden`은 꼭 붙인다(본문에 두 번 보이지 않게).
```html
<div class="sum" hidden>
  <p class="sum-lead">토픽 핵심 한 문장("~해요" 체)</p>
  <p class="panel-label">핵심 식</p>
  <ul class="eq-list"><li><span class="eq-name">식 이름</span>$$…$$</li></ul>
  <p class="panel-label">용어</p>
  <dl class="terms"><dt>용어(영어)</dt><dd>한 줄 뜻</dd></dl>
</div>
```
- 새 내용을 쓰지 않는다. 본문(formal 레이어)에 이미 나온 식·용어를 **같은 TeX 표기로** 필요한 만큼 고른다. 요약에만 있는 식이나 설명은 두지 않는다.
- 패널은 폭이 약 300px로 좁다. 분수·근호가 겹친 긴 식은 한 `$$`에 넣지 말고 `=`나 곱 앞에서 여러 `$$` 줄로 나눈다(같은 `<li>` 안, 예: `$$I_{D1}-I_{D2}$$` `$$=\tfrac12 k(V_{in1}-V_{in2})$$` `$$\times\sqrt{\dfrac{4I_{SS}}{k}-(V_{in1}-V_{in2})^2}$$`). 기호와 항은 본문과 같게 둔다. 넘치면 브라우저 검사의 `panelOverflow`가 잡는다.
- 식이 없는 토픽은 "핵심 식" 줄과 `eq-list`를 빼고, 용어가 없으면 "용어" 줄과 `dl`을 뺀다. `sum-lead`는 항상 쓴다.
- 요약·예고 섹션처럼 `layers`가 `[]`인 토픽에는 두지 않는다.

## 문체
- 쉽게 말하면(eli5): 짧고 직접적인 1~3문장(figcaption 포함) + 그림. 필요한 용어는 짧게 풀고, 작은 숫자·상태 변화 표기는 허용한다. 긴 식과 유도는 formal에 둔다. 토스처럼 짧고 다정한 "~해요" 체.
- 정확히 말하면(formal): 선택 모델과 조건 안에서 빠짐없이, 정확하게. $R_{out}$은 이 레이어에서도 유효한 근사식부터 시작하며 정확식 유도를 보충하지 않는다(위 예외 제외). 유도는 한 줄에 한 단계. 문장은 "~해요" 체, 유도 단계는 식 위주로 짧게.
- 교수님 말씀(prof)/꼭 기억해요(warn): 원문 인용은 15단어 안팎으로 줄이고 `(0914 26:00)`처럼 출처.
- UI 글은 한국어, 전문용어는 영어 병기(예: 출력저항(output resistance)). 한 문장에 한 가지만 말하고, 군더더기 수식어("아주", "정말", "한번")는 뺀다.

## 이해되는 설명의 순서
- 첫 설명은 **핵심 동작 → 작은 예시 → 이유·수식 유도** 순서로 쓴다. 비유는 선택 사항이며, 실제 값이나 상태 변화가 더 직접적이면 그것을 쓴다.
- 변화 규칙을 설명할 때는 **시작 상태 → 변화 규칙 → 결과**를 보여 준다. 예: 실수 pole을 지날 때마다 기존 기울기에 −20 dB/dec를 더하므로 0 → −20 → −40. 이득이 순간적으로 20 dB 떨어지는 것과 기울기가 바뀌는 것을 구별한다.
- 예시에는 단위·축·근사 조건을 붙인다. pole 예시는 평평한 저주파 이득에서 시작하는 저역통과 응답이고 관심 범위에 zero 영향이 없는 경우로 한정하며, 실제 곡선은 부드럽게 변한다는 점을 밝힌다.
- formal의 첫 부분에서 작은 예시를 실제로 적용한 뒤 유도한다. 그림의 라벨과 페이지 요약도 같은 규칙·순서를 보여 준다.
- 자기 검사: 첫 설명과 예시만 읽고 풀 수 있는 작은 적용 질문을 만들고 답·이유를 기록한다. 예: "두 번째 pole 뒤 −40일 때 세 번째 pole 뒤는?" → "−60 dB/dec: −40에 −20을 더함". 본문과 질문에 붙인 조건이 같은지도 확인한다. 이 기록은 작성자 보고에 포함한다.
- 순차적 예측 규칙이 없는 정의·구조 토픽은 구체적 사례를 하나 골라 정의가 어디에 해당하는지 설명하게 한다. 변화 단계를 억지로 만들지 않는다.

## 수식
- `$…$`(인라인), `$$…$$`(디스플레이)만. 본문에 리터럴 `$` 금지.
- TeX 안에 `<`, `>`, `&` 금지 → `\lt`, `\gt`. 정렬 환경 대신 `$$` 줄을 나눈다.
- 표기 고정(manifest `required_terms`와 같게): 트랜스컨덕턴스 `g_m`, 출력저항 `r_O`, 단의 출력저항 `R_{out}`, 전압 `V_{GS}`·`V_{DS}`·`V_{BE}`·`V_{CE}`, 이득 `A_v`, 병렬은 `\parallel`(`||`, `//` 금지).
- 근사는 `\approx`, 조건은 글로 쓴다(예: "$g_m r_O \gg 1$일 때").
- 소신호 유도는 "등가회로 → KCL/KVL 한 줄씩 → 결과" 순서로 `ol.steps`에 쓴다. $R_{out}$은 유효한 근사 모델·근사식에서 출발하며 정확식 → 근사식 전개는 위 예외가 아니면 내부 검산에만 둔다.

## SVG 그림
- 개념 토픽마다 eli5 레이어에 그림 1개 이상(흐름도, 막대, 곡선 등).
- `<figure class="figure"><svg id="fig-<kebab>" viewBox="…" role="img" aria-label="한국어 설명">…</svg><figcaption>…</figcaption></figure>`
- 색은 클래스로만: `fig-ink`, `fig-accent`, `fig-danger`, `fig-dot`, `fig-text`, `fig-muted`. 하드코딩 색 금지(다크모드).
- 채움과 윤곽: `fig-ink`, `fig-accent`, `fig-danger`는 선만 그린다(`fill:none`). 속이 칠해진 점·도형은 `fig-dot`(강조색 채움)뿐이다(`fig-text`, `fig-muted`는 글자용). 글·figcaption·`aria-label`에서 "색칠된", "채워진"은 `fig-dot` 도형에만 쓰고, 선만 있는 도형은 "테두리", "선"으로 부른다.
- 글자 12~14px, SVG `<text>`에 `$` 금지(Ω, ∥, ₁, ₘ 같은 유니코드).
- id는 페이지 전체에서 유일해야 한다(`fig-` + 토픽 고유 단어).
- 회로도: 트랜지스터·저항·전류원은 `fig-ink` 선으로, 지금 설명하는 경로(예: 출력저항을 들여다보는 노드)는 `fig-accent`로 그린다. 소자 이름·값은 `fig-text`(예: "M1", "R_D" 대신 유니코드 "R D"가 어색하면 `<tspan baseline-shift="sub">`), 노드 이름·극성은 대응 노드 점과 같은 파랑/빨강(위 노드 색 대응 규칙)을 쓴다. 접지 표기에는 기본 글자색을 쓴다.
- 교과서 그림 PNG(`교과서/마이크로전자회로/chNN/figures/`)를 붙이지 않는다. 다크모드와 MD 변환이 SVG 클래스 전제이기 때문이다.

## 본문과 페이지 요약의 계약

요약은 본문의 핵심 개념·작동 원리·성립 조건·혼동 구분을 압축하며 항목 수의 고정 상한을 두지 않는다. 본문에 없는 사실을 요약에만 추가하지 않고 보충의 범위·출처·불확실성을 유지한다. 긴 회로식은 패널 폭 안에서 읽히도록 여러 수식 줄로 나눈다. 중앙 제목과 고정 패널 제목은 유지하며 우측 중복 주제·문항 제목은 출력하지 않는다. `sum-for`는 `.sums` 컨테이너의 유일한 ID로 보존하고 제목 대입 JS를 만들지 않는다. 문제·보기·정답·해설·원문 탭·앵커·저장 키는 보존한다.

모든 학습 토픽에 대해 자료·토픽별 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 감사한다. 본문 주장·대응 요약 문장·판정/생략 이유와 `pass | unresolved`를 기록하고 보완 뒤 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고를 동기화하되 없는 MD 형식을 만들지 않는다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`이며 실제 검사 뒤에만 상태를 갱신한다. 파일 해시 변경 후 기존 증거는 갱신 전까지 오래된 근거다.
