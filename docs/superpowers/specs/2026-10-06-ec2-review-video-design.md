- #0=B: 제작 코드 독립 복사. 생명과학 저장소에 실행 중 의존하지 않는다.
- #1=개념 이해 + 필요한 수식 유도 [confirmed by default]. 사용자에게 제시한 추천값에 별도 변경 없이 계획 작성을 요청했다.
- #2=.agents/skills/ec2-review-video/: 전자회로2 프로젝트 로컬 설치.
- #3=완성된 복습노트·해당 문제 자료: 원자료로 새 노트를 작성하는 일은 ec2-review-pack에 맡긴다.

- #5=회로 변화·가정·부호·수식 대조: 구조 검사와 의미 검토를 구분한다.

## 전역 제약

- 스킬 이름은 ec2-review-video, 위치는 전자회로2/.agents/skills/ec2-review-video/이다.
- 기존 생명과학 저장소·전자회로2 ec2-review-pack·STT·강의자료·교과서·workbook은 수정하지 않는다.
- 한국어 Aoede, Vertex AI Express, gemini-2.5-flash-tts, ko-KR를 기본 설정으로 계승한다. 현재 서비스 가용성을 확인했다는 뜻은 아니다.
- 1920×1080, 30fps, PCM 24000Hz, Pretendard, 다크모드 고정을 유지한다.
- 로컬 런타임 자산은 GSAP 3.13.0, KaTeX 0.16.11, Pretendard 1.3.9로 동결하며 출처·라이선스를 보존한다. 생명과학의 런타임 코드와 전자회로2 템플릿에서 확인한 버전을 따른다.
- 주제별 목표 길이는 60–180초다. 실제 음성 길이를 사용하고 필요한 개념을 길이에 맞춰 삭제하지 않는다. 사용자 요청 또는 설명상 필요한 변경은 duration_override_reason에 기록한다.
- 기본 자동 제작이다. --review일 때만 전체 선정·장면 구성을 묶어 검토한다. --resume 및 목소리 교체를 지원한다.
- budget_usd=null을 유지하고 사용량 ledger를 기록한다. 공급자·모델·목소리를 자동 대체하지 않는다.
- GOOGLE_API_KEY/GEMINI_API_KEY 또는 명시적 --env-file을 사용한다. 키나 기존 .env를 복사하거나 자동 탐색하지 않는다.
- 유료 API 호출 없는 fake transport·로컬 PCM으로 개발 회귀를 수행한다. 실제 제작은 별도 단계로 실행·보고한다.
- 출력은 복습영상/<기간>/의 제목 있는 최종 MP4 N개와 <기간>_제작자료/ 하나다. N=0도 가능하다.
- 기존 결과·이전 버전을 보존한다. 모든 선정 영상 검증 전에는 최신 결과를 교체하지 않는다.
- 이 계획 작성 단계에서는 스킬 구현·영상 제작·커밋·푸시를 수행하지 않는다. 구현 시에도 푸시와 생성 영상 커밋은 별도 요청에 따른다.

## 접근 방식과 경계

A: 생명과학 코드 호출 래퍼 / B: 독립 복사와 연결부 조정 / C: 공통 엔진 추출 중 B를 선택했다.
새 스킬은 독립 실행 단위다. 공통 엔진 추출, 복습팩 자동 생성, 모든 문제 풀이 영상화, 범용 회로 시뮬레이터는 이번 범위 밖이다.
생명과학 실행 산출물·인증·캐시는 복사하지 않고 스킬 소스·공개 자산·테스트만 가져온다.

## 입력과 출처

인자는 MMDD, MMDD-MMDD 또는 노트 폴더다. 날짜·중복·겹친 기간·NFC/NFD 처리와 기존 source ID/hash 계약을 유지한다.
해당 노트의 HTML·MD·그림, problems.txt와 문제·답안 PDF를 읽고 source inventory와 동결 스냅샷에 포함한다.
problems.txt의 ID가 가리키는 교과서·기출 MD와 필요한 참조 문제·그림을 연결한다. 원문과 해설을 구분하고 depends_on을 따른다.
충돌 해결에 필요한 강의자료·STT·교과서만 명시적으로 보충 출처로 등록한다. 저장소 전체를 영상 범위로 포함하지 않는다.
문제가 없는 날짜는 정상이다. 누락한 문제 원문은 명시하며 해당 자료에 기대는 claim을 확정하지 않는다. HTML/MD 충돌은 원자료로 해결한 뒤 TTS를 진행한다.
스냅샷 파일명은 source ID로 바뀌므로 원래 MD의 상대 그림·참조 경로와 source ID의 연결을 메타데이터에 보존한다.

## 선정과 대본

선정 질문: 어떤 입력·조건을 바꾸면 무엇이 변하고, 이것을 보여주면 어떤 혼동이 풀리는가?
전체 항목을 animate/text/context로 분류하고 독립 학습 질문 하나당 영상 하나를 만든다. 주개념은 중복 소유하지 않고 선수 개념만 재사용한다.
선정된 주제가 없으면 선정 기록만 남기고 MP4·TTS를 생성하지 않는다. 통합 복습 영상은 명시 요청에만 만든다.
설명은 직관 → 실제 회로 → 변화의 원인 → 필요한 식 → 성립 조건 순서다. 긴 유도는 장면을 나눈다.
차동쌍의 전류 분배, 공통 모드 응답, 전류 미러, 캐스코드, 수업에서 실제 다룬 주파수 응답이 선정 예시다. 특정 주제를 무조건 포함하지 않는다.
정의·공식 목록은 정적 노트에 남긴다. 문제는 판별점의 근거이며 자동으로 풀이 영상 주제가 되지 않는다.

## 화면과 음성

디자인 원본은 .claude/skills/ec2-review-pack/assets/note-template.html이다. note/review 장면 모두 이 원본을 쓰고 새 review-template.html을 요구하지 않는다.
HTML 전체의 pager/theme/위젯 스크립트를 실행하지 않고 CSS 스냅샷과 의미별 클래스만 재사용한다. 영상 크기·배치는 video-layout.css로 조정한다.
노트 회로도 SVG의 연결·소자·노드 이름을 보존한다. 입력·전류·출력·그래프의 색상 대응을 영상 내에서 유지한다.
위젯 이벤트 코드를 복사하지 않고 원래 계산식을 확인해 대표 상태·좌표를 산출하고 결정적 motion JSON으로 변환한다.
KaTeX·GSAP·Pretendard는 새 스킬의 assets/runtime/에 fonts/와 vendor/ 구조로 준비해 로컬 파일을 stage한다. 구현 때 공개 라이브러리 파일만 재사용·확보하고 원본 음성·영상·출처 스냅샷은 복사하지 않는다. 실행 중 생명과학 폴더를 참조하지 않는다. 누락은 조립 전에 알리고 CDN fallback으로 감추지 않는다.
화면 수식은 g_m, r_O, R_out 등의 원문 표기를 유지하고 음성용 한국어 발음을 별도로 적용한다. 서로 겹치는 문자열 치환으로 식을 훼손하지 않게 검증한다.
화면 하단 .video-caption을 만들지 않는다. 자막 굽기 설정·마스터 보존 규칙은 원본 스킬을 유지하며 자막본은 제작자료 안에 둔다.

## 회로 검토와 완료 조건

에이전트는 source/circuit-review.json에 원자료·장면별 대조 근거를 작성한다.
검토 항목은 DC/소신호 구분, 연결·소자·노드, 전류 방향·출력 극성·이득 정의, KCL/KVL·등가회로, 동작영역·근사·대칭 가정, 식·수치·그래프·발화 대응이다.
BJT의 컬렉터 전류 합을 테일 이미터 전류와 같다고 표현하려면 베이스 전류 무시 가정을 명시한다. 차동 입력의 가상 접지를 모든 공통 모드 입력으로 일반화하지 않는다.
계산 예시는 출처의 조건과 단위를 유지한다. 좌표를 독립 계산과 비교하며 임의 그래프를 실제 시뮬레이션으로 소개하지 않는다.
프로그램은 검토 기록의 참조·완전성·현재 입력과의 일치를 검사한다. 식의 물리적 정당성은 의미 검토의 책임이다.
check와 TTS 전에는 현재 대본·그림·원자료에 대한 회로 검토를 요구하고, verify에도 증거를 연결한다. 바뀐 입력의 옛 passed 기록은 무효다.
회로 검토 자체의 hash를 자기 입력 hash에 포함하지 않아 순환 지문이 생기지 않게 한다.
기존 content/audio/visual/source/media/sync 검증과 실제 편집 소스 검사를 유지한다. 회로 검토만으로 최종 화면·음성이 검증됐다고 주장하지 않는다.

선정·스냅샷·캐시·예산 ledger를 묶음과 각 RUN에서 관리한다. 부분 실패 시 성공한 형제 영상과 음성을 보존한다.

최종 보고에는 영상 수·제목·길이·절대 경로와 실제 확인한 검증 범위를 적는다.

## 검증과 수용 기준

1. 원본 회귀와 전자회로2 source/theme/circuit/CLI 회귀가 유료 호출 없이 통과한다.
2. PDF·problems.txt·문제 ID·상속 문제·그림·Unicode 경로·해시 동결과 누락 보고를 확인한다.
3. note-template 하나만으로 note/review를 조립하고 로컬 수식·폰트를 브라우저에서 확인한다.
4. 0·1·N개, 부분 실패·재개, 이전 결과·링크 보존, 입력 변경 후 검증 무효화를 확인한다.
5. 로컬 PCM 렌더는 기술적 smoke 검증이다. 실제 Aoede 발음·내용·청취 검증은 실영상 실행으로 따로 확인한다.
