# 문장·쉼표 기준 문제풀이 자막 설계

## 의도와 결정
기존 34자 길이 기반 교체를 문장·절 기반 교체로 바꾼다. 기존 subtitles.py 수정으로 끝나는 bounded 작업이다. grill 결정 #6은 후속 writing-plans 요청에서 권장안으로 confirmed by default: 중간 자막은 쉼표를 유지하고 문장 마지막 자막은 온점으로 끝낸다. Native 실행 선호를 유지하며 계획 검토 후에만 구현한다.

## 표시 계약
- 문장 종료 온점에서 반드시 자막을 교체하고 서로 다른 문장을 한 cue에 합치지 않는다.
- 수식·괄호 밖 쉼표마다 cue를 교체하고 쉼표를 앞 cue 끝에 남긴다. 짧은 열거 구절도 이 규칙을 따른다. 임의 최소 표시 시간이나 합치기는 이번 범위에 넣지 않는다.
- 화면 내 줄바꿈은 cue 교체와 다르다. cue당 최대 두 줄, 줄당 최대 34자이며 가능한 경우 한 줄을 사용한다.
- 줄바꿈은 공백을 우선하고 불가피한 수식은 +−=∥×÷ 경계를 사용한다. r_O1, g_m1, V_BE, 첨자 토큰은 원자적으로 보존한다. 줄 첫 구두점이나 닫는 괄호만 남는 줄을 만들지 않는다.
- 전체 문자열 마지막이 온점 없이 끝나는 기존 대본은 표시용 온점만 덧붙인다. 이는 이전 설계의 '온점 검사'를 구체화한 호환 처리다. 음성 text와 저장된 caption_text는 수정하지 않는다. ?, !, … 등 다른 종결부호는 자동 치환하지 않고 명확한 저작 오류로 알린다.
- 숫자 사이 점(0.5, E10.13), 식별자 내부 점, 괄호 안 구두점은 cue 경계가 아니다. 인용 전체가 한 문장이며 온점 바로 뒤에 보호 구간을 닫는 따옴표가 오는 경우에는 해당 닫는 따옴표까지 앞 cue에 붙여 문장 경계로 처리한다. 인용 내부의 다른 구두점은 보호한다. 문자열 끝 온점 또는 다음 문장 앞 공백이 있는 온점을 문장 끝으로 인식한다. 쉼표 뒤 공백은 필수가 아니다.
- (), [], {}와 “”, ‘’, ASCII 큰따옴표 안 구두점은 보호한다. 인접 두 숫자 사이 쉼표(1,000)는 보호한다. ASCII 작은따옴표는 미분/prime 기호일 수 있으므로 보호 구간 시작으로 해석하지 않는다. 괄호 불균형은 저작 오류다.
- $...$ / \( ... \) LaTeX 원문은 지원하지 않는다. 기호 자막의 기존 규칙을 유지한다.
- 두 줄에 들어가지 않는 구절이나 34자 초과 원자 토큰은 segment id와 문제 구절을 포함한 InputError로 유료 TTS 전에 막는다. 작성자가 의미상 쉼표를 넣거나 표기를 간결하게 고친다. 런타임은 임의 문구/쉼표를 생성하지 않는다.

## 시간과 호환
현재 measured voice_samples 안에서 글자 수 비율로 시간을 배분한다. 새 줄바꿈 문자는 가중치에서 제외하고 표시용 마지막 온점 추가도 원문 길이 가중치에서 제외한다. 인접 cue 사이 인위적 빈 구간은 넣지 않으며 첫 cue 시작과 마지막 cue 끝은 기존 PCM 구간과 동일하다. 정밀한 문장/쉼표 발화 정렬을 주장하지 않는다.
caption_text 우선, 없으면 text fallback, TTS/cache 원고와 키는 유지한다. 자막 변경 시 이전 final/SRT 검증은 무효이며 WAV는 재사용한다. 원본 PDF/MD, 이전 MP4, 필기 7.5 chars/sec와 회로 카메라 동작은 보존한다.

## 예시
입력: g_m1은 Q₁의 트랜스컨덕턴스이고, r_O1은 Q₁의 출력 저항입니다. 이 두 기호를 구별해 둡니다.
출력 cue: [g_m1은 Q₁의 트랜스컨덕턴스이고,] → [r_O1은 Q₁의 출력 저항입니다.] → [이 두 기호를 구별해 둡니다.]
긴 cue 예: 따라서 Q₁은 이미터가 접지된\n공통 이미터 증폭기로 볼 수 있습니다.

## 범위와 검증
자막 분할·줄바꿈·사전 검사·SRT·저작 문서가 범위다. STT/강제 정렬/음성 재생성/영상 구조 변경/공개/latest 변경은 제외한다. 20개 E10.13 세그먼트로 의미 경계와 두 줄 실제 표시를 확인한다. 기존 무음 master를 복사하여 자막만 다시 입힐 수 있고 이것은 자막 화면 검증이지 실제 음성 검증이 아니다. 외부 패키지 설치 및 커밋은 별도 승인 없이 하지 않는다.
