# 문제풀이 입문 설명 저작 (작성자용)

본문은 회로 판단 → 첫 식 → 핵심 계산 → 최종 답으로 쓴다. 소문항별 출력은 `explanations/pN.html` 한 파일이며, 조립기가 원문·조건·구할 것·문제 그림을 붙인다. 처음 나오는 판단은 식 옆 한두 문장으로 설명한다. 익숙한 계산과 반복 유도는 줄이고, 모든 소문항 답과 답을 바꾸는 가정·근사·부호는 남긴다.

## 간략 해설 원고

```html
<div class="layer formal circuit-explanation" data-explanation="solve">
  <figure class="figure circuit">
    <svg id="fig-feedback" viewBox="0 0 320 180" role="img" aria-label="감지 가지가 연결된 개루프 회로">
      <!-- 해당 회로 상태의 SVG를 넣는다. -->
      <text class="fig-loc" x="264" y="93" font-size="17">㉠</text>
    </svg>
    <figcaption class="circuit-state">감지 가지가 붙은 개루프 회로</figcaption>
  </figure>
  <div data-subpart="main">
    <h4>출력에서 본 첫 식</h4>
    <p data-answer-step="출력 부하"><span class="loc">㉠</span> 감지 가지의 가운데 포트를 열면 두 저항이 직렬이에요.</p>
    <div data-answer-final="">
      $$R_{out,\mathrm{open}}=R_D\parallel(R_1+R_2)$$
    </div>
  </div>
</div>
<div class="sum" hidden><p class="sum-lead">감지 가지의 두 저항이 출력에 부하로 걸려요.</p></div>
```

- 소문항별 `data-subpart`는 원문 순서대로 한 번씩 둔다. 각 그룹의 기존 요소에 하나 이상의 `data-answer-step`과 정확히 하나의 `data-answer-final`을 붙인다. 구할 값이 여럿이면 같은 final 안에 별도 식으로 둔다. 본문의 식을 복제해 별도 완성 답 블록을 만들지 않는다.
- `figure.circuit`는 풀이 구역의 직계 요소로 둔다. 회로 상태가 이어지는 구간에서 그대로 참조하고, 다른 측정 상태가 필요하면 새 상태를 해당 구간의 그림으로 명시한다. 회로가 판단에 필요 없는 문항은 그림을 생략한다.
- 정리노트 SVG가 같은 회로·회로 상태를 나타내면 재사용한다. 그림 속 `fig-loc`과 본문의 `loc`을 ㉠부터 대응시킨다. 단순 위치를 넘어서 해당 위치에서 어떤 가지가 남거나 없어지는지와 어떤 식이 달라지는지 적는다. 표지는 본문에서 실제로 짚는 위치에 붙인다. 답안 overlay에서는 HTML 표지를 제거하므로 소자나 노드는 문장 자체에서 식별되게 쓴다.
- 문제를 다시 서술하거나 일률적인 연습 질문을 넣지 않는다. 익숙한 대입·약분을 줄인다. 지정된 방법, 처음 써야 할 식과 의미 있는 중간량, 모든 소문항 답은 유지한다. 결과를 판별하는 검산이 필요할 때는 식 바로 아래에 짧게 붙이고 상세 검산은 evidence에 둔다.

## 인계 전 자체 점검

작성한 모든 문제를 인계하기 전에 원문 그림·조건·값·단위와 입출력 기준을 대조하고, 추가 가정과 재현되지 않는 원문 수치는 기존 보고에 구분해 적어요. 주요 유도는 가지 전류와 KCL 또는 별도 계산, 단위·극한으로 점검하고 근사와 반올림 기호를 확인해요.

각 문제의 모든 생성 회로에서 도선 끝을 따라 소자·노드·접지·시험원으로 이어지는지 확인하고 의도된 개방 단자와 실수로 남은 선을 구별해요. 해당 풀이 단계의 측정 조건, 노드/라벨 색과 겹침도 함께 봐요. 렌더와 화면 도구가 있으면 요약·본문의 긴 식과 표를 실제 모바일/데스크톱 화면에서 확인하고 TeX 오류를 고쳐요. 조립 전이라 전체 화면을 확인할 수 없으면 미실시로 기록하고 조립 후 정식 화면 검토자가 확인해요. 선택 요소가 답안에 필요한 회로·조건·계산·최종 답을 빠뜨리지 않는지 대조해요. PDF 글리프와 실제 사용 글꼴은 렌더가 가능한 단계에서 확인해요. 결함을 모아 수정하고 변경된 부분을 다시 확인하며, 미실시는 보고해요. 이 자체 점검은 독립 검산과 공식 브라우저/PDF 검토를 대신하지 않아요.


## 식과 답안 선택

`<REPO>/.claude/skills/ec2-review-pack/references/solution-style.md`와 `source.json.learning_style`을 대조하고 원문 조건을 확인한다. 한 행에 독립 계산 하나를 쓴다. 같은 양의 연속 등식은 유지하고, 긴 관계식은 한 `aligned` 블록에서 줄을 나눈다.

## 같은 본문에서 간결한 답안 선택

- solve의 **기존 보이는 요소**를 `data-answer-step="회로 판단"`처럼 일반 텍스트 제목으로 표시한다. 핵심 회로·필요 조건·주요 계산을 포함하고 상세 이유·긴 유도는 선택 요소 밖의 같은 단계에 둔다. 사본을 추가하지 않는다.
- solve의 소문항 그룹은 해당 구역의 직계 `<div data-subpart="a">`처럼 원문 순서로 각각 한 번 둔다. 모든 소문항마다 step 하나 이상과 `data-answer-final` 요소 정확히 하나가 필요하다. final에는 최종 답과 성립 조건을 담고 상세 검산은 밖에 둔다.
- 선택 요소는 부모 소문항 범위를 따른다. 기존 일곱 구역 원고의 start에서만 다중 소문항을 `data-answer-subpart="a"`로 명시한다.
- 선택 표지는 중첩하지 않는다. 하나의 요소에 step과 final을 함께 붙이지 않는다. 제목만 있는 요소·빈 제목·빈 내용·구역 밖 선택은 거부한다.
- 독립된 식은 선택 요소 안에서도 각각 별도 display 블록이다. 한 요소에 여러 display를 담을 수 있으며 같은 양의 연속 등식은 유지한다.
- 조립기는 최종 stage의 자원 경로를 가진 선택 요소의 내부 HTML을 그대로 overlay에 담는다. wrapper가 필요한 회로는 figure를 포함하는 기존 div를 선택한다. 단락 측정/입력 영점 회로·근사 조건·단위·부호가 빠지지 않았는지 실제 PDF에서 대조한다.


회로는 해당 start/solve 단계에서 측정 조건 → 단순화 근거 → 노드 관계 → 첫 식을 보여 준다. 필요한 모델을 유지하고 다른 근사 모델로 바꾸면 조건·결과의 대응을 명시한다.
- 출력 배치 필수: 입력은 왼쪽, 출력 단자·출력 라벨·출력 시험원/단락 접속은 오른쪽에 둔다. 회로로 유입하는 시험전류는 오른쪽에서 왼쪽으로 그리며, 내부 제어 전류원의 방향·전압 극성·실제 접속은 유지한다. 전기적으로 같은 노드라는 이유로 출력 접속을 왼쪽이나 중앙에 두지 않는다. 풀이 본문·HTML·PDF에서 각각 확인한다.
- 병렬 가지 순서 필수: 제어 전류원과 $r_o$가 병렬이면 반드시 **제어 전류원 왼쪽 → $r_o$ 또는 병렬 합성 저항 오른쪽 → 출력 접속 맨 오른쪽** 순서로 그린다. 입력은 그 왼쪽, 이미터/소스 축퇴 저항은 해당 노드 아래에 둔다. $r_o$를 생략한 축약 모델에는 없는 저항을 추가하지 않는다. 그 모델의 제어원 위치를 병렬쌍의 배치 규칙으로 일반화하지 않는다. 풀이 본문의 모든 SVG와 답안 PDF에서 소자·단자 전체 배치를 대조하고, 전기적 등가성만으로 위치 불일치를 승인하지 않는다.
- 노드 점과 시험 표기 필수: 접지 표기만 하는 비분기 단자와 접지 기호의 직접 접속점을 제외하고, 입력·출력·시험 노드와 이름을 붙인 전압 노드에는 연결 위치가 분명한 눈에 보이는 점을 찍는다. 출력 시험전압 노드의 점은 출력 도선의 실제 맨 끝이자 가장 오른쪽 단자에 둔다. 점 오른쪽으로 도선(ink)이 더 이어지거나 연장된 도선 중간에 점이 놓이면 안 된다. 시험 노드 전압 $V_t(+)$는 그 끝점 위에 둔다. 유입 시험전류는 오른쪽에서 왼쪽으로 흐르며, 왼쪽을 향하는 $i_t$ 화살표는 $V_t$ 점 왼쪽의 도선 구간에 둔다. $i_t$ 라벨도 점 왼쪽에서 그 화살표 아래나 곁에 둔다. 화살표 전체가 점 왼쪽에 머물고 점을 덮지 않도록 화살표 꼬리와 점 사이에 작은 간격을 남긴다. 화살표나 전류 라벨을 점 오른쪽에 놓지 않는다. 다른 시험 기호($v_x/i_x$ 등)를 쓰면 같은 배치와 정의를 적용한다. 선 교차만 있고 연결되지 않은 곳에는 점을 찍지 않는다. 라이트·다크 HTML과 실제 답안 PDF에서 점·라벨·화살표의 분리와 가시성을 각각 확인한다.
- 회로 안 글자와 점의 정돈: SVG 안에는 소자 이름·값·제어 전류원 라벨(예: $g_mv_\pi$), 노드 이름·극성·방향처럼 실제 회로를 읽는 표기를 남긴다. 분석용 $G_m$ 제목·측정 조건 문구·유도 설명은 그림 아래 figcaption이나 수식 문단에 둔다. 출력 단락·입력 영점의 실제 연결은 그림에 보존한다. 접지 입력 위의 독립 제목 `Rout`처럼 불필요한 제목은 옮겨 중복하지 않고 삭제한다. 가까운 노드 관계는 유도 설명이 아니고 겹치지 않을 때만 남길 수 있다. 접지 표기만 하는 비분기 단자·접지 기호의 직접 접속점은 제외하고 입력·출력·시험 단자, 이름 붙인 내부 전압 노드, 실제 분기 접속점의 점은 유지하되 이름도 분기도 없는 직선 도선 중간의 장식 점은 없앤다. 모든 도선에 점을 추가하라는 규칙이 아니다. $V_{out}(+)$·$V_t$ 등 라벨은 아래첨자까지 포함한 실제 글리프 경계상자가 도선에서 최소 0.6em(보통 화면에서 약 8px) 떨어지게 배치한다. 텍스트 기준선 간격만 확인하지 않는다. 필요하면 라벨을 옮기고 viewBox 위쪽 여백을 늘린다. 풀이 본문의 모든 SVG를 열거하여 라이트·다크 HTML과 실제 답안 PDF의 보통 보기 크기에서 이 간격·클리핑·겹침을 확인한다. 병렬 제어원 왼쪽/$r_o$ 오른쪽/출력 맨 오른쪽, 맨 끝 $V_t$ 점 오른쪽 도선 없음, 점 왼쪽의 왼쪽 방향 $i_t$와 라벨 배치도 유지한다.
- 접지·전압 라벨·노드 색 대응: 접지 기호에 직접 닿는 점과 접지만 표시하는 비분기 입력 단자의 점은 생략한다. 접지로 이어지는 회로라도 별도의 실제 분기 접속점·이름 있는 비접지 노드는 유지한다. $v_e$ 등 전압 이름은 다른 소자나 저항 옆으로 멀리 밀지 않고 해당 노드 바로 곁에 둔다. 아래첨자·극성을 포함한 실제 글리프 경계로 도선과 최소 0.6em 간격을 확보하면서 가능하면 0.6–1em 정도의 가까운 간격을 목표로 한다. 혼잡 때문에 더 벌리면 배치 이유를 검토에 기록한다. 노드 점과 해당 전압 이름·극성은 같은 파랑 또는 빨강으로 묶는다. 주요 신호 경로를 따라 파랑·빨강을 교대하고 가까운 전압 라벨끼리 최대한 다른 색을 쓴다. 같은 전기적 노드는 다른 위치의 점도 같은 색이며, 모든 인접 노드를 반대색으로 만드는 그래프 채색을 강제하지 않는다. 접지 표기·도선·소자/제어원 라벨·전류 화살표/라벨·본문 수식의 색은 이 노드 색 규칙으로 바꾸지 않는다. 색 없이도 노드 이름과 극성으로 구분되어야 한다. SVG에는 대응 노드 식별자와 색을 명시하고, HTML 테마와 PDF에서 실제 계산된 색이 파랑/빨강인지 확인한다. PDF의 문항 종류별 초록/주황 `--kind`를 노드 파랑의 대체값으로 사용하지 않는다. 풀이 본문의 모든 SVG와 MD에 참조된 같은 그림, 라이트·다크 HTML 및 실제 답안 PDF에서 접지 점 생략·가까운 라벨·점/전압 색 일치를 검토한다.
- 출력저항 표시/검산 경계: $R_{out}$은 처음부터 유효한 근사식으로 시작하고 조건과 $\approx$를 유지한다. 이 규칙은 생성하는 풀이 본문(start/solve/verify·formal/보충 포함) HTML·요약·동반 MD·답안 PDF 모두에 적용한다. 정확식 → 근사식 유도나 정확식과 수치 비교를 학습 본문에 추가하지 않는다. 정확한 $R_{out}$의 전체 모델·유도·수치/극한 대조는 내부 독립 검산 evidence에만 둔다. 원문이 정확식·유한 β 전체 결과 또는 수업 기본 큰 곱 근사와 반대인 조건·수치를 명시하면 예외 이유를 짧게 밝히고 필요한 모델과 결과를 제시한다. 유한 β 또는 $r_o$가 있다는 사실만으로 예외를 선언하지 않는다. 이 제한은 $R_{out}$에 한정하며 다른 개념의 필요한 상세 유도를 줄이지 않는다.

검토한 본문의 선택 요소에서 답안 내용을 추출한다. 새 원고의 답안은 `data-answer-step`·`data-answer-final`로 표시한다. `data-personalization`, `data-solution-core`, `data-core-label`은 과거 원고에만 남아 있는 표지다. 새 원고에는 새 검토에서 승인한 `answer-overlay.json`을 쓴다. 원문·조건·그림은 조립기 입력을 유지하며 계산에 필요한 회로 판단만 본문에 담는다.

## 기존 일곱 구역 원고를 대조할 때

각 조각은 다음 직계 구역을 표 순서대로 하나씩 포함해요. understand·recall 앞에 별도 핵심 풀이를 넣지 않아요. 모든 구역은 `class="layer …"`가 있는 직계 `div`이고, 본문 답은 모두 펼쳐요.

| data-explanation | layer | 표시 제목 | 작성할 내용 |
|---|---|---|---|

## recall: 이 개념과 공식을 떠올려요

제목은 **이 개념과 공식을 떠올려요**이에요. 개념 이름이나 공식만 나열하지 말고 다섯 단계를 이어요.

1. **단서**: 문제의 어떤 표현·그림이 개념을 부르는지. 예: "두 입력에 같은 전압", "테일에 전류원", "$\lambda\neq0$은 M3만".
2. **개념**: 공통 모드(common-mode, CM) 하프 서킷, 축퇴(degeneration), 출력 저항(output resistance) 등. 영어 전문용어를 병기해요.
3. **기호의 뜻**: $g_m$(트랜스컨덕턴스, 게이트 전압 변화가 드레인 전류를 얼마나 바꾸는지), $r_o$(채널 길이 변조로 생기는 출력 저항, $1/(\lambda I_D)$), $R_{SS}$(테일 소자가 소스 쪽에 보이는 저항), $R_{out}$, $A_{CM}$, $A_{CM-DM}$, CMRR 등 이 문제에 나오는 것만.
4. **근사 조건**: PROFILE의 수업 기본값 $g_mr_o\gg1$, $g_mR_e\gg1$을 적용하고 주항으로 정리해요. 원문이 명시한 반대 조건만 구분해요. 내부 $r_e=1/g_m$와 외부 축퇴 저항을 구별하고 유한 $r_\pi$를 유지해요. 그 밖의 조건은 $\lambda\to0$(그 트랜지스터의 $r_o\to\infty$), $r_o\gg R_D$, $g_m r_o\gg1$, 대칭 회로 등. 어디서 쓰고 어디서 안 쓰는지 밝혀요. 문제가 "M3만 $\lambda\neq0$"처럼 정하면 그 범위를 지켜요.
5. **선택 이유**: 왜 이 개념이 이 문제의 첫 도구인지. 예: 대칭이라 CM 입력에서 두 반쪽이 같은 전류를 흘리므로 테일을 $2R_{SS}$ 두 개로 쪼갤 수 있어요.

recall은 일반 개념을 고르는 과정이고 start는 주어진 기호로 종이에 적는 실제 첫 줄이에요. 긴 설명을 두 구역에 복제하지 않아요.

```html
<div class="layer formal" data-explanation="recall">
  <h4>이 개념과 공식을 떠올려요</h4>
  <p>"두 입력에 같은 $\Delta V_{in,CM}$"이라는 말에서 공통 모드 하프 서킷(CM half circuit)을 떠올려요.</p>
  <p>$R_{SS}$는 테일 소자가 소스 노드에 보이는 소신호 저항이에요. 대칭이라 두 반쪽 전류가 같으므로 테일을 $2R_{SS}$ 두 개로 나눠 반쪽마다 하나씩 붙여요.</p>
  <p>M1·M2는 $\lambda=0$이라 $r_o\to\infty$로 두고, M3만 $R_{SS}=r_{O3}$로 남겨요. 그러면 축퇴 CS 단 이득 $A=-\dfrac{R_D/2}{1/(2g_m)+R_{SS}}$ 꼴을 바로 쓸 수 있어요.</p>
</div>
```

공통 개념은 한 번 설명하고, 서로 다른 개념을 요구하는 소문항은 `(a)`, `(1)`처럼 구분해요. 개념 수를 고정하지 않아요. 증명·정성 문항은 정의·판단 기준과 논증 조건을 설명해요.

## start: 실제 첫 줄

종이에 그대로 옮길 수 있게 써요.
- 소신호 등가회로: 어느 전원을 접지로 보내는지, 어떤 트랜지스터를 $g_m v_{gs}$와 $r_o$로 바꾸는지.
- 하프 서킷: 차동(DM)이면 대칭선이 가상 접지, 공통 모드(CM)면 대칭선을 끊고 $2R_{SS}$로 나누기.
- 첫 식: 단별 이득으로 이어지는 전압이득은 중간 노드를 짚고 해당 단의 부하와 부호 있는 이득부터 써요. $G_m$·$R_{out}$ 경로에서는 출력 단락에서 $G_m=i_{out,sc}/v_{in}$을 먼저 구해요. 원문 지정 증명·다른 목표의 문항은 그 목표에 맞는 KCL/첫 식을 써요.

### 핵심 규칙에서 첫 식까지

학생이 설명만 보고 첫 식을 세울 수 있어야 해요. **핵심 규칙 → 작은 상태 변화 또는 기호 조작 → 실제 첫 식 → 유도**를 연결해요. 수치 예시는 연결을 드러낼 때만 쓰고, 문제에서 준 값과 구별해 "이해를 위한 예시"라고 표시해요. 이미 충분히 연결된 기호 유도에는 숫자를 억지로 추가하지 않아요.

- KCL 앞에서 노드 전압·전류의 양의 방향·제어 전압을 정의하고 각 가지 전류를 쓴 뒤 항을 모아요. 정리된 계수식부터 시작하지 않아요.
- 출력저항은 시험전류의 유입 방향과 귀환 경로, $R_{out}=v_t/i_t$를 먼저 밝혀요. $G_m$의 출력 단락과 전압 이득의 무부하 조건도 구별해요.
- 반회로를 골랐다면 유도 끝까지 유지해요. 합친 회로로 바꾸면 왜 동등한지 먼저 보여요.
- 대입·병렬 공통 인자·차수 표기에서 새 식이 갑자기 나오지 않게 중간 조작과 단위를 써요. 작은 예시는 일반 증명을 대신하지 않아요.
- $R_{out}$ 외의 보충 정확식과 위 예외에 해당하는 $R_{out}$은 출발 KCL과 중간 대입을 보여요. 정확은 명시한 모델 안에서의 정확이며, 주항 근사의 조건과 답을 구분해요. "KCL로 구하면" 뒤에 결과만 붙이지 않아요.
- 그림은 본문의 노드 이름·화살표 방향·수치·조건과 같아야 해요. 전류 경로가 핵심이면 그 경로가 그림에서 보여야 해요. 요약에는 핵심 규칙과 적용 순서를 남겨요.

### 소신호 등가회로 그림

**언제 필수인가**: 내부 검산 전용 정확식은 학습 그림을 추가할 이유가 아니에요. 출력저항 블록 공식도 표시/검산 경계에 따라 처음부터 유효한 근사식으로 써요. start나 solve에서 소신호 등가회로의 노드 KCL/KVL을 세우면 그 회로를 직접 그린 inline SVG가 반드시 있어야 해요. 시험원으로 $R_{out}=v_x/i_x$를 구할 때, 노드 전압을 정의해 정확식을 낼 때, 증명·유도에서 KCL을 쓸 때가 여기에 해당해요. 바이어스 전류 분배처럼 DC KCL만 쓰거나, 블록 공식(조건을 확인한 $R_{out}\approx g_mR_Er_O$, $1/g_m$, 병렬 합치기, $A_v=-G_mR_{out}$, 하프 서킷)만으로 끝나는 문항은 필수가 아니에요. 교과서 그림 PNG는 원 회로라서 이 그림을 대신하지 못해요.

**핵심 회로의 형태**
- start/solve에서 $G_m$ 측정 회로를 그리면 출력에 접지까지 이어진 단락선과 $v_{out}=0$, 정의한 $i_{out}$ 화살표를 그려요. $R_{out}$ 측정 회로에는 입력 영점 접속과 출력 시험원·$v_x/i_x$ 방향을 그려요. 구할 값이 바뀌면 해당 측정 조건의 그림도 바꿔요. 이미 알려진 블록 공식으로 끝나는 모든 단계에 새 측정 회로를 강제하지는 않아요.
- 축퇴 구조는 입력 가지를 왼쪽, 축퇴 저항을 해당 이미터/소스 노드 아래에 두어요. 병렬 제어원·출력저항은 제어원 왼쪽/저항 오른쪽으로 그려요. P9.23의 ro2 생략 모델에는 그 병렬쌍 비교를 적용하지 않아요. 해당 모델에서 성립하는 노드 관계를 직접 붙여요. 큰 β, $g_{m2}r_{o2}\gg1$, $r_{o1}\ll\beta r_{o2}$에서 $G_m$ 주항을 얻기 위한 $r_{o2}$ 가지 생략 모델만 $v_e\approx i_{out}r_{o1}$과 $i_{out}\approx g_{m2}(v_{in}-i_{out}r_{o1})$로 연결해요. 가지 생략을 실제 $r_{o2}$ 전류가 작거나 0이라는 뜻으로 설명하지 않아요. 전체 모델의 $i_{out}=g_{m2}(v_{in}-v_e)-v_e/r_{o2}$, $v_e=r_{o1}(i_{out}+i_b)$와 구별해요. $G_m\approx1/r_{o1}$에는 추가로 $g_{m2}r_{o1}\gg1$이 필요해요.
- 유한 β나 $r_o$가 결과에 필요하면 풀이에도 해당 가지를 유지하고 올바른 노드 관계를 써요. 원문이 큰 $g_mr_o$만 주었다고 큰 β를 자동 가정하지 않아요. 원·마름모 선택이나 글꼴보다 연결·측정·식의 대응을 먼저 맞춰요.

**몇 개, 어디에**
- start/solve의 해당 계산 단계에 필요한 회로를 둬요. 같은 목적의 회로를 별도 핵심/상세 버전으로 복제하지 않아요.
- 첫 KCL 식 바로 앞에 그 식의 모델에 맞는 회로를 둬요.
- 같은 문항에서 경계 조건 때문에 회로가 실제로 달라지면(예: $G_m$은 출력 단락, $A_v$는 무부하, CM과 DM 하프 서킷) solve의 해당 소문항에 두 번째 그림을 둬요. 측정 조건·필수 모델이 다르면 필요한 그림을 각각 두되, 같은 모델·측정의 중복을 만들지 않아요. 바뀐 단자·가지를 구별해요.

**무엇을 그리나**
- 선택한 상세 모델에서 독립 DC 전원은 AC 접지로, 각 트랜지스터는 제어 전류원 $g_m v_{gs}$(BJT는 $g_m v_\pi$와 $r_\pi$)과 필요한 $r_O$로 바꿔 그려요. $R_{out}$의 경우 유효한 근사 모델로 시작하며 정확 전체 모델 그림은 위 예외가 아니면 내부 검산에만 둬요. $\lambda=0$처럼 문제가 없앤 소자는 그리지 않아요.
- 노드 이름($v_x$, $v_e$, $v_{out}$), 전류의 양의 방향 화살표, 제어 전압의 $+$/$-$ 극성이 첫 KCL 식과 글자 그대로 같아야 해요.
- 시험원과 KCL을 세우는 노드는 `fig-accent`(노드 점은 `fig-dot`), 나머지 소자는 `fig-ink`로 그려요. 문제가 덧붙인 기생 소자처럼 함정이 되는 가지는 `fig-danger`로 그릴 수 있어요.
- figcaption 한 줄에 어느 전원을 접지로 보냈고 어느 소자를 무엇으로 바꿨는지 적어요. `aria-label`에는 노드와 소자 연결을 문장으로 적어요.

**마크업**
- `<figure class="figure"><svg viewBox="…" role="img" aria-label="…">…</svg><figcaption>…</figcaption></figure>`
- 색은 클래스로만 칠해요: `fig-ink`, `fig-accent`, `fig-danger`(선만), `fig-dot`(채움), `fig-text`, `fig-muted`(글자). 템플릿이 라이트·다크 모드 색을 정해요. 배경 `rect`, hex 색, `fill="#…"`, `style` 속성은 쓰지 않아요.
- 생성 회로 수식은 PROFILE의 NOTATION-01대로 native `<text class="fig-text fig-math">`와 `<tspan baseline-shift="sub" font-size="78%">`/`super`로 표현해요. 유니코드 가짜 첨자·평문 vCM/gm/ro·밑줄 기호 대신 실제 첨자를 써요. 변수·숫자·단위·설명 라벨 모두 Pretendard 600 정체로 통일해요. 실제 600 face를 로드하고 독립 SVG에도 SemiBold를 포함해요. Ω·π와 같이 실제 Pretendard에 있는 기호를 쓰고 병렬은 지원되는 ‖로 표현해요. 본문 LaTeX \parallel은 유지해요. `<text>` 안의 `$...$`나 foreignObject KaTeX에 의존하지 않아요. 글자는 12~14px 정도가 되게 viewBox를 잡아요(가로 360~480).

### 고주파 모델 및 밀러 효과(Miller Effect) 회로도 규칙

1. **밀러 정리(Miller's Theorem) 적용 문항**:
   - **변환 전/후 2단 비교 회로도(Miller Decoupling Pair) 필수**: `start`(종이에 쓸 첫 줄) 또는 `solve` 도입부에 [Before: 부유 피드백 임피던스($C_F$ 또는 $R_F$)]와 [After: 입력측 접지 임피던스 $Z_{in,M}$ 및 출력측 접지 임피던스 $Z_{out,M}$]를 나란히 대조하는 1장의 SVG(viewBox 약 `0 0 520 160`)를 삽입해요.
   - 변환 후 회로에는 반드시 입력측 접지 커패시터 $C_{in,M}=(1-A_v)C_F$와 출력측 접지 커패시터 $C_{out,M}=(1-1/A_v)C_F$를 접지와 연결된 형태로 명시해요.
   - `solve`의 극점 추정 단계에는 입력 노드의 테브난 저항과 결합된 $R_{in,eq} \parallel C_{in,M}$ 루프 및 출력 노드의 $R_{out,eq} \parallel C_{out,M}$ 루프를 나타내는 도해를 보여줘요.

2. **고주파 소신호 등가회로(High-Frequency Models)**:
   - 기생 커패시터($C_\pi, C_\mu, C_{CS}$ 또는 $C_{GS}, C_{GD}, C_{DB}$)를 단순 박스 나열이나 텍스트 행으로 표현하는 것을 금지해요.
   - 트랜지스터 심볼 또는 제어 전류원($g_m v_{gs}$ / $g_m v_\pi$)과 실제 회로 노드(입력, 출력, 중간 노드 $X$, AC 접지) 사이에 커패시터 기호(평행 두 선)를 올바른 배선으로 그린 정식 등가회로를 삽입해요.
   - 캐스코드(Cascode) 회로의 경우, 중간 노드 $X$가 AC 접지가 아닌 신호 노드임을 분명히 나타내고, $Q_1$의 $C_{\mu1}$이 입력–$X$ 사이에 걸려 있음을 시각화해요.

### retry: 다른 조건에 규칙 적용하기

"첫 식을 쓰고 다시 계산해 보세요" 같은 범용 문구만으로 끝내지 않아요. 문항마다 조건 하나를 바꾼 예측, 첫 도구 선택, 부호·전류 경로 판단 중 적합한 질문 1~3개를 써요. 예: "기존 기울기 −20 dB/dec에서 1차 영점을 지나면 얼마인가요?" 질문에 필요한 조건과 값을 밝혀요. 본문에 이미 나온 문제를 반복하더라도 왜 그 규칙을 선택하는지 확인해요.

작성자는 질문별 예상 답·이유·적용 조건을 검토용 evidence에 기록해요. 리뷰어는 먼저 질문만 보고 답과 이유를 적은 뒤 작성자 기록과 대조해요. 이 검토를 실제 학생의 독립 회상이나 숙달 확인이라고 보고하지 않아요.

## 기존 원고의 solve·verify 소문항 표지

`source.json`의 그 문항 `subparts`가 `["a","b"]`(또는 `["1","2"]`)이면 **solve와 verify 모두** 각 값을 `data-subpart`로 한 번씩 써요. 소문항이 없으면 `["main"]`이고 `data-subpart="main"` 하나가 필요해요. 제목에는 원문 그대로 `(a)`·`(1)` 표지를 한 번 붙이고, 같은 묶음의 문단 앞에는 반복하지 않아요(조립기가 제목 있는 묶음의 같은 접두사를 지워요). `(a)에서 구한 $R_{out}$`처럼 의미 있는 참조는 유지해요. 소문항 표지를 임의로 합치거나 이름을 바꾸지 않아요.

```html
<div class="layer formal" data-explanation="solve">
  <h4>이렇게 풀어요</h4>
  <div data-subpart="a"><h4>(a) 캐스코드 테일</h4><p>실제 식, 변형 이유, 완성 답을 써요.</p></div>
  <div data-subpart="b"><h4>(b) 캐스코드 부하</h4><p>실제 식, 변형 이유, 완성 답을 써요.</p></div>
</div>
<div class="layer formal" data-explanation="verify">
  <h4>완성 답과 검산</h4>
  <div data-subpart="a"><h4>(a) 검산</h4><p>극한 대입과 단위로 확인한 결과를 써요.</p></div>
  <div data-subpart="b"><h4>(b) 검산</h4><p>특수값을 넣어 확인한 결과를 써요.</p></div>
</div>
```

## 기존 원고의 verify: 회로 검산

완성 답을 굵게 다시 적고, 아래 중 그 문항에 맞는 것을 실제로 해 보여요.
- **극한 대입**: $R_{SS}\to\infty$이면 $A_{CM}\to0$, $\lambda\to0$이면 원래 식으로 돌아오는지, $g_m r_o\to\infty$에서의 값.
- **단위·차수**: 이득은 무차원, 저항은 Ω, $g_m$은 S. 분모·분자의 저항 차수가 맞는지.
- **대칭 특수값**: $\Delta R_D=0$이면 $A_{CM-DM}=0$, 미스매치가 없으면 CMRR→∞ 같은 확인.
- **수치 대입**: 수치 문항은 주어진 값을 넣어 유효숫자까지 계산하고 단위를 붙여요.

숫자 예 몇 개로 증명이 끝났다고 쓰지 않아요. 증명 문항은 적용 조건과 논증을 확인해요.

## 요약 sum

마지막에 직계 `<div class="sum" hidden>` 하나를 넣어요. 이 요약만 UI 오른쪽 패널로 이동해요. 요약은 시험 직전 확인할 핵심만 남긴다. 기본 구성은 핵심 한 문장 → 필요한 식 1~3개 → 판단 기준 1~3개이며 권장 분량이지 할당량이나 강제 상한이 아니다. 반복 예시·유도·중복 용어 풀이·일반적인 경고는 본문에 둔다. 식의 적용 여부나 답의 부호를 바꾸는 조건은 해당 식 옆에 압축한다. 본문에 없는 사실을 추가하지 않는다. 모든 본문 주장을 요약에 복제하지 않고 핵심의 일치·오해 가능성·중복 여부를 검토하며 생략 이유는 감사 기록에 남긴다.

요약의 문장은 각각 별도 `<p>`로 작성하며 한 문장에는 하나의 판단을 담는다. 마침표로 문장을 실행 중 자동 분리하지 않는다(소수·약어·TeX 보존). 자연스러운 화면 줄바꿈은 허용한다. 의미가 나뉘면 짧은 소제목의 `summary-group`으로 묶되 단순 요약에 소제목을 늘리지 않는다. 제목 아래 12px, 그룹 사이 24px, 문장 문단 사이 8px을 공통 템플릿이 처리하며 빈 문단·연속 `<br>`로 간격을 만들지 않는다. 긴 식은 하나의 `aligned` 안에서 관계를 유지하며 나눈다. 중앙 제목·고정 패널 제목과 유일한 `.sums#sum-for`, 문제·원문 탭·앵커·저장 키를 보존한다.

공개 학습 HTML·요약·동반 MD·툴팁·접근성 문구에는 STT 줄 번호·Part·타임스탬프·시각 정보 유무를 출력하지 않는다. 근거 위치는 별도 검토 기록에만 보관한다. 해설 HTML·동반 MD의 학습량 행(핵심/추가 연습·소문항 묶음·예상 시간)은 생성하지 않고 선발 JSON에는 유지한다. PDF 규칙은 이 HTML 가독성 변경으로 바꾸지 않는다.

```html
<div class="sum" hidden>
  <p class="sum-lead">대칭 CM 입력은 반회로로 풀어요.</p>
  <div class="summary-group"><h4>첫 식</h4><p>각 반회로에 $2R_{SS}$를 넣어요.</p><p>출력 하나의 이득을 먼저 구해요.</p></div>
</div>
```

본문 전체를 요약에 복제하지 않아요. 요약의 핵심 개념·공식은 본문 recall과 일치해야 해요.

## 수식과 여백

짧은 수식은 문장 안에 두고 수식마다 스크롤 컨테이너를 만들지 않아요. 긴 유도는 의미가 유지되는 등호·항을 기준으로 여러 식으로 나누고, 한 수식이 여러 줄이 필요하면 `aligned`를 써요. 병렬 기호는 `\parallel`(예: $r_{O2}\parallel r_{O4}$)로 통일해요. 요약 패널은 폭이 좁으니 요약 속 식은 짧게 나눠요.

제목과 첫 설명 사이 12px, 설명 문단 사이 12px, 요약 그룹·설명 구역 사이 24px, 요약 문장 사이 8px은 템플릿이 정해요. solve의 첫 직계 소문항은 제목 뒤 24px, 동급 소문항 사이는 1024px 이상에서 32px·그 미만에서 24px이에요. 간격은 이전 블록의 끝부터 다음 블록의 시작까지 실제 화면 값이며 중첩 요소에 중복 가산하지 않아요. 간격을 만들려고 빈 문단이나 연속 `<br>`을 넣지 않아요.


## 용어·보기·문항 결함의 일관성

recall은 원천에서 확인한 이름과 개념을 짧게 대응하고, pitfall은 인접 오답과의 결정적 차이를 설명한다. 비교 대상·단위·조건·결과를 분명히 한다. 자료에 없는 동의어·번역·가정을 원문에 끼워 넣지 않는다. 긴 설명을 start·solve·pitfall에 복제하지 않는다.

객관식은 understand에서 긍정/부정 질문 방향과 단일/복수 선택 조건을 밝힌다. solve에서는 보기마다 근거를 판정하고, 진술의 참·거짓과 질문에 대한 선택 적합성을 구별한다. ‘항상’ 같은 절대 표현만으로 오답으로 정하지 않는다. ㄱㄴㄷ형은 개별 진술을 판정한 뒤 조합을 고른다. 선택지 목록을 소문항으로 바꾸지 않는다.

표현 결함·필요 가정·출제 의도상 답과 엄밀한 답의 차이는 understand·solve에 밝히고, verify의 소거·검산과 pitfall·sum에도 같은 조건과 유보를 유지한다. 공식 답 미확인이면 그 사실을 밝힌다. 공식 답 부재만으로 독립 검산 성공/실패를 추정하지 않는다. 정상 문항에는 불필요한 모호성 문구를 붙이지 않는다. 이 원칙은 과목별 기존 disputed 정책을 완화하지 않는다. DS의 UB·비종료·은행 충돌, ML의 미해결 수학적 모호함, EC2의 workbook 풀이와 독립 검산 불일치는 계속 발행을 보류한다. 원자료를 몰래 수정하지 않는다.

해설·답을 본 뒤의 성공을 독립 회상이나 학생 숙달 확인으로 보고하지 않는다. retry는 해설을 닫고 개념·첫 줄을 다시 떠올리게 한다. 객관식 정답 모델은 입력의 검증된 데이터만 사용하며 해설에서 새로 추정하지 않는다.


**수치 표시:** 계산 결과는 소수점 둘째 자리까지 반올림해 표시한다. 정수·짧은 소수에 불필요한 0이나 말줄임표를 붙이지 않는다. 내부 계산은 반올림 전 정밀도를 유지하고, 반올림한 결과는 등호 대신 근사 기호로 구별한다. 간단한 분수·근호는 유지할 수 있으며 원문 입력값·요구 정밀도는 보존한다.

## 공통 모드 이득의 본풀이

PROFILE CIRCUIT-02·GAIN-01에 따라 **성립 조건 → $2R_{SS}$ 반회로 → 출력 단락의 $G_m$ → 입력 영점에서 부하 포함 $R_{out}$ → 부호 있는 곱** 순서를 적용한다. $v_P=(2i)R_{SS}=i(2R_{SS})$로 2배를 설명하고 CM 대칭선을 가상 접지로 두지 않는다. $G_m\approx1/(2R_{SS})$와 $R_{out}\approx R_L$를 각각 구한 뒤 $A_{CM,SE}\approx-G_mR_{out}$로 연결하며, 결과식만 제시하지 않는다. 테일 저항은 필요한 유효 근사값을 먼저 쓰며 시험 회로·긴 유도는 뒤로 분리한다. $R_{out}$ 정확 전체식·긴 노드방정식은 원문 예외가 아니면 내부 검산에 둔다. 부하 불일치에서는 같은 가지 전류 조건을 확인하고 유한 $r_o$에 의한 전류 차이가 필요하면 실제 연결을 유지한다. 전류 거울·능동 부하는 연결별로 판단하며 동일한 두 반회로를 강제하지 않는다. 원문이 특정 증명·정확식·다른 방법을 요구하면 그 방법을 본풀이에 유지한다. 요약·MD·답안 PDF도 중간량의 의미·조건을 맞춘다.

### 전압이득의 계산 순서

PROFILE GAIN-01에 따라 원문 지정 방법을 우선한다. 중간 노드를 거치는 신호 경로를 단별로 읽을 수 있으면 먼저 $A_v=(v_X/v_{in})(v_{out}/v_X)$처럼 목표 전달비를 곱으로 쓰고 각 항의 실제 부하와 부호를 채운다. 단별 곱의 각 판단과 식은 일반 `data-answer-step`으로 표시한다. 유한 $r_\pi$·$r_o$, 우회 전달, 개루프 복제의 종단 등 답에 영향을 주는 조건을 유지한다.

귀환 회로에서는 감지량과 반송량을 원 회로에서 짚고, 복제의 종단과 남는 로딩을 보여 준다. 뒤의 이득 항이나 폐루프 계산에서 다시 쓸 개루프 저항을 연결에서 바로 읽을 수 있으면 목표 곱을 쓰기 전에 구하고 같은 기호로 재사용한다. 개루프 회로에서 $I_{in}\parallel R_p$가 독립된 입력 블록이면 $v_{\mathrm{Th}}=I_{in}R_p$와 직렬 $R_p$로 변환한다. 목표 전달비의 첫 인자는 $v_{\mathrm{Th}}/I_{in}=R_p$로 쓴다. CG의 소스 또는 CE의 베이스까지 생기는 분압을 $v_{\mathrm{Th}}$ 기준 이득에 한 번 포함하고, 실제 입력 노드 전압과 $R_{in,\mathrm{open}}$을 각각 구별한다. 예제 12.29처럼 두 포트의 개루프 저항이 바로 읽히는 경우는 출력·입력저항 → $R_0$의 연쇄 곱 → CG·CS 항 순서다. 소문항의 요구 순서나 별도 측정에 의존하는 양은 해당 문제의 순서를 따른다.

귀환율은 귀환망의 시험 조건과 반송량의 기준 방향을 먼저 보여 주고 동일한 기호로 비를 쓴다. 방향을 원 회로에서 곧바로 읽기 어렵거나 인쇄 화살표와 풀이의 기준이 다르면 시험 가지를 해당 단계에 두고 기호 대응을 밝힌다. 알려진 CS 또는 팔로워 이득을 연쇄 곱의 한 인자로 바로 쓰는 경우에는 별도 $G_m$ 측정 표지를 붙이지 않는다.

$G_m$·$R_{out}$ 경로를 쓰는 경우에는 성립 조건·입출력 정의 → 출력 단락의 $G_m$ → 입력 영점에서 부하 포함 $R_{out}$ → 부호 있는 $A_v=-G_mR_{out}$ 순으로 보인다. $R_{out}$ 정확 전체식·긴 노드방정식은 PROFILE에서 정한 예외가 아니면 내부 검산에 둔다. 기존 미수정 문항에 소급 적용하지 않는다.


### 새/수정 Gm–Rout 경로의 구조 검사

$G_m$·$R_{out}$ 방식으로 쓰는 새/수정 전압이득 경로에는 `data-gain-route="gm-rout"`와 그 안의 `data-gain-stage="gm"`, `"rout"`, `"gain"`을 사용한다. 수정하지 않는 기존 문항의 표지 없는 본문은 보존하고 사람 검토 범위로 남긴다. 세 단계는 같은 경로에 각각 한 번, 그 DOM 순서로 두고 각 단계의 제목 밖에 보이는 비어 있지 않은 `$...$` 또는 `$$...$$` 중간 수식을 쓴다. 경로를 중첩하거나 수식을 숨기지 않는다. 기존 보이는 `data-answer-step` 요소 안에도 넣을 수 있으며 새 본문이나 두 번째 풀이를 만들지 않는다. 이 속성들은 표시/MD 내용이나 답안 선택 의미를 바꾸지 않는다.

공통 HTML 검사와 EPE 조각 계약은 선언된 경로의 누락·순서·빈 식·명시적 숨김을 검사한다. 식의 정당성·입출력과 측정 조건·외부 부하 병렬·부호·필요한 유한 β/ro는 사람이 검토한다. 표지가 없는 과거 문장을 정규식으로 전압이득 풀이로 추측하지 않는다. 이 방식에 해당하는 새/수정 문항에 표지가 빠졌으면 보완하고 세 단계의 순서를 확인한다. 연쇄 곱은 GAIN-01을 적용한 경로로 기록하고 일반 답안 단계에서 식을 확인한다. 다른 목표나 원문 지정 방법은 GAIN-01 감사에 근거를 적는다. 숨김 CSS의 실제 가시성은 브라우저에서도 확인한다.
