# 문항 작성 규칙

## 범위와 난이도

- 정리노트의 실제 토픽 순서로 수업에서 새로 배운 조작·판단을 고른다. 예를 들어 연결 방식, $R_{in}$과 $R_{out}$ 변화, 귀환의 부호, MOS 동작 조건을 문항의 결정 지점으로 삼는다. 반복·예고·교재 보충은 출제 범위에서 제외한다.
- 목표당 1~2문항, 전체 6~16문항이 보통이다. 한 문항에는 판단 하나 또는 한두 단계 계산을 둔다. 4지선다와 값 입력형을 개념에 맞춰 섞고 객관식 정답 위치를 분산한다.
- 기존 복습문제는 `.assets/problems.txt`에 있는 경우 그 문항 ID의 workbook 원문과 비교한다. 기존 문항의 수치나 보기 순서만 바꾼 형태는 피한다. 오답은 실제로 생길 법한 조건·부호·연결 해석의 오류로 만들고, 오답마다 어떤 판단에서 갈렸는지 설명한다.
- 회로 해석에 필요한 기준 노드, 전류 방향, 신호 종류, 동작 영역과 근사 조건을 제공한다. 값을 입력받을 때 숫자만인지 단위까지인지, 반올림과 부호 규칙도 발문에 적는다. 단위의 대소문자는 구분하며 동등한 표기는 `accepted`에 열거한다.
- 해요체로 짧게 쓴다. 제목은 답을 드러내지 않는다. 힌트는 처음 볼 노드나 적용할 조건 하나를 짚어 준다. 발문·보기·힌트·풀이에서 수식은 `$…$`로 쓴다.

## 파일 형식

`objectives.json`은 `range`, `slug`, `objectives`를 갖는다. 각 목표는 아래와 같이 기록한다. `source.slide`은 HTML 토픽에 슬라이드 태그가 있으면 그대로 적고, `source.stt`는 실제 전사의 절·시점과 근거를 가리킨다.

```json
{
  "id": "o1",
  "topic_id": "s0-current-return",
  "concept": "전류 반송",
  "source": {"date": "1113", "slide": "L06 s23", "stt": "Part 01 전류 반송을 도입하는 대목"}
}
```

`items.json`은 `items` 배열을 갖는다. 공통 키는 `id`(`q1` 등), `objective`(`o1` 등), `format`, `title`, `stem_html`, `hint`다. `stem_html`에는 속성 없이 `p, strong, em, code, br, ul, ol, li`를 쓸 수 있다.

- `format: "mcq"`는 `options`에 A~D 순으로 `id`, `text`, `why`를 두며, 오답에는 `misconception`을 더한다. `answer`는 보기 문자 하나다.
- `format: "short"`는 `answer: {"canonical":"20","accepted":["20.0"]}`와 `solution` 문자열 배열을 갖는다. 예시의 경우 입력 단위는 발문에 고정한다.
- 회로도가 필요하면 `figure_svg` 문자열에 독립 SVG를 넣는다. `xmlns`, `viewBox`, `aria-label`을 지정하고 직접 선·도형·텍스트로 그린다. `currentColor`를 사용해 두 테마에서 보이게 한다. 스크립트·외부 참조·`style`·이벤트 속성은 사용하지 않는다. 학습자와 독립 풀이자는 같은 SVG를 본다.
