# 섹션 작성 규칙

역할·파일 인계는 [delegation.md](delegation.md)를 따른다. 범위 설계자가 만든 `<RUN>/briefs/<sid>.json` 경로만 받은 호출도 아래 작성자 브리프와 같은 입력 계약으로 허용한다. 파일의 실제 경로·담당 토픽·조건을 읽고, 개인 명세 전체와 현재 snapshot 확인 및 아래 작성자 자기 검사를 그대로 수행한다. 상세 설명·자기 검사·수정 기록은 현재 생성 브리프의 `report` 경로에 쓰고, 부모에게는 상태·산출물/보고 경로·담당 topic ID·미해결만 800자 이하(개행 포함 Python len)로 반환한다. 상세 본문이나 전체 수식·자기 검사 답안을 메시지에 복사하지 않는다.

선발 공통 명세는 `references/problem-selection.md`의 exam-first-v2다. 최대 20문항·기출 우선·다른 회차 사용 문항 항상 제외이며 참고 풀이 없는 문항도 직접 풀이/독립 검산 후 수록한다. 고정 종류 비율이나 기존 10문항 목표를 되살리지 않는다. 핵심/추가·소문항 묶음 수·추정 시간은 selection.json에 보관한다. 해설 HTML·동반 MD의 학습량 행은 출력하지 않고 PDF 표시는 기존 PDF 정책을 따른다. 원문·짧은 제목에 메타데이터를 삽입하지 않는다.

## 문제 해설의 순서·제목·수식 행

문제 해설은 자식 스킬의 [간략 해설 저작 규칙](../../ec2-problem-explain/references/authoring.md)을 따른다. 회로 위치 표시와 첫 판단을 연결하고 첫 식·필수 중간식·소문항별 답을 한 흐름으로 쓴다. 정리노트의 순수 개념 토픽은 기존 레이어 순서를 유지한다.

**한 행에 하나의 식:** 독립된 계산 대상은 각각 별도 display 블록/MD 줄/PDF 행에 쓴다. 서로 다른 $g_m$, $r_\pi$, $r_o$ 계산을 쉼표·\quad·\qquad로 한 줄에 묶지 않는다. 같은 양의 `식 = 대입 = 결과` 연속 등식과 실제 같은 값을 가진 소자의 등식 묶음은 유지할 수 있으며, 폭을 넘으면 단계별로 세로로 나눈다. 설명문의 짧은 기호·조건은 인라인으로 쓸 수 있다.

검토에서는 독립 계산이 실제로 별도 행/블록인지 HTML·동반 MD·답안 PDF 각각 확인한다. 같은 양의 연속 등식을 이유 없이 잘게 쪼개지 않는다. 현재 구형 route 추출과 새 통합 본문의 호환성을 확인하고, 미지원이면 발행을 보류한다. 문서 개정이나 정적 검사를 정상 발행/수학 검산/화면 검토로 간주하지 않는다.

- 병렬 가지 순서 필수: 제어 전류원과 $r_o$가 병렬이면 반드시 **제어 전류원 왼쪽 → $r_o$ 또는 병렬 합성 저항 오른쪽 → 출력 접속 맨 오른쪽** 순서로 그린다. 입력은 그 왼쪽, 이미터/소스 축퇴 저항은 해당 노드 아래에 둔다. $r_o$를 생략한 축약 모델에는 없는 저항을 추가하지 않는다. 그 모델의 제어원 위치를 병렬쌍의 배치 규칙으로 일반화하지 않는다. 풀이 본문의 모든 SVG와 답안 PDF에서 소자·단자 전체 배치를 대조하고, 전기적 등가성만으로 위치 불일치를 승인하지 않는다.
- 노드 점과 시험 표기 필수: 접지 표기만 하는 비분기 단자와 접지 기호의 직접 접속점을 제외하고, 입력·출력·시험 노드와 이름을 붙인 전압 노드에는 연결 위치가 분명한 눈에 보이는 점을 찍는다. 출력 시험전압 노드의 점은 출력 도선의 실제 맨 끝이자 가장 오른쪽 단자에 둔다. 점 오른쪽으로 도선(ink)이 더 이어지거나 연장된 도선 중간에 점이 놓이면 안 된다. 시험 노드 전압 $V_t(+)$는 그 끝점 위에 둔다. 유입 시험전류는 오른쪽에서 왼쪽으로 흐르며, 왼쪽을 향하는 $i_t$ 화살표는 $V_t$ 점 왼쪽의 도선 구간에 둔다. $i_t$ 라벨도 점 왼쪽에서 그 화살표 아래나 곁에 둔다. 화살표 전체가 점 왼쪽에 머물고 점을 덮지 않도록 화살표 꼬리와 점 사이에 작은 간격을 남긴다. 화살표나 전류 라벨을 점 오른쪽에 놓지 않는다. 다른 시험 기호($v_x/i_x$ 등)를 쓰면 같은 배치와 정의를 적용한다. 선 교차만 있고 연결되지 않은 곳에는 점을 찍지 않는다. 라이트·다크 HTML과 실제 답안 PDF에서 점·라벨·화살표의 분리와 가시성을 각각 확인한다.
- 회로 안 글자와 점의 정돈: SVG 안에는 소자 이름·값·제어 전류원 라벨(예: $g_mv_\pi$), 노드 이름·극성·방향처럼 실제 회로를 읽는 표기를 남긴다. 분석용 $G_m$ 제목·측정 조건 문구·유도 설명은 그림 아래 figcaption이나 수식 문단에 둔다. 출력 단락·입력 영점의 실제 연결은 그림에 보존한다. 접지 입력 위의 독립 제목 `Rout`처럼 불필요한 제목은 옮겨 중복하지 않고 삭제한다. 가까운 노드 관계는 유도 설명이 아니고 겹치지 않을 때만 남길 수 있다. 접지 표기만 하는 비분기 단자·접지 기호의 직접 접속점은 제외하고 입력·출력·시험 단자, 이름 붙인 내부 전압 노드, 실제 분기 접속점의 점은 유지하되 이름도 분기도 없는 직선 도선 중간의 장식 점은 없앤다. 모든 도선에 점을 추가하라는 규칙이 아니다. $V_{out}(+)$·$V_t$ 등 라벨은 아래첨자까지 포함한 실제 글리프 경계상자가 도선에서 최소 0.6em(보통 화면에서 약 8px) 떨어지게 배치한다. 텍스트 기준선 간격만 확인하지 않는다. 필요하면 라벨을 옮기고 viewBox 위쪽 여백을 늘린다. 풀이 본문의 모든 SVG를 열거하여 라이트·다크 HTML과 실제 답안 PDF의 보통 보기 크기에서 이 간격·클리핑·겹침을 확인한다. 병렬 제어원 왼쪽/$r_o$ 오른쪽/출력 맨 오른쪽, 맨 끝 $V_t$ 점 오른쪽 도선 없음, 점 왼쪽의 왼쪽 방향 $i_t$와 라벨 배치도 유지한다.
- 정리노트 위치 표시 예외: 정리노트의 `figure.circuit`에는 본문이 짚는 위치 표시 ㉠㉡㉢㉣(`fig-loc`)을 둘 수 있다. 회로를 읽는 표기이며 제목·유도 설명이 아니다. 도선과의 간격은 글자 크기의 0.25em 이상이고, 다른 라벨의 0.6em 규칙은 그대로다. 다른 그림·문제설명·답안 PDF에는 쓰지 않는다.
- 접지·전압 라벨·노드 색 대응: 접지 기호에 직접 닿는 점과 접지만 표시하는 비분기 입력 단자의 점은 생략한다. 접지로 이어지는 회로라도 별도의 실제 분기 접속점·이름 있는 비접지 노드는 유지한다. $v_e$ 등 전압 이름은 다른 소자나 저항 옆으로 멀리 밀지 않고 해당 노드 바로 곁에 둔다. 아래첨자·극성을 포함한 실제 글리프 경계로 도선과 최소 0.6em 간격을 확보하면서 가능하면 0.6–1em 정도의 가까운 간격을 목표로 한다. 혼잡 때문에 더 벌리면 배치 이유를 검토에 기록한다. 노드 점과 해당 전압 이름·극성은 같은 파랑 또는 빨강으로 묶는다. 주요 신호 경로를 따라 파랑·빨강을 교대하고 가까운 전압 라벨끼리 최대한 다른 색을 쓴다. 같은 전기적 노드는 다른 위치의 점도 같은 색이며, 모든 인접 노드를 반대색으로 만드는 그래프 채색을 강제하지 않는다. 접지 표기·도선·소자/제어원 라벨·전류 화살표/라벨·본문 수식의 색은 이 노드 색 규칙으로 바꾸지 않는다. 색 없이도 노드 이름과 극성으로 구분되어야 한다. - 자기 검사(끝내기 전): 토픽별로 `required_terms`가 모두 문자 그대로 들어갔는지, `$` 짝, `links` 항목이 해당 토픽 안에 있는지, 금지어 `<forbidden 목록>`이 없는지. 금지어는 예고 토픽 `<preview_topic>` 안에서만 허용된다 — 이 토픽에는 예고 제목을 빠뜨리지 말고 쓴다. eli5 레이어마다 문장 수(figcaption 포함)가 3 이하이고, 필요한 용어는 짧게 풀었는지 확인한다. 아래 "이해되는 설명의 순서"에 따라 첫 설명과 작은 예시만으로 다음 상태를 예측할 수 있는지 자기 검사한다. 긴 식·유도는 formal 레이어로 옮긴다. 조각 어디에도 이모지를 쓰지 않았는지. `layers`가 빈 목록이 아닌 토픽마다 마지막에 `<div class="sum" hidden>`이 있고, 그 식·용어가 본문과 같은 표기인지. 아래 "정확히 말하면의 길잡이"대로 formal 소제목 개수, 소제목 구간마다 굵은 결론 하나, 토픽 끝 확인 질문 하나와 그 답, 레이어 안 `<details>` 없음을 확인했는지. 아래 "토픽 회로"대로 manifest의 회로를 모두 그렸고, 글과 회로의 ㉠㉡㉢이 빠짐없이 짝이 맞는지. 그림 설명(글, `aria-label`)이 SVG 클래스의 실제 모양(채움/윤곽)과 맞는지.
- 보고: 파일 경로, 토픽별 한 줄, 요약에 있었지만 넣지 않은 것과 이유를 현재 생성 브리프의 `report` 경로에 기록한다. 부모에게는 위 800자 이하(개행 포함 Python len) 반환 계약을 따른다.

## 범위
- 요약의 슬라이드 대조표에서 "다룸/일부"인 내용만 쓴다. "예고만/안 다룸"은 `s<N>-next`에 제목만.
- 수업에서 말한 모든 개념, 칠판 유도, 교수님 비유와 강조 발언을 빠짐없이 싣는다(잡담 제외). 같은 뜻의 인용이 여럿이면 가장 분명한 하나를 대표로 남기고, 나머지는 빠뜨린 것이 아니라 합친 것으로 작성자 보고에 적는다(아래 "문체"의 prof/warn). 다만 $R_{out}$의 정확식 → 근사식 전개는 위 표시/검산 경계에 따라 내부 evidence에만 보존한다. 원문이 정확 결과 또는 수업 기본 큰 곱 근사와 반대인 조건·수치를 명시할 때만 이유를 짧게 밝히고 필요한 결과를 싣는다.
- STT 오인식과 말실수는 올바른 형태로 쓴다. 식이 틀렸던 경우만 각주 한 줄로 "(수업 중 X로 적었다가 정정)".

## 토픽 마크업 (이 순서)
```html
<article class="topic" id="…"><h3>…</h3><div class="tags"><span class="tag date">MMDD 수업</span><span class="tag slide">L0X sN</span></div>
  <div class="layer eli5"><span class="layer-title">쉽게 말하면</span><p class="lead">무엇이 어떻게 바뀌는지 직접 말하는 한 문장</p> …그림… </div>
  <div class="layer formal"><span class="layer-title">정확히 말하면</span> <figure class="figure circuit">…</figure> <h4 class="sub">소제목</h4> …정의·수식·단계별 유도(ol.steps)… <h4 class="sub">다음 소제목</h4> … </div>   ← 아래 "정확히 말하면의 길잡이"
  <div class="layer prof"><span class="layer-title">교수님 말씀</span> …비유·일화, 원문은 blockquote… </div>
  <div class="layer warn"><span class="layer-title">꼭 기억해요</span> …짧은 원문 인용(근거 위치는 별도 검토 기록에만 보관)… </div>   ← 강조 발언이 있을 때만
  <div class="layer supp"><span class="badge supp">보충 · 수업에서 유도하진 않았어요</span> … </div>             ← manifest supp=true만
  <div class="quiz after"><p class="q">확인해 봐요. …</p><details><summary>답 보기</summary><p>…</p></details></div>   ← layers가 빈 목록이 아닌 토픽만, 레이어 뒤
  <div class="sum" hidden>…페이지 요약(아래)…</div>                                                    ← layers가 빈 목록이 아닌 토픽만, 맨 끝
</article>
```
- 위젯이 있으면 레이어들 뒤, `.quiz.after` 앞에 둔다.
- 레이어 제목과 배지 글자는 위와 글자 그대로 쓴다. 이모지, 장식 기호(★, ↗ 같은 아이콘; 상태 변화의 순서를 나타내는 →는 허용), "아래를 보세요" 같은 안내 문장은 쓰지 않는다.
- 템플릿이 토픽 하나를 한 화면에 보여 준다. 토픽은 그것만 읽어도 이해되게 쓰고, "위에서 본 것처럼"처럼 앞 토픽의 위치에 기대는 말 대신 `<a href="#토픽id">토픽 제목</a>`으로 잇는다.
- 요약·예고 섹션: 치트시트는 표(`<div class="table-wrap"><table>`), 예고는 `<ul>`, 링크는 `<ul><li><a>`.
- 복습문제 PDF 링크는 `href="{{PROBLEM_PDF}}"`(문제), `href="{{ANSWER_PDF}}"`(답안)로 쓴다(조립기가 실제 파일명으로 바꾼다). 링크 글자는 "복습문제 N개 (PDF)", "답안 (PDF)"처럼 쓴다. 문제가 0개인 팩은 링크 대신 "이번 범위에는 workbook 문제가 없어요." 한 줄을 쓴다. 다른 링크는 manifest `href`를 글자 그대로.

## 왜 쓰는가 페이지 (`why-circuit`)
노트를 열면 표지 다음에 처음 보이는 화면이다. 이번 범위의 회로를 **왜 쓰는지**만 말하고, 자세한 내용은 뒤 토픽으로 보낸다.
- formal 레이어는 이 4단계를 순서대로 쓰고, 단계 제목을 각각 `<h4 class="sub">`로 둔다(예: `<h4 class="sub">풀고 싶은 문제</h4>`). 단계마다 결론 한 문장을 `<b>`로 감싸고, 그 내용을 자세히 다루는 뒤 토픽으로 `<a href="#토픽id">토픽 제목</a>`을 건다.
  1. **풀고 싶은 문제**: 무엇이 필요했나(예: 더 큰 이득, 잡음에 강한 입력).
  2. **단순한 해법과 그 한계**: 가장 쉬운 회로로 하면 어디서 막히나. 식은 1~2줄만.
  3. **핵심 아이디어**: 이번 회로가 그 한계를 넘는 방법 한 문장.
  4. **대가와 쓰이는 곳**: 무엇을 내주나(헤드룸, 소자 수, 전력 등), 실제로 어디에 쓰나.
- 범위에 회로가 여럿이면 회로마다 1~4를 짧게 반복하거나, 하나의 문제에서 다음 회로로 이어지는 흐름으로 쓴다. 한 토픽 안에 모두 담는다.
- 유도, `ol.steps`, 소신호 등가회로는 쓰지 않는다. 그건 링크한 토픽의 몫이다.
- eli5 레이어: 문제 → 단순한 해법의 한계 → 이번 회로로 이어지는 흐름도 SVG(id `fig-why`) 1개. 비유는 흐름을 이해하는 데 도움이 될 때만 쓴다.
- 근거 우선순위: 요약의 `## 동기 발언` > 강의 슬라이드 첫 장 > Razavi 장 도입부. 교수님 발언은 prof 레이어에, 수업에서 말하지 않은 동기는 supp 레이어(manifest `supp: true`)에 싣는다.
- 링크는 `<a href="#토픽id">`로 쓴다. 마크다운 `[글자](#id)`는 화면에 그대로 찍히므로 `check_html.py`와 `insert_why.py`가 막는다.
- 확인 질문은 계산이 아닌 개념 질문으로 쓴다(예: "저항비 $K$만으로 증폭기를 만들면 안 되는 이유는?"). 답은 이 페이지의 4단계에서 찾을 수 있어야 한다.
- 위젯과 `<script>`는 넣지 않는다. 맨 끝에 `.sum`을 둔다(아래).

## 정확히 말하면의 길잡이
처음 배우는 학생이 긴 formal을 끝까지 읽는 동안 길을 잃지 않게 한다. 내용을 숨기거나 줄이지 않고, 다 읽는다고 보고 읽는 순서 안에 길잡이를 넣는다.
- **소제목**: formal을 내용 단위로 나눠 `<h4 class="sub">`를 2~6개 둔다. 제목은 그 구간이 답하는 질문이나 하는 일로 쓴다(예: "숫자로 확인하기", "$A_1$은 왜 흔들리나요", "$K$는 왜 정확한가요"). 본문 블록(`p`·`ol`·`ul`·`figure`·표 등, 레이어 제목 제외)이 5개 이하인 짧은 formal은 생략할 수 있고, 6개 이상이면 반드시 둔다(`check_html.py`의 `formal-no-subheads`). 소제목 바로 뒤 문장이 같은 질문을 되풀이하면 그 질문은 지운다.
- **굵은 결론**: 소제목 구간마다 그 구간의 결론 문장 또는 절 하나를 `<b>`로 감싼다. 새 문장을 쓰지 않고 원문 문장을 고른다. 굵은 글씨만 따라 읽어도 토픽의 흐름이 이어지는지 자기 검사한다. 한 구간에 굵은 글씨를 여럿 두지 않는다.
- **식|이유 두 열**: `ol.steps` 항목 중 식 블록 앞 설명이 60자 이하이고 식 뒤에 글이 없으면 `<li><div class="drow"><div>$$…$$</div><p class="why">설명</p></div></li>`로 쓴다. 넓은 화면에서는 왼쪽 식·오른쪽 이유, 좁은 화면에서는 이유가 위로 온다. 설명이 길거나 식 사이에 글이 끼는 항목은 기존 모양으로 둔다. 한 목록에 두 모양이 섞여도 된다.
- **확인 질문**: 토픽 끝(레이어·위젯 뒤, `.sum` 앞)에 `<div class="quiz after">` 하나를 둔다. 질문은 "확인해 봐요."로 시작하고, 본문 작은 예시와 같은 절차로 풀리는 문제에서 숫자만 바꾼다. 처음 보는 개념이나 본문에 없는 절차를 요구하지 않는다. 답은 `<details><summary>답 보기</summary><p>…</p></details>` 안에 결과와 계산 한 줄로 쓴다. 정의·구조 토픽은 작은 사례를 주고 어디에 해당하는지 묻는다.
- **금지**: 레이어 본문을 `<details>`로 접지 않는다(`folded-body`). 토픽 머리에 질문을 두지 않는다. 처음 배우는 학생은 건너뛸지 판단할 수 없고, 아직 배우지 않은 문제는 풀 수 없기 때문이다.

## 토픽 회로 (`figure.circuit`)
유도식을 읽는 동안 회로가 계속 보여야 한다. 템플릿이 화면 크기와 상관없이 회로를 formal 위쪽(상단 바 바로 아래)에 고정한다. 높이 500px 미만인 화면에서만 고정하지 않는다. 작성자는 formal 안에 한 번만 쓴다.
```html
<figure class="figure circuit"><svg id="fig-circuit-<kebab>" viewBox="…" role="img" aria-label="한국어 설명">…</svg><figcaption><span class="loc">㉠</span> 위치 이름 · <span class="loc">㉡</span> 위치 이름 (강의노트 s37)</figcaption></figure>
```
- **쓰는 순서**: 강의노트 PDF의 그 쪽을 연다 → 회로를 그린다 → 글이 짚을 곳에 ㉠㉡㉢을 붙인다 → 글을 쓴다. 글을 먼저 쓰고 그림을 붙이지 않는다.
- **무엇을**: 그 토픽 manifest의 `circuits`를 id 그대로 모두 그린다. `source`가 `LNN sK`이면 그 쪽의 소자·접속·극성·단자를 그대로 옮긴다. 노트의 기호와 다른 이름만 노트 기호로 바꾸고, 바꾼 것과 뺀 것을 보고에 적는다. `new: …`이면 그 근거로 새로 그리고 figcaption에 "수업 예시를 옮긴 그림"처럼 밝힌다(STT 위치는 쓰지 않는다). 슬라이드 이미지는 붙이지 않는다.
- **어디에**: formal 레이어의 직계 자식이며 첫 `$$` 식보다 앞이다. 하나면 레이어 제목 바로 뒤, 둘이면 각각 자기 유도 구간의 `<h4 class="sub">` 바로 앞에 둔다. 한 토픽에 최대 2개다. 식은 바로 앞 회로로 읽는다. `why-circuit`과 `layers`가 `[]`인 토픽에는 두지 않는다.
- **글과 짝**: 회로의 위치는 `<text class="fig-text fig-loc" style="font-size:17px">㉠</text>`, 글과 figcaption은 `<span class="loc">㉠</span>`로 쓴다(`<b>`로 감싸지 않는다). 독립 SVG에서는 변환기가 이 표시를 원과 Pretendard 자모로 바꿔 그리므로 작성자는 ㉠ 문자를 그대로 쓴다. 유도 단계마다 전류·전압이 회로의 어디에 있는지 먼저 짚고 식을 쓴다. 예: "㉠ 접점으로 들어온 $I_X$에서 $I_F$가 아래로 빠지고, 남은 전류가 ㉡ $R_{in}$을 지나요." 글에만 있거나 회로에만 있는 위치는 검사에 걸린다(`loc-not-in-circuit`, `loc-unused`). 토픽마다 ㉠부터 다시 시작하고, 회로가 둘이면 이어서 매긴다.
- **크기와 모양**: 위쪽에 고정해도 읽히게 viewBox 폭 330·높이 250 안팎으로 작게 그린다. 저항·전원·증폭기·접지·화살표처럼 도선이 아닌 모양은 `<g data-symbol="이름">`으로 감싼다(라벨 간격 검사에서 빠진다). 도선은 감싸지 않는다. 위 "회로 계약"과 배치·점·색·라벨 간격 규칙은 이 회로에도 모두 적용한다.

## 페이지 요약 (`.sum`)
화면 오른쪽 "요약" 패널에 그 토픽의 핵심만 보여 준다. 템플릿이 토픽의 **직계 자식** `.sum`을 패널로 옮기므로 토픽 안 맨 끝에, 레이어 밖에 둔다. `hidden`은 꼭 붙인다(본문에 두 번 보이지 않게).
```html
<div class="sum" hidden>
  <p class="sum-lead">토픽 핵심 한 문장("~해요" 체)</p>
  <p class="panel-label">핵심 식</p>
  <ul class="eq-list"><li><span class="eq-name">식 이름</span>$$…$$</li></ul>
  <p class="panel-label">용어</p>
  <dl class="terms"><dt>용어(영어)</dt><dd>한 줄 뜻</dd></dl>
</div>
```
- 새 내용을 쓰지 않는다. 본문(formal 레이어)에 이미 나온 식·용어를 **같은 TeX 표기로** 필요한 만큼 고른다. 요약에만 있는 식이나 설명은 두지 않는다.
- 패널은 좁으므로 긴 식은 하나의 `$$\begin{aligned}...\end{aligned}$$`에서 관계를 유지하며 나눈다. 정렬용 `&`는 HTML에서 `&amp;`로 쓴다. 본문과 같은 기호·항을 유지하고 화면의 실제 잘림·넘침을 확인한다.
- 식이 없는 토픽은 "핵심 식" 줄과 `eq-list`를 빼고, 용어가 없으면 "용어" 줄과 `dl`을 뺀다. `sum-lead`는 항상 쓴다.
- 요약·예고 섹션처럼 `layers`가 `[]`인 토픽에는 두지 않는다.

## 문체
- 쉽게 말하면(eli5): 짧고 직접적인 1~3문장(figcaption 포함) + 그림. 필요한 용어는 짧게 풀고, 작은 숫자·상태 변화 표기는 허용한다. 긴 식과 유도는 formal에 둔다. 토스처럼 짧고 다정한 "~해요" 체.
- 정확히 말하면(formal): 선택 모델과 조건 안에서 빠짐없이, 정확하게. $R_{out}$은 이 레이어에서도 유효한 근사식부터 시작하며 정확식 유도를 보충하지 않는다(위 예외 제외). 유도는 한 줄에 한 단계. 문장은 "~해요" 체, 유도 단계는 식 위주로 짧게.
- 교수님 말씀(prof)/꼭 기억해요(warn): 원문 인용은 15단어 안팎으로 줄인다. 공개 본문에는 STT 위치 정보를 붙이지 않고 별도 감사 기록으로 대조한다. 같은 뜻의 인용이 여럿이면 가장 분명한 하나만 남긴다. prof와 warn에 같은 인용을 다시 쓰지 않는다. warn은 formal에 없는 주의(헷갈리기 쉬운 구별, 조건, 흔한 실수)가 있을 때만 두고, formal 문장을 되풀이하는 설명은 쓰지 않는다.
- UI 글은 한국어, 전문용어는 영어 병기(예: 출력저항(output resistance)). 한 문장에 한 가지만 말하고, 군더더기 수식어("아주", "정말", "한번")는 뺀다.

## 이해되는 설명의 순서
- 첫 설명은 **핵심 동작 → 작은 예시 → 이유·수식 유도** 순서로 쓴다. 비유는 선택 사항이며, 실제 값이나 상태 변화가 더 직접적이면 그것을 쓴다.
- 변화 규칙을 설명할 때는 **시작 상태 → 변화 규칙 → 결과**를 보여 준다. 예: 실수 pole을 지날 때마다 기존 기울기에 −20 dB/dec를 더하므로 0 → −20 → −40. 이득이 순간적으로 20 dB 떨어지는 것과 기울기가 바뀌는 것을 구별한다.
- 예시에는 단위·축·근사 조건을 붙인다. pole 예시는 평평한 저주파 이득에서 시작하는 저역통과 응답이고 관심 범위에 zero 영향이 없는 경우로 한정하며, 실제 곡선은 부드럽게 변한다는 점을 밝힌다.
- formal의 첫 부분에서 작은 예시를 실제로 적용한 뒤 유도한다. 그림의 라벨과 페이지 요약도 같은 규칙·순서를 보여 준다.
- 자기 검사: 첫 설명과 예시만 읽고 풀 수 있는 작은 적용 질문을 만들고 답·이유를 기록한다. 예: "두 번째 pole 뒤 −40일 때 세 번째 pole 뒤는?" → "−60 dB/dec: −40에 −20을 더함". 본문과 질문에 붙인 조건이 같은지도 확인한다. 이 질문을 토픽 끝 확인 질문(`.quiz.after`, 위 "정확히 말하면의 길잡이")으로 공개하고, 기록은 작성자 보고에도 포함한다.
- 순차적 예측 규칙이 없는 정의·구조 토픽은 구체적 사례를 하나 골라 정의가 어디에 해당하는지 설명하게 한다. 변화 단계를 억지로 만들지 않는다.

## 수식
- `$…$`(인라인), `$$…$$`(디스플레이)만. 본문에 리터럴 `$` 금지.
- TeX 안의 `<`, `>`는 `\lt`, `\gt`로 쓴다. `aligned`의 정렬용 `&`는 HTML에서 `&amp;`로 이스케이프한다. 서로 다른 계산 대상은 별도 `$$`로 유지한다.
- 표기 고정(manifest `required_terms`와 같게): 트랜스컨덕턴스 `g_m`, 출력저항 `r_O`, 단의 출력저항 `R_{out}`, 전압 `V_{GS}`·`V_{DS}`·`V_{BE}`·`V_{CE}`, 이득 `A_v`, 병렬은 `\parallel`(`||`, `//` 금지).
- 근사는 `\approx`, 조건은 글로 쓴다(예: "$g_m r_O \gg 1$일 때").
- 소신호 유도는 "등가회로 → KCL/KVL 한 줄씩 → 결과" 순서로 `ol.steps`에 쓴다. 각 단계는 토픽 회로의 ㉠㉡㉢으로 자리를 짚고 시작한다(위 "토픽 회로"). $R_{out}$은 유효한 근사 모델·근사식에서 출발하며 정확식 → 근사식 전개는 위 예외가 아니면 내부 검산에만 둔다.

## SVG 그림
- 개념 토픽마다 eli5 레이어에 그림 1개 이상(흐름도, 막대, 곡선 등). formal의 토픽 회로는 이것과 별도다.
- `<figure class="figure"><svg id="fig-<kebab>" viewBox="…" role="img" aria-label="한국어 설명">…</svg><figcaption>…</figcaption></figure>`
- 색은 클래스로만: `fig-ink`, `fig-accent`, `fig-danger`, `fig-dot`, `fig-text`, `fig-muted`, 그리고 토픽 회로의 위치 표시에만 `fig-loc`. 하드코딩 색 금지(다크모드).
- 채움과 윤곽: `fig-ink`, `fig-accent`, `fig-danger`는 선만 그린다(`fill:none`). 속이 칠해진 점·도형은 `fig-dot`(강조색 채움)뿐이다(`fig-text`, `fig-muted`는 글자용). 글·figcaption·`aria-label`에서 "색칠된", "채워진"은 `fig-dot` 도형에만 쓰고, 선만 있는 도형은 "테두리", "선"으로 부른다.
- 글자 12~14px. 생성 회로 수식은 PROFILE NOTATION-01의 native `<text class="fig-text fig-math">`와 실제 sub/super `<tspan>`으로 쓰고 Pretendard 600 정체를 적용한다(변수 포함). 실제 600 face를 로드하고 독립 SVG에도 SemiBold를 포함한다. `$...$`, 평문 vCM/gm/ro·밑줄 대체·유니코드 가짜 첨자 대신 실제 첨자를 사용한다. Ω·π와 같이 실제 Pretendard에 있는 기호를 쓴다. 병렬은 지원되는 ‖로 표현하고 본문 LaTeX \parallel은 유지한다.
- id는 페이지 전체에서 유일해야 한다(`fig-` + 토픽 고유 단어).
- 회로도: 트랜지스터·저항·전류원은 `fig-ink` 선으로, 지금 설명하는 경로(예: 출력저항을 들여다보는 노드)는 `fig-accent`로 그린다. 소자 이름·값은 `fig-text`(소자 번호·수식 아래첨자는 `<tspan baseline-shift="sub" font-size="78%">`), 노드 이름·극성은 대응 노드 점과 같은 파랑/빨강(위 노드 색 대응 규칙)을 쓴다. 접지 표기에는 기본 글자색을 쓴다.
- 교과서 그림 PNG(`교과서/마이크로전자회로/chNN/figures/`)를 붙이지 않는다. 다크모드와 MD 변환이 SVG 클래스 전제이기 때문이다.

## 본문과 페이지 요약의 계약

요약은 시험 직전 확인할 핵심만 남긴다. 기본 구성은 핵심 한 문장 → 필요한 식 1~3개 → 판단 기준 1~3개이며 권장 분량이지 할당량이나 강제 상한이 아니다. 반복 예시·유도·중복 용어 풀이·일반적인 경고는 본문에 둔다. 식의 적용 여부나 답의 부호를 바꾸는 조건은 해당 식 옆에 압축한다. 본문에 없는 사실을 추가하지 않는다. 모든 본문 주장을 요약에 복제하지 않고 핵심의 일치·오해 가능성·중복 여부를 검토하며 생략 이유는 감사 기록에 남긴다.

요약의 문장은 각각 별도 `<p>`로 작성하며 한 문장에는 하나의 판단을 담는다. 마침표로 문장을 실행 중 자동 분리하지 않는다(소수·약어·TeX 보존). 자연스러운 화면 줄바꿈은 허용한다. 의미가 나뉘면 짧은 소제목의 `summary-group`으로 묶되 단순 요약에 소제목을 늘리지 않는다. 제목 아래 12px, 그룹 사이 24px, 문장 문단 사이 8px을 공통 템플릿이 처리하며 빈 문단·연속 `<br>`로 간격을 만들지 않는다. 긴 식은 하나의 `aligned` 안에서 관계를 유지하며 나눈다. 중앙 제목·고정 패널 제목과 유일한 `.sums#sum-for`, 문제·원문 탭·앵커·저장 키를 보존한다.

공개 학습 HTML·요약·동반 MD·툴팁·접근성 문구에는 STT 줄 번호·Part·타임스탬프·시각 정보 유무를 출력하지 않는다. 근거 위치는 별도 검토 기록에만 보관한다. 해설 HTML·동반 MD의 학습량 행(핵심/추가 연습·소문항 묶음·예상 시간)은 생성하지 않고 선발 JSON에는 유지한다. PDF 규칙은 이 HTML 가독성 변경으로 바꾸지 않는다.

모든 학습 토픽에 대해 자료·토픽별 일반·강조·주의·보충의 서로 다른 핵심을 별도 행으로 감사한다. 본문 주장·대응 요약 문장·판정/생략 이유와 `pass | unresolved`를 기록하고 보완 뒤 실제 요약을 다시 읽는다. 기존 동반 MD와 재생성 원고를 동기화하되 없는 MD 형식을 만들지 않는다. 검증 JSON은 `{schema_version:1, html, html_sha256, audit_path, audit_sha256, semantic_status, browser_status, evidence, unresolved}`이며 실제 검사 뒤에만 상태를 갱신한다. 파일 해시 변경 후 기존 증거는 갱신 전까지 오래된 근거다.

## 공통 모드 이득의 본풀이

PROFILE CIRCUIT-02·GAIN-01에 따라 **성립 조건 → $2R_{SS}$ 반회로 → 출력 단락의 $G_m$ → 입력 영점에서 부하 포함 $R_{out}$ → 부호 있는 곱** 순서를 적용한다. $v_P=(2i)R_{SS}=i(2R_{SS})$로 2배를 설명하고 CM 대칭선을 가상 접지로 두지 않는다. $G_m\approx1/(2R_{SS})$와 $R_{out}\approx R_L$를 각각 구한 뒤 $A_{CM,SE}\approx-G_mR_{out}$로 연결하며, 결과식만 제시하지 않는다. 테일 저항은 필요한 유효 근사값을 먼저 쓰며 시험 회로·긴 유도는 뒤로 분리한다. $R_{out}$ 정확 전체식·긴 노드방정식은 원문 예외가 아니면 내부 검산에 둔다. 부하 불일치에서는 같은 가지 전류 조건을 확인하고 유한 $r_o$에 의한 전류 차이가 필요하면 실제 연결을 유지한다. 전류 거울·능동 부하는 연결별로 판단하며 동일한 두 반회로를 강제하지 않는다. 원문이 특정 증명·정확식·다른 방법을 요구하면 그 방법을 본풀이에 유지한다. 요약·MD·답안 PDF도 중간량의 의미·조건을 맞춘다.


**전압이득의 계산 순서:** [PROFILE GAIN-01](solution-style.md)에 따라 성립하는 단별 이득의 연쇄 곱을 우선한다. 중간 노드, 각 단의 실제 부하와 부호를 보여 준다. $G_m$·$R_{out}$ 경로를 선택하면 출력 단락, 입력 영점의 부하 포함 출력저항, 두 양의 부호 있는 곱을 각각 보인다.

실행기 역할 인계는 [runner 계약](runner-contract.md)의 receipt/고정 입력·허용 출력 계약을 따른다. 상세 내용은 파일에 보존하고 최종 반환은 task/status/receipt 절대 경로만 800자 이하로 보낸다.
