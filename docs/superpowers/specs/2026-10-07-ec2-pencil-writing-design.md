# 전자회로2 연필 필기 애니메이션 설계

상태: 2026-10-07 채팅 설계를 구현 계획용으로 동결했다. 사용자는 writing-plans를 호출했고 grill-yourself의 단일 질문 라운드에서 별도 변경값을 주지 않았다. 따라서 #1 점진 공개, #3 최대 5글자/초, #7 앞으로 연필 기본은 **confirmed by default**다. 사용자는 Native 실행과 별도 워크트리를 선택했다. 구현 및 검증 증거는 대응 review 문서에 기록한다.

## 목적과 범위

ec2-solution-video의 기존 글자 공개에 연필 PNG 한 장의 위치·각도 애니메이션을 더한다. 촉과 공개 경계를 맞춰 작성 위치를 쉽게 따라가게 한다. PDF 답안의 문장·기호·수치·순서·줄바꿈·윤곽을 보존하며 완성 화면은 원본과 같아야 한다. 기존 흐름을 확장하는 bounded 작업이다.

신규 실행은 연필 모드가 기본이고 타이핑 모드를 명시적으로 선택할 수 있다. 작성 설정이 없는 기존 실행은 기존 타이핑으로 읽는다. 기존 PDF·노트·영상·ec2-review-video는 수정하지 않는다. 기존 결과 일괄 재제작, 실제 획순 복원, 손 이미지, 입체 회전, 효과음, 단어별 음성 동기화는 제외한다.

## 화면 동작

- 원본 SVG 글자에 왼쪽→오른쪽 공개 마스크를 적용한다. 실제 한글·수식 획순을 재현한다고 설명하지 않는다.
- 공개 마스크는 원본 변환·클립·공유 defs를 보존한다. 결합 문자와 분해된 한글의 여러 svg_ids는 한 공개 단위다.
- 공개 경계가 오른쪽 끝에 닿는 프레임에도 마스크를 유지하고 전체 윤곽을 검사한다. 이후 마스크를 해제한다. 최종 원본 이미지 교체로 결함을 숨기지 않는다.
- 촉은 공개 경계의 x, 글자 bbox의 y0 + 0.8 * height 위치를 따른다. 다음 글자로 이동할 때 새 글자를 미리 공개하지 않는다.
- 연필은 촉부터 지우개 끝까지 화면상 160px이고 확대와 무관하다. PNG의 촉·지우개 끝 좌표를 직접 보정해 metadata에 기록한다. 촉을 회전 중심으로 쓰며 작은 기울기는 최대 ±2°다.
- 카메라는 글자 작성 전 이동하고 작성 중 고정한다. 기존 본문 가독성 검사와 전체 완성 화면 hold를 보존한다.
- 글자와 연필 전체가 1920×900 내용 영역에 들어가도록 카메라 여백을 확보한다. 기본 몸통 방향으로 배치가 안 되면 촉 기준 수평 반전하고, 그래도 안 되면 카메라를 재조정한다. 작성 중 viewbox는 필요한 연필 여백만큼 페이지 밖으로 확장할 수 있고 그 영역은 기존 흰 배경으로 표시한다. 최종 hold는 원래 전체 페이지다. 충족 불가능하면 실패를 보고한다. 본문 크기를 기존 기준 아래로 낮추거나 촉을 글자에서 떼어 배치하지 않는다.
- 긴 이동에서는 연필을 살짝 들어 옮기는 느낌을 주되 난수나 실제 시간에 의존하지 않는다. 단계 작성 완료, 설명 구간, 전체 완성 hold에는 연필을 숨긴다.
- 공백에는 공개나 필기 동작이 없고 이동 시간만 사용한다. 첨자는 원래 위치와 순서를 유지하고 연필 크기는 고정한다.
- 분수선·근호선·단계 배경·답 상자는 기존 shape_anchors의 연결 글자가 완료되는 순간 공개한다. 도형 자체를 연필로 그리는 기능은 이번 범위에서 제외한다.

## 타이밍

- 1920×1080 / 30fps / mono PCM 24kHz를 유지한다.
- 연필 기본 속도는 최대 5글자/초다. 30fps 정수 프레임으로 양자화하며 인접 글자는 기본 이동 1프레임 + 작성 5프레임이다.
- 줄바꿈·단계 간 이동·먼 이동은 이동 시간을 최소 8프레임으로 늘린다. 작성 프레임을 줄여 보상하지 않는다.
- 읽기 여유는 0.75초이며 ceil(0.75 * 30) = 23프레임으로 계산한다. 기존 최종 전체 화면 hold도 보존한다.
- 각 write 구간 길이는 max(실측 음성 길이, 전체 작성·이동 길이) + 읽기 여유다. 음성은 구간 시작부터 재생하고 남는 공간을 조용히 유지한다.
- events.frame은 계속 글자 또는 도형의 **완료 시점**이다. 새로운 writing_spans는 이동·작성의 [start_frame, end_frame) 구간을 기록한다.
- 상태는 오직 정수 프레임으로 계산한다. 되감기·임의 seek 결과는 순차 재생과 같아야 한다.

## 설정과 기존 실행 호환

source/writing.json을 새로 두고 음성 source/config.json과 분리한다. 신규 기본값은 mode=pencil, chars_per_second=5, pencil_length_px=160, adjacent_move_frames=1, lifted_move_frames=8, tilt_degrees=2, read_hold_seconds=0.75, asset_id=pencil-yellow-v1이다. 명시적 typing은 해당 모드의 기존 공개 방식과 원래 속도 7글자/초를 사용한다. 작성 파일이 없는 실행은 기존 config의 속도와 읽기 여유를 사용한다.

작성 속도는 0보다 크고 7 이하인 유한 수만 허용한다. 기존 legacy config 검증의 8글자/초 상한은 그대로 둔다. 길이는 양의 유한 수, 이동 프레임은 양의 정수, 기울기는 0~2°, 읽기 여유는 0 이상의 유한 수만 허용한다. 알 수 없는 모드나 asset_id는 실패한다.

prepare에 --writing-mode pencil|typing을 추가하고 각 run에 명시적 설정을 동결한다. retime --run RUN [--writing-config JSON]은 현재 내용 게이트와 WAV 샘플·형식·해시를 확인하고 저장된 음성만으로 timeline을 다시 만든다. TTS 공급자 호출과 음성 승인 변경은 하지 않는다.

## Asset과 재개

승인된 그림은 .agents/skills/ec2-solution-video/assets/pencil/pencil-yellow-v1.png이고 생성 프롬프트도 보존한다. PNG는 현재 RGBA 1254×1254, alpha extrema [0,255], SHA256 8f09ff6af2689c9cb50bab4382c4d18a46639312ea8d2edf42ad82c774d20269다. 이미지를 다시 생성하거나 덮어쓰지 않고 metadata에 촉·지우개 끝 좌표만 추가한다.

assemble은 PNG와 metadata를 composition 최상위에 복사해 실행마다 동결한다. 외부 경로나 생성 도구의 기본 저장 위치에 의존하지 않는다. 로딩 전에 PNG 실제 형식·크기·alpha·해시와 좌표를 검사한다.

작성 속도·모드·이동 시간·읽기 여유 변경은 timing부터, PNG·촉 좌표·연필 길이·기울기 변경은 composition부터 무효가 된다. 음성 설정 변경은 기존 voice부터 무효다. 파일 전체를 timing 지문에 넣어 크기 변경이 음성/타이밍까지 무효화되게 만들지 않는다. 작성 설정과 asset 해시는 stage별로 구분해서 기록한다. 성공 WAV는 보존한다.

## 검증과 실패

한글·결합 글자·첨자·분수·공백·줄바꿈을 포함한 짧은 무료 샘플부터 만들고 실제 1002 한 문항으로 가독성을 확인한다. 개발용 PCM은 실제 Aoede 청취 검증으로 승인하지 않는다. production publish와 latest를 개발 샘플에 사용하지 않는다.

필수 검사는 다음과 같다.

1. 공개 시작/중간/마스크 유지 완료/마스크 제거 완료를 검사하고 미래 글자 누출이 없어야 한다.
2. 변환·기존 clip·공유 defs·여러 svg_ids가 있는 글자와 겹치는 첨자를 검사한다.
3. 화면 네 모서리·카메라 확대·긴 2단 이동에서도 촉과 몸통이 자막 영역을 침범하지 않아야 한다.
4. 동일 프레임의 역방향·무작위 seek PNG가 같고 완성 프레임과 수정하지 않은 원본 SVG 렌더의 pixel_diff는 0이어야 한다.
5. 설정·asset 변경의 첫 무효 단계, WAV 보존, 유료 호출 0, asset 누락/변조 실패를 검사한다.
6. HyperFrames check, 실제 렌더, 하드 자막, 프레임 수·A/V 길이·전체 디코드를 검사한다. 원본 PDF native 렌더와 가독성은 직접 확인한다.

asset 누락·손상·좌표 불량·지원하지 않는 변환·불가능한 카메라 여백은 해당 문항의 실패로 보고한다. 조용히 타이핑으로 대체하지 않는다. 기존 실행의 정상 typing 호환은 명시적 정책이다.
