상태: 사용자 선택 #7·#8 확정. 이 파일은 설계이며 구현 또는 기존 자료 재생성 완료를 뜻하지 않는다.
작성일: 2026-10-21 (Asia/Seoul)

## 목적과 확정한 선택

손풀이에 나타난 단위·계산·회로 해석·식 전개·표기를 `docs/learning/solution-style.md`에 근거와 함께 명세한다. `ec2-review-pack`과 `ec2-problem-explain`의 작성자와 내용 리뷰어가 같은 문서를 읽고, 결과에 실제로 반영했는지 검토한다.

- HTML: 내 사고 순서의 핵심 풀이를 먼저 보여주고, 필요한 개념·유도를 이어서 자세히 설명.
- 답안 PDF: 핵심 회로·판단·계산·최종 답을 담고, 상세 설명은 HTML에서 제공.
- 공통 명세와 검토된 핵심 풀이를 공유한다. 기존 문제 MD의 `## 풀이`는 개인화 목적으로 수정하지 않는다.
- 기존 문제설명 일곱 구역은 유지한다. 그 앞에 핵심 풀이를 추가하고, 그 핵심 부분을 PDF로 추출한다.
- 단독 `ec2-problem-explain`은 HTML·MD와 내부 답안 데이터를 발행한다. PDF를 교체하는 주체는 부모 `ec2-review-pack`이다.

## 개인 명세에 반드시 보존할 분석

명세는 각 규칙에 `관찰 / 근거 / 확신도 / 생성 규칙 / 예외 / 검토 기준`을 구분한다. 규칙 ID는 `### UNIT-01`처럼 제목에서 추출 가능하게 작성한다. 아래 12개 ID를 초기 집합으로 사용한다.

### UNIT-01: 공학 단위와 환산

- 관찰: MOS 계산은 V·mA·kΩ·mS 조합을 반복한다. 100 μA/V²를 0.1 mA/V²로, 500 Ω를 0.5 kΩ로 바꾼다. 인자 아래에도 단위를 적는다.
- 근거: H0909 p1·2·3·6·8. 확신도 높음.
- 예외: BJT gm은 1/26 S 형태도 사용한다(H0911 p6, H0916 p6). 따라서 항상 mS를 쓴다고 기록하지 않는다.
- 생성: 첫 사용에서 환산을 보여주며 mA×kΩ=V, mS×kΩ=1, mS×kΩ²=kΩ를 일관되게 유지한다. 다른 규모에서는 적합한 단위를 선택한다.

### CALC-01: 중간값과 역산

- 관찰: 소자별 ro·gm·rπ를 구해 조립한다. 목표 Rout에서 gm, 이어 W/L을 역산한다. 같은 소자는 등식으로 묶는다.

- 생성: 목표 식 → 필요한 중간값 → 대입 → 최종 답. 한 식에 모든 소자식을 무리하게 대입하지 않는다.

## 현재 코드가 정하는 연결 지점

- `.agents/skills/ec2-review-pack` 및 `ec2-problem-explain`은 `.claude/skills/`를 가리키는 링크다. 실제 파일 한 곳만 수정한다.
- `workbook/problem.py:215`는 MD 풀이를 읽고 `workbook/assemble.py:116`가 답안에 넣는다. `build_workbook.py:56`는 현재 문제·답안을 함께 생성한다.
- `epe_contract.py`는 일곱 설명 구역과 solve/verify의 소문항을 검사한다. 그 계약을 제거하지 않는다.
- `epe_publish.py`는 참조·산출 해시와 네 검토를 확인한다. 개인 명세와 답안 데이터도 이 경계에 포함한다.
- `epe_rerender.py`의 일반 HTML/CSS 동등성 판단으로 개인 명세 변경을 통과시키지 않는다. 개인 명세는 바이트 해시가 같아야 한다.
- 복습팩 조립은 `problems.txt`와 최종 정리노트 이름을 만들며, 문제설명은 이를 입력으로 사용한다. PDF를 늦게 만들어도 정리노트의 바이트를 자식 검토 뒤 바꾸지 않도록 한다.

## 완료 기준과 실패 동작

1. 공통 명세에 위 관찰·근거·예외가 빠짐없이 들어 있다. 원본 Downloads PDF를 반복 생성의 필수 의존성으로 삼지 않는다.
2. 두 스킬의 실제 작성자와 내용 리뷰어 브리프가 명세 읽기를 요구한다. 규칙별 적용/비적용 사유를 기록한다. 해시만으로 읽기·의미 반영을 입증했다고 쓰지 않는다.
3. 문제설명은 핵심 풀이를 먼저 제시하고 상세 설명·요약·MD와 단위·조건·답이 일치한다.
4. PDF의 핵심 풀이를 별도 AI가 다시 요약하지 않는다. 같은 검토된 HTML의 명시 영역에서 추출한다.
5. 누락·중복·재정렬된 문항/소문항, 변경된 명세/원문/그림/해설/검토 기록은 개인화 PDF 생성을 실패시킨다.
6. 답안 PDF는 임시 RUN에서 렌더·실제 화면 검토 후 교체한다. 실패 시 기존 PDF를 유지하고 보류로 보고한다. 새로운 문제 목록과 맞지 않는 기존 PDF는 현재 팩의 성공 산출물로 링크하거나 보고하지 않는다.
7. 답안 PDF 생성 전에는 그 파일 하나의 존재 검사만 예비 단계로 유예할 수 있다. 최종 검사에는 유예가 없으며 정리노트 링크까지 실제로 존재해야 한다.
8. 문제 없는 팩은 개념 개인화만 수행하고 PDF/문제설명 단계를 건너뛴다.
9. lite도 개인 명세 적용과 부모의 실제 적용 감사는 생략하지 않는다. 자식의 독립 검산·네 검토는 기존처럼 유지한다.

## 제외 범위

필기체 렌더링, 자동 학생 능력 평가, 원문/원본 풀이 수정, 새 문제 선별 정책, 타 과목 일반화, 기존 팩 전체 재생성, 별도의 상세 해설 PDF, 새 UI 테마, 전역 Codex 메모리 수정은 포함하지 않는다.
