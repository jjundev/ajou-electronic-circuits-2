# 복습문제 PDF 16:9 전환 검증

기본 복습문제 문제지·답안지 14개(0909, 0911, 0916, 0918, 0923, 0930, 1002), 총 142쪽을 기존 파일명으로 교체했다. 이후 복습팩도 같은 규격을 사용한다. workbook 장별 PDF의 기본 A4 규격은 유지한다.

## 최종 글꼴 기준

사용자의 마지막 요청은 pt 값 자체보다 이전 영상 전체 화면에서 보이던 텍스트 크기를 유지하는 것이다. 이전 A4 페이지는 높이 900px에 맞췄고, 새 16:9 페이지는 전체 1920×1080에 맞춘다. 두 표시 배율의 차이를 보정한 약 1.134배를 본문·제목·힌트·수식의 pt 값에 적용했다. 본문 기본값은 약 11.34pt다. A4 맞춤 과정에서 긴 문항에 적용했던 본문·수식 축소 배율도 보존한다.

## 실제 산출물 검증

- 14개 PDF, 142쪽 모두 16:9이며 하단 y=900–1080의 렌더 픽셀은 전부 흰색이다.
- 페이지 수와 문항 순서, 문제·풀이 텍스트, 디코딩한 회로 이미지가 보존됐다. 텍스트 비교에서 줄바꿈에 따른 U+2010 자동 하이픈과 공백만 제외했다.
- PDF 본문의 글자별 글꼴·크기를 이전 A4 화면 배율과 새 화면 배율로 비교했다. 표시 크기 차이는 최대 약 0.0176px다.
- 게시된 모든 PDF의 SHA256이 검증한 생성본과 일치한다.
- 세 대표 문항 E10.11, E10.13, 2021-1_중간-Q3의 빈/부분/완성 SVG 게이트에서 pixel_diff, non_target_diff, hidden_leaks가 모두 0이다. 역방향 탐색 상태 일치와 마지막 커서 제거를 확인했다.
- 전체 PDF를 1920×1080으로 배치하고 예약된 하단만 잘라 자막 영역으로 사용한다. 타이핑 커서와 카메라 검증은 같은 SVG 배율·여백 좌표를 사용한다.
- 새 글꼴로 기출 번호와 제목이 같은 PDF 텍스트 줄로 묶이는 경우를 재현하고, 문항 번호 접두사를 숫자로 읽도록 수정했다. 현재 7개 날짜의 모든 69개 문항 대응이 정상이다.
- 후속 수식 점검에서 최종 PDF 14개의 검증 SHA256과 142쪽의 대체 문자 부재를 다시 확인했다. Chrome에서 수식 2,822개를 검사했고 KaTeX 렌더 오류와 가로·세로 잘림은 모두 0건이었다. 근거는 같은 실행 폴더의 `math-check.json`이다.

근거 파일은 `.superpowers/sdd/2026-10-07-wide-pdf/`의 `validation.json`, `preview-validation.json`, `source-validation.json`, 테스트 로그와 프레임이다. 교체 전 PDF는 같은 폴더의 `backup/`에 보존했다.

## 테스트와 기존 상태

- workbook: 102개 통과.
- ec2-solution-video: 40개 통과, 실제 유료 음성·MP4 수용 테스트 1개는 명시적 개발 batch가 없어 생략.
- 기존 ec2-review-video: libass 포함 로컬 FFmpeg로 81개 통과.
- ec2-review-pack: 102개 통과, `test_template_is_identical_to_ml` 1개 실패. 변경하지 않은 이 프로젝트 노트 템플릿과 외부 머신러닝 스킬 템플릿의 불일치다. 이 프로젝트 파일은 HEAD와 동일하고, HEAD에서도 외부 파일과 달랐음을 확인했다.
- 두 관련 스킬의 구조 검사, Python 컴파일, 공백 검사를 통과했다.

0909–1002를 한꺼번에 영상 입력으로 선택하면 E9.06의 날짜 간 본문 화면 차이로 중복 충돌이 검출된다. 교체 전후 동일한 기존 상태이며 각 날짜 단독 입력은 정상이다. 이번 작업에서 서로 다른 입력을 임의로 합치지 않았다.

유료 음성 생성, 영상 재출시, 푸시는 실행하지 않았다. 실제 PDF와 세 대표 문항의 브라우저 프레임을 검증한 범위다.

## 독립 리뷰 범위와 판단

읽기 전용 리뷰어는 직접 읽은 초기 배치 변경에서 Critical/Important/Minor 결함을 발견하지 않았다. 전체 SVG 높이와 자막 viewport 분리, 커서 좌표, 조건 패널 비교, 종료 전체 화면을 확인했다. 다만 다음 항목은 최종 코드를 직접 다시 검토하지 못했다고 명시했다.

- 이후 추가된 글꼴 배율 측정·수식 transform 보존·letterbox 카메라 검사·기출 번호 정규식: 구현자가 실패 재현 후 통과하는 테스트와 최종 suite로 검증했다. 독립적인 최종 코드 확인으로 표현하지 않는다.
- 최종 14개 PDF의 내용·이미지·표시 글꼴 크기·자막 여백: 구현자가 위 142쪽 검사와 실제 프레임 대조로 검증했다. 독립적인 산출물 재검증으로 표현하지 않는다.
- 실제 MP4·음성: 이번 PDF 업데이트 범위에서 새로 제작하지 않았으며 미검증으로 남긴다. 브라우저 프레임 검사와 실제 영상 청취·재생 검사를 혼동하지 않는다.
- 외부 ML 템플릿 불일치: HEAD의 동일한 실패를 확인했으므로 이번 변경과 분리하여 기록한다.
