# 문제설명 통합 계약

## 부모 복습팩에서 호출

1. 부모의 기계·내용·브라우저 검토(lite의 부모 내용 리뷰 생략 규칙 포함)와 MD 변환을 끝낸다. 확정된 `range`, `slug`, manifest `problems`, 절대 경로 `RUN`을 입력으로 삼는다.
2. 문제가 0개이면 `skipped-no-problems`로 기록하고 자식을 실행하지 않는다.
3. manifest 문제 id 순서와 `.assets/problems.txt`의 id 순서가 같은지 확인한다. 다르면 부모 조립을 고친다.
   새 JSON 선별 흐름에서는 `RUN/selection.json`의 ID·순서도 같아야 한다. 기출은 문항 전체를 전달한다. 선택용 JSON을 자식의 `source.json`이나 독립 검산 근거로 대체하지 않는다.
4. **필수 하위 스킬: ec2-problem-explain.** 형제 `../ec2-problem-explain/SKILL.md`를 읽고 전체 절차를 수행한다. 부모 `range`를 명시하며 최신 팩 자동 선택을 사용하지 않는다. 통합/개별 팩 후보가 모호하면 오류와 후보 경로를 보고하고 임의 선택하지 않는다.
5. `EXPLAIN_RUN = RUN/problem-explain/<새 실행ID>/`를 없거나 빈 폴더로 정한다. `python3 <자식 SKILL>/scripts/epe_cli.py extract --repo <REPO> --target <range> --run <EXPLAIN_RUN>`을 실행한다. 상태 이름은 보고용이며 CLI 인자가 아니다.
6. extract → 자료 읽기 → 문항별 저작 → 별도 독립 검산 → build/check → 네 검토 → publish를 끝까지 수행한다. CLI만으로 저작은 되지 않는다.
7. lite는 부모에만 적용한다. 자식 작성자 모델과 네 검토를 낮추거나 생략하지 않는다. 지정 모델을 사용할 수 없으면 보고하고 검토를 생략해 완료 처리하지 않는다.
8. 부모 호출에서는 중간 진행만 표시하고 최종 결과를 부모 보고에 합친다. 단독 호출은 자식 보고 형식을 유지한다.
9. `source_visual/content/independent/browser` 중 하나라도 통과하지 못하면 `withheld`다. `disputed`는 보류 이유로 함께 적고 원본 풀이를 고치지 않는다.
10. 성공은 `published`, 검증된 기존 발행 재사용은 `reused-verified`다. 기본 팩 상태와 설명 상태를 따로 보고하며 설명이 withheld이면 전체 완료라고 쓰지 않는다. 한 팩 실패 후 다른 팩은 계속한다.
11. extract 이후 정리노트·문제 목록·참고 자료가 바뀌면 새 EXPLAIN_RUN에서 재시작한다.
12. 정리노트 링크 자동 삽입, 원본 수정, PDF 재빌드는 하지 않는다.

## 재생성 전에 기존 설명 다루기

이 절차는 수동 파일 작업 계약이다. 부모가 입력을 처음 변경하기 전(PDF 선행 빌드 포함)에 한 번 수행하며 재조립마다 반복하지 않는다.

1. 팩의 최상위 `문제설명_<range>_*.html`, `.assets/문제설명_<range>_*.md`, `.assets/figures_문제설명_<range>_*`, `.assets/자료_문제설명_<range>_*`만 목록화한다. 정확한 range 접두사와 NFC 이름으로 비교한다. 다른 날짜·인터랙티브·정리노트·PDF·원본 문제는 포함하지 않는다.
2. 모든 대상과 백업의 절대 경로를 resolve해 의도한 팩과 전용 `RUN/previous-explanations-<고유ID>/` 안에 있는지 확인한다. 심볼릭 링크 등 팩 밖으로 나가는 대상은 중단한다.
3. 상대 경로대로 복사하고 원본·백업의 전체 파일 상대 경로 집합과 각 SHA-256이 같은지 확인한다. 빈 폴더도 보존한다. 목록·해시·백업 경로를 RUN에 기록한다.
4. 검증 후에만 목록화한 설명 소유 파일·폴더를 팩에서 제거한다. 복사·검증 실패면 원본을 유지하고 부모 첫 조립을 중단한다. 제거 도중 실패하면 검증된 백업으로 설명을 복원하고 부모 조립을 중단한다.
5. 이 선제 정리 덕분에 문제 0개 전환·slug 변경·새 설명 보류 시에도 이전 설명이 최신 파일처럼 남지 않는다.
6. 기본 팩 재생성이 실패하면 기본 팩 백업을 먼저 복원한 뒤 그 입력과 대응되는 설명 백업을 복원한다. 입력 대응을 확인하지 못하면 설명은 백업에 유지하고 보고한다.

## 기존 팩 보충

- 실제 날짜 폴더별 `problems.txt`를 조사한다. 없거나 문항이 0개인 팩은 `skipped-no-problems`다.
- 부모 전체를 재생성하지 않고 설명 스킬만 실행한다. 정리노트 HTML·MD, 문제/답안 PDF, 목록, 원본 문제 md·그림을 그대로 보존한다.
- 입력을 바꾸지 않으므로 기존 설명을 선제 제거하지 않는다. 정상 교체는 publish의 백업·복구를 사용한다.
- 기존 설명은 검토 기록·현재 입력·참조·산출 해시·원래 저작 조각·문항/소문항 대응이 모두 입증되는 경우에만 `reused-verified`다. 원래 RUN이나 조각이 없어 input_hash를 재현하지 못하면 추측하지 말고 재생성한다.
- 재사용 검증 실패 시 기존 설명을 위 절차대로 백업·검증해 발행 경로에서 치운 뒤 재생성한다. 한 팩 실패는 그 팩만 보류하고 나머지 팩과 원본은 유지한다.
