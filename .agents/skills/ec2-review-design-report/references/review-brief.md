# 독립 검토자 지시문

지정한 전자회로2 설계과제 제출 PDF를 읽기 전용으로 검토한다. 먼저 PDF의 SHA-256을 직접 계산해 전달받은 값과 대조한다. 다르면 판본 불일치를 보고한다. 전달 목록에 있는 공식 자료, 현재 보고서와 그림, 실제 시뮬레이션 입력·출력만 사용한다. 작성·수정 대화, 작성자 메모, 초안, 이력, 이전 판정은 조회하지 않는다. 검산용 파일이 필요하면 임시 복사본에서 작업한다.

## 검사 기준

1. **문항과 증거.** 이번 공식 문제를 요구사항 단위로 나누고 각각의 답·유도·표·그림 위치를 적는다. 후속 과제에도 적용한다고 명시한 조교 지침을 함께 적용한다. 선배 감점표와 과제별 기준은 해당 과제에 맞는지 확인한다. 이전 과제의 오차 기준이나 transient 요구를 자동으로 가져오지 않는다.
2. **시뮬레이션 증거.** 제출 PDF에 실제 실행 화면과 측정 근거가 있는지 본다. 적용되는 조교 지침이 LTspice/PSpice 원본 화면, 커서, `.meas` 결과를 요구하면 해당 증거를 확인한다. 회로도와 `.op`의 소자·노드 라벨, 주파수 응답의 크기·위상, 극점 계산에 사용한 원본 측정값과 계산 경로를 문항에 맞춰 찾는다. 추가로 인용한 시뮬레이션 결과도 같은 증거 기준을 적용한다. 별도 그래프와 로컬 로그는 검산에 활용한다.
3. **독립 검산.** 결론의 강한 주장부터 확인한다. 전원 전류로 계산한 전력, 포화 여유가 가장 작은 소자, 이득, 최저 극점과 나머지 극점의 비교를 과제에 맞춰 원본에서 다시 계산한다. 한계 판정에 반올림 전 값을 쓴다. 보고서·회로도·실행 netlist의 결선, 소자값, 바이어스, 입출력 정의와 실제 사용 모델을 비교한다. 공식 모델을 그대로 쓰라는 조건은 실제 로드한 파일과 대조한다.
4. **모순과 설명.** 본문·표·그림·결론의 주장을 서로 대조한다. 조건, 모델, 입출력 정의, 단위, 반올림을 비교해 같은 조건에서 양쪽이 동시에 참인지 판정한다. 손계산의 목표, 근사, SPICE 측정값이 다르면 차이 자체와 보고서의 사양 판정을 따로 확인한다. 별도 허용 오차가 없으면 임의로 정하지 않는다. 오차 원인과 근사의 유효 범위에 근거가 있는지 보고, 극점과 노드의 대응이 모호하면 배정 기준·대안·등가값의 의미가 설명됐는지 확인한다.
5. **PDF 화면.** 전 페이지를 렌더링해 그림·표·수식·로그·축·범례·단위·표지 날짜를 본다. 곡선이나 그림이 빠졌다고 판정하기 전에 관련 영역을 확대해 재확인한다. 목차에 링크가 있으면 실제 문항 제목으로 연결되는지 확인한다. 표지 날짜의 사실 여부를 판단할 근거가 없으면 확인 사항으로 남긴다.

## 결과 형식

- 검토한 PDF 절대 경로·SHA-256·쪽수와 종합 판정(통과/보류)을 적는다. 쪽수는 표지를 포함해 1부터 센다.
- 문항별로 `요구사항(필수/추가) | 통과/실패/검증 불가 | PDF 쪽·근거 | 검산값 또는 최소 수정`을 남긴다. 제출물에 필수 증거가 없으면 해당 증거 요건을 실패로 기록한다. 원본 접근이나 확인 수단이 없어 독립 검증이 안 되는 항목은 검증 불가로 기록한다.
- **모순은 두 쪽을 모두 제시한다.** `주장 A — PDF p.__ + 문장·수치 | 주장 B — PDF p.__ + 문장·수치 | 비교 조건과 충돌 근거(식·로그·행 등) | 최소 수정`. 같은 쪽이면 반복해서 쓰고, 반대 증거가 PDF 밖에만 있으면 그 파일과 행 또는 측정 항목으로 대신한다. 실측 잔차, 증거 누락, 선택 항목의 감점 위험, 서식 권고를 각 근거에 맞춰 표현한다.
