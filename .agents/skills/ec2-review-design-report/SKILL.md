# 전자회로2 설계과제 보고서 최종 검토

최종 제출용 PDF를 문항별로 독립 검토한다. 병합 뒤, Notion에서 새로 내보낸 PDF를 제출본으로 만든 뒤, 또는 기존 제출본을 보완한 뒤에 적용한다. 단독 실행은 `/ec2-review-design-report <과제 번호 또는 PDF 경로>`를 사용한다.

1. **판본을 확정한다.** 사용자 지정 PDF 또는 이번 작업에서 생성·수정한 PDF를 우선한다. 과제 번호만 있고 제출본과 보완본이 함께 있으면 현재 제출 후보를 확인한다. 구분할 근거가 없으면 경로를 확인한다. 과제 원문 PDF를 잘못 고르지 않는다. 대상 절대 경로와 SHA-256을 기록한다.
2. **검토 자료를 고른다.** 해당 과제의 공식 문제지와 적용되는 공지·조교 지침, 대상 PDF, 현재 보고서 MD, 사용된 그림, 실제 실행에 쓴 netlist·모델·측정 로그·원본 데이터를 고른다. 제출본에 실린 결과와 대응하는 실행 자료를 고르고, 확인할 수 없는 자료는 누락으로 표시한다. 수정 중인 MD나 다시 생성될 로그는 검토에 쓸 판본을 임시 사본으로 고정한다. 과거 감점 체크리스트는 참고로만 전달한다.
3. **새 검토자에게 위임한다.** Codex에서는 새 서브에이전트를 `fork_turns: "none"`으로 시작한다. 다른 환경에서는 대화를 상속하지 않는 독립 에이전트를 사용한다. [검토자 지시문](references/review-brief.md)의 절대 경로, 과제 번호, PDF 해시, 선택한 자료의 경로와 자료별 역할만 전달한다. 작성·수정 대화, 작성자 메모, 초안, 변경 내역, 이전 리뷰, 발견한 문제나 기대 판정은 전달하지 않는다. 검토자는 명시된 자료만 읽고 보고서를 수정하지 않는다.
4. **판정을 확인한다.** 검토자가 문항별 답과 증거를 판정했고 PDF를 렌더링했는지, 핵심 수치에 원본 근거 또는 확인 한계가 있는지 확인한다. 모순이 있으면 **주장 A의 PDF 쪽과 문장·수치, 주장 B의 PDF 쪽과 문장·수치, 당시 조건과 충돌 근거**를 모두 적는다. 같은 쪽에 있으면 양쪽에 같은 쪽수를 쓴다. 반대 근거가 PDF 밖에만 있으면 실제 파일·행·측정 항목을 쓴다. 쪽수는 표지를 포함한 물리 쪽수다.
5. **검토한 판본의 상태를 보고한다.** 현재 PDF 해시가 검토 대상과 일치하고 필수 항목이 확인됐으며 미해결 계산 오류나 모순이 없을 때 최종 검토 통과로 보고한다. 필수 항목의 실패 또는 검증 불가, 미해결 모순, 독립 검토를 실행할 수 없는 상황은 그 이유와 함께 보류로 기록한다. 권고와 제출일처럼 확인이 남은 항목은 근거를 덧붙인다. PDF나 판정에 사용한 근거가 바뀌면 현재 판본과 근거를 작성·수정 대화를 모르는 새 검토자에게 다시 맡긴다.

검토 결과는 사용자에게 보고한다. 수정·업로드·제출은 해당 작업이 요청됐을 때 진행한다. Notion 게시본은 본문 되읽기와 그림 삽입 상태를 별도로 확인하며, 그 결과를 PDF 검토 판정에 대신 쓰지 않는다.
