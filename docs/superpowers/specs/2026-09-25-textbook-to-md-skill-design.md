# 교과서 문제 → MD 변환 스킬 (`textbook-to-md`) — 설계

## Intent
Razavi 마이크로전자회로의 새 장 PDF(12장, 13장 …)를 받으면, 9–11장에서 검증된 절차를 한 번의 호출로 재현하는 프로젝트 스킬을 만든다. 재현할 절차는 다음과 같다.
- 쪽 조사
- 묶음 계획
- opus 작성·리뷰 파이프라인
- 리뷰 반영
- 인덱스 생성
- 장 단위 최종 검증

완료 기준은 세 가지다.
- "12장 변환해줘" 한 번으로 `ch12/`가 9–11장과 같은 품질로 채워진다. 형식 검사는 오류 0·WARN 0이고, 모든 묶음이 리뷰 보고서를 남긴다.
- 관례는 FORMAT.md에만 있다. 스킬과 템플릿은 형식을 다시 적지 않는다.
- 장 단위 검증이 도구 하나로 끝난다.

분류: architectural. 스킬, 프롬프트 템플릿, 장 단위 검증 도구가 새로 생긴다.

## 완료 후 동작
- **호출:** "12장 문제 md로 변환해줘" 또는 `/textbook-to-md 12`로 스킬이 켜진다.
- **전제 확인:** PDF가 있는지 확인한다. `ch12`가 이미 있으면 진행 상황을 파악해 이어서 한다. 작업 트리가 깨끗한지 확인하고, 장 전용 worktree를 만든다.
- **0단계 조사:** 쪽 대응표, 예제·장말문제 분포, 묶음 계획을 보여 준다. 멈춰서 묻는 것은 FORMAT이 다루지 않는 새 그림 유형이 있을 때뿐이다.
- **진행 보고:** 묶음마다 한 줄씩 보고한다. 작성 완료, 리뷰 결과, 반영 커밋이다.
- **마무리:** 결과를 요약하고, main 병합과 push 여부를 묻기만 한다.
- **실패 처리:**
  - PDF가 없으면 즉시 중단한다.
  - 검증 도구가 오류를 내면 완료를 선언하지 않고 오류 목록을 보여 준다.
  - 서브에이전트가 끊기면 커밋 기록을 보고 다음 묶음부터 이어 간다.

## 이번 범위에서 뺀 것
- **Workflow 스크립트 자동화:** 매번 ultracode 동의가 필요하고 비용이 크다. 지금의 Agent 파이프라인으로 검증됐다.
- **다른 교재로 일반화:** 12–13장은 같은 교재라서 교재 루트를 고정한다.
- **9–11장 재검토:** FORMAT에 옮기는 관례는 이미 그 파일들에 적용돼 있다.
- **스킬 안에서 push·병합:** 외부로 나가는 동작이라 항상 사용자 확인 사항이다.

## 접근
저장소 안의 `.claude/skills/textbook-to-md/`에 두고, 형식과 도구는 기존 FORMAT.md와 `_tools/`를 참조한다. 규칙과 도구가 모두 이 저장소에 있으므로 스킬도 같은 곳에 두어야 함께 바뀐다.

기각한 안은 두 가지다.
- **전역 `~/.claude/skills`:** 도구와 FORMAT이 저장소와 둘로 갈라진다.
- **저장된 Workflow 스크립트:** 동의 조건이 까다롭고, 판독 중에 필요한 판단을 넣기 어렵다.

## 구성
1. **FORMAT.md 보강:** 10·11장 관례는 이미 FORMAT.md의 각 절에 들어가 있다(커밋 `10b7995`). 이 구조를 따르고, 새 절은 만들지 않는다. 더하는 것은 세 가지뿐이다.
   - 새 도구 `verify_chapter.py` 등록 (폴더 절, 검사 절)
   - 변압기 결합을 K 문 대신 주석으로 적는 규칙 (넷리스트 절, E10.01·E10.02에서 사용)
   - 연습문제가 없는 예제는 X 파일을 만들지 않는다는 규칙 (폴더 절, E11.29)
2. **`_tools/verify_chapter.py`:** 장 단위 정합성 검사 도구다.
   - 번호가 빠짐없이 이어지는지
   - 연습문제에 짝 예제가 있는지
   - 그림 id 세 집합(figures.yaml, PNG, md 참조)이 일치하는지
   - 이미지 링크
   - 절 순서
   - README가 최신인지
   - `--recrop`을 주면 다시 크롭해서 픽셀을 비교한다
3. **`.claude/skills/textbook-to-md/SKILL.md`와 `references/`:** 절차와 프롬프트 템플릿이다.
   - `survey.md`: 0단계 조사
   - `common.md`: 공통 지침
   - `writer.md`: 작성 에이전트
   - `reviewer.md`: 리뷰 에이전트
4. **리뷰 보고서 보존:** 보고서를 `docs/superpowers/reports/ch<N>/review-<묶음>.md`로 커밋한다. 남아 있는 9장 A–G와 11장 H 보고서도 옮긴다.
