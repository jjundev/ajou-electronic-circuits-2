# 역할·파일 인계 계약

목표는 메인의 원문·풀이·화면 독해를 담당자에게 옮기는 것이다. 품질 기준·실제 검토·발행 게이트는 그대로 유지한다. 메인은 진입점과 이 계약을 읽고, [runner 계약](runner-contract.md)의 현재 명령 절만 연다. 상세 절차는 현재 단계만 연다.

## 실행과 컨텍스트

- Codex는 `spawn_agent`에 `fork_turns: "none"`을 써서 새 컨텍스트로 시작한다. 다른 환경도 대화 전체를 복사하지 않는 서브에이전트를 쓴다. 필요한 정보는 아래 브리프 파일에 명시한다.
- **모델 선택.** 메인은 날짜별 STT 텍스트 요약자와 정리노트 섹션 작성자를 호출할 때, 현재 환경에서 서브에이전트에 지정할 수 있는 모델을 환경이 제공하는 등급순으로 본다. 요약자와 작성자에게 **가장 높은 등급의 모델**을 지정한다. 기존 팩의 왜 페이지를 작성할 때도 이 기준을 적용한다. 선택 가능한 모델이 하나면 그 모델을 사용한다. 환경이 제공하는 등급 순서를 확인할 수 없으면 환경의 기본 모델을 사용하고 이유를 최종 보고에 적는다. 문제설명과 확인문제 작업자는 각 하위 스킬의 모델 선택 규칙을 따른다.
- 독립 작업은 **현재 가용 슬롯만큼 배치**한다. 4슬롯이면 메인+직접 작업자 최대 3명, 자식 조정자 실행 중에는 메인+조정자+작업자 최대 2명이다. 남은 작업은 대기열에 두며 순서 의존 단계는 병렬화하지 않는다.
- 병렬 RUN에서 작성·독립 풀이 슬롯을 먼저 확보하고 두 결과를 받은 조정자에게 검토를 맡긴다. 예상 종료 시각으로 슬롯을 재배정하지 않는다. 인계 묶음의 거부·차단 ID와 관련 근거만 메인에서 열어 본다. 레거시 RUN은 이전 단계 작업을 끝내고 자식 조정자를 실행한다. 조정자는 또 다른 조정자를 만들지 않는다. 중첩 spawn이 불가능하면 조정자가 작업 브리프를 파일로 남기고 반환하고, 메인이 해당 leaf들을 실행한 뒤 같은 조정자를 재개한다. 독립 검산자/내용 리뷰어를 작성자로 대체하지 않는다.
- 수정은 기존 담당자를 재개한다(Codex `followup_task`). 담당자를 재개할 수 없을 때만 같은 브리프와 수정 요청 경로로 새 작업자를 띄운다.
- 메인이 STT·교과서·전체 후보 JSON·HTML/SVG·모든 스크린샷·자식 검토 전문을 재독하는 것을 기본 경로로 삼지 않는다. 결함 위치·해시·승인 상태가 불명확하면 필요한 범위의 근거를 직접 확인한다.
- 서브에이전트가 없거나 실제 검사 도구에 접근할 수 없으면 조용히 검토를 생략하지 않는다. 메인 실행이 필요한 작업을 표시하고 실제 수행하거나 미실시/보류로 보고한다.

## 브리프는 경로로 전달

실행기는 `RUN/work/<역할ID>/brief.json`에 고정 역할 브리프를 만들고, scope-final은 섹션 교육 브리프 `RUN/briefs/<sid>.json`을 만든다. 호출 메시지는 `역할`, `브리프 절대 경로`, `반환 형식`이면 충분하다. 수업 원문·PROFILE 전문·다른 역할의 전체 브리프를 메시지에 복제하지 않는다.

| 항목 | 브리프에 담을 값 |
|---|---|
| 실행 | 역할 ID, range, REPO/RUN/SKILL/PROFILE 절대 경로, snapshot 파일 경로 |
| 계약 | 읽을 참조 문서와 제목 범위, manifest/scope/source-map 등 입력 파일 경로 |
| 담당 범위 | 날짜 또는 섹션/토픽/문항 ID, 필요한 STT·요약·교과서 PDF와 쪽 |
| 출력 | 허용 산출물 절대 경로, `RUN/work/<역할ID>/`, 완료/실패 인계 경로 |
| 섹션 전용 | 금지어·예고 토픽·해당 links·widget 배치·why의 뒤 토픽 목록·문제 수 |
| 선행조건 | 앞 단계 산출/검사, snapshot, 고정 입력의 해시, 수정 요청 파일(있을 때) |

snapshot **파일 경로**로 전체 객체를 전달한다. 담당자는 이를 읽고 실제 PROFILE 해시와 대조하며 manifest/source에 객체 전체를 넣는다. 경로만 받았다는 이유로 규칙·원문·참조 자료를 읽지 않아도 되는 것은 아니다.

작성·내용/개인화 감사 브리프에는 execution-guide의 `기본 근사와 회로 표기`, `전압이득의 계산 순서`, `확정한 문제 해설 형식`, `본문과 페이지 요약의 계약`, `수치 표시`, `HTML 가독성 생성·검사`도 읽을 범위로 포함한다. 이 공통 계약은 단계 밖에 있다는 이유로 누락하지 않는다. PROFILE 전체와 원문 조건을 유지한다.

## 역할과 산출

| 역할 | 직접 읽는 상세/참조 | RUN 안 산출과 인계 |
|---|---|---|
| 자료 준비자 | execution-guide `1`의 1, STT·PDF | `source-map.json`, `slides.txt`; 날짜별 PDF/미게시/추출 실패 |
| 날짜별 요약자 | stt-summary-prompt, 해당 STT 전체·자료 | `summaries/stt-<날짜>.md`; 기존 총평 3줄 |
| 범위 설계자 | manifest-guide, 모든 요약·필요한 근거 | `scope.json`, manifest 초안→선발 후 확정본, `briefs/<sid>.json`, 브리프 `report` |
| 문제 선발자 | problem-selection 전체, scope·후보·이력·원문/그림 | candidates/catalog, manifest의 problems/links, selection-review/selection, 표시 제목 후보, `work/selection/report.md` |
| 섹션 작성자 | content-rules, PROFILE, execution-guide `3`, 해당 근거; widget-rules는 담당자만 | `sections/<sid>.html`, 브리프 `report` |
| 개인화 감사자 | review-prompt의 감사 계약, PROFILE, manifest·전체 토픽 | 브리프 `audit_output`과 `report` |
| 내용 리뷰어 | review-prompt 전체·원문 근거·선발 기록 | 전체 감사 재검토, 브리프 `report` |
| 브라우저 QA | browser-check 전체·PROFILE의 화면 기준 | `work/browser/` 증거·실제 이미지·브리프 `report` |
| 독립 SVG QA (`standalone-svg-qa`) | PROFILE 전체·NOTATION-01/CIRCUIT-02·execution-guide `8`, 변환된 MD/SVG | `work/standalone-svg-qa/report.json`, `report.md`, 대상별 지정 PNG·receipt; MD/SVG 읽기 전용 |
| 문제설명 조정자 | problem-explain-integration 부모 호출·형제 스킬/참조 | EXPLAIN_RUN 전체 stage/검산/검토, `child-receipt.json`; 발행 직전 반환 |
| PDF QA | 통합 계약 `답안 PDF 렌더 검토 기록`·승인 HTML/overlay | `answer-pages/`, 브리프 `report`, `answer-review.json` |

`scope.json`은 날짜별 배운 절/슬라이드·예고/금지어 근거·필요 PDF/쪽·미루거나 제외한 내용·관련 요약 경로를 보관하는 작업 인계물이다. 새 검증기 입력으로 가정하지 않는다. 기존 manifest/selection/audit/review JSON 스키마는 바꾸지 않는다.

manifest 소유권은 **설계자 초안 → 선발자 → 설계자 확정** 순서다. 동시 편집하지 않는다. 위젯은 설계자가 미리 0~2개만 지정하고 이유를 기록한다. 최종 섹션 브리프의 링크·문제 수는 선발 완료본을 따른다. 문제 수/순서가 바뀌면 선발 기록과 영향받은 브리프도 갱신한다.

## 인계 전 묶음 점검

새 승인 스키마나 추가 파일을 만들지 않는다. 각 담당자는 현재 브리프의 허용 보고 파일에 해당 항목의 대상·근거 위치·결함/조치·미해결을 기록하고, 자기 산출 전체를 한 차례 확인한 뒤 인계한다. 적용되지 않는 항목은 이유를 적는다. 발견한 결함은 가능한 범위에서 한 번에 모아 고친 뒤 변경된 산출을 다시 확인한다. 이 점검은 기존 독립 감사·실제 화면/PDF 검토·발행 게이트와 수정 횟수 계약을 대체하거나 늘리지 않는다.

- **원문과 계산:** 수치 예제와 주요 유도마다 원본 페이지/그림, 각 소자의 값·단위, 입출력 정의, 명시 조건과 추가 가정, 재현한 결과를 서로 대조한다. 원문과 계산이 다르면 양쪽과 가정을 구분해 기록하고 불확실한 것을 원문 사실로 단정하지 않는다. 전달함수 계수와 근사는 가지 전류/KCL 또는 독립 계산·단위·극한으로 검토한다. 반올림과 근사 기호도 확인한다.
- **회로와 화면:** 필요한 측정 회로가 해당 풀이 단계에 있는지 확인한다. 모든 새 SVG에서 각 도선 끝을 따라 의도된 노드·소자·접지·시험원에 닿는지, 의도된 개방 단자인지 대조하여 부유 선·오해할 커패시터 평행선을 찾는다. 입력 영점과 출력 단락/시험원, 노드와 전압 라벨 색, 라벨 간격 및 소자 기호를 함께 확인한다. 열린 요약과 긴 수식·표는 사용 가능한 실제 화면 폭과 밝은색/어두운색에서 잘림·겹침을 확인한다. PDF 추출에 핵심 회로·조건·계산·답이 남는지, 지원 글리프와 실제 출력 글꼴이 맞는지도 해당 단계에서 대조한다. 실제 도구가 없으면 확인하지 않은 항목을 미실시로 남긴다.
- **선발과 인계:** 브리프의 필수 산출물 전체(선발의 `catalog.json` 포함), 표시 제목의 Fig 번호 금지, 경로·현재 해시·보고서·필요한 `reviews` 근거를 receipt와 일일이 대조한다. 수락 오류는 모두 확인해 한 번에 고치며 없는 파일이나 수행하지 않은 검토를 통과로 적지 않는다.
- **독립 검산:** 검산자에게 전달하기 전 실제로 전달할 입력과 브리프에 명시한 참조를 살펴 문제·그림·필요한 이론 외에 정답·참고 풀이·작성자 설명이 섞이지 않았는지 확인한다. 검산자가 먼저 풀이를 기록한 뒤 조정자가 결과와 비교한다. 답 또는 풀이가 먼저 노출되었다면 그 검산은 무효이며 답을 보지 않은 다른 검산자로 다시 수행한다.
- **화면 탐침:** 작성자와 browser-qa는 인계 전에 `python3 <SKILL>/scripts/layout_probe.py <노트 HTML> --widths 1280,375 --themes light,dark --out <허용 출력>/probe.json`을 실행한다. 1280/375 × 라이트/다크에서 결함 0(수식·요약·표 가로 넘침 0, SVG 라벨과 도선 간격 0.6em 이상)이어야 넘긴다. `data-circuits` 노트는 탐침이 모든 토픽을 넘기며 넘침과 `figure.circuit` 라벨 간격(위치 표시 ㉠은 0.25em)을 재고, 식마다 바로 앞 회로가 다 보이고 식을 가리지 않는지, 앞선 회로가 그 아래로 비집고 나오지 않는지(1280×720 패널 닫힘·열림, 375×667) 확인한다. 그 밖의 그림은 첫 화면만 재므로 라벨 간격을 화면에서 직접 본다. 결과 파일은 보고 근거이며 실제 화면 검토를 대체하지 않는다.
- **반환 전 검증:** 모든 역할은 receipt를 쓴 뒤 `task check --run <RUN> --task <id> --attempt <UUID> --receipt <절대 경로>`를 실행하고 status ok를 확인한 뒤 반환한다. reason이 나오면 고치고 다시 실행한다. 메인의 accept 거부가 되풀이되지 않게 하는 단계다.
- **상태와 중단:** 같은 RUN의 `claim`·`bind`·`accept`·수정·발행 등 상태 변경은 하나가 끝난 뒤 다음 명령을 실행한다. 잠금 충돌 시 기존 명령의 종료 상태를 확인하고 runner 계약에 따라 재개하며 lock 삭제나 상태 수동 변경으로 우회하지 않는다. 브라우저 URL/접근 문제로 못 본 항목은 blocked로 기록하고 사용자가 직접 본 범위와 별도로 남은 검토를 이어간다.

## 짧은 응답과 상세 기록

표의 경로는 산출물 종류다. 실제 허용 출력/보고/감사는 현재 생성 브리프의 `allowed_outputs`, `allowed_output_roots`, `report`, `audit_output`을 단일 기준으로 따른다. 옛 참조의 고정 보고 경로로 쓰기 권한을 늘리지 않는다.

각 역할은 자세한 내용·수식·원문 근거·자기 검사·결함 목록을 자신의 보고 파일에 쓴다. 메인에 반환하는 응답은 **800자 이하**(개행 포함 Python len)로 다음 순서다. 긴 JSON 전문이나 코드 블록을 응답에 붙이지 않는다. 자식 조정자는 모든 leaf 브리프에도 800자 이하 반환 요청을 명시한다.

1. 역할/담당 ID와 상태(`done | needs-fix | blocked`; 자식은 별도 계약의 `ready-for-publish | withheld`).
2. 산출물 및 상세 보고의 절대 경로.
3. 검사 대상 입력/산출의 현재 해시 또는 그 인계 파일 경로.
4. 건수·누락·미해결과 다음 담당; 결함은 심각도·where(topic/section/problem ID)·근거 경로.

짧은 응답의 pass나 일반 작업 인계 기록은 **기존 검사·승인 JSON을 대체하지 않는다**. 검토자는 실제 자료/화면을 확인한 뒤 기존 형식으로 기록한다. 메인은 schema/현재 snapshot·입출력 해시·대상 전체 coverage·미해결·CLI 종료 코드를 확인한다. 렌더 명령의 exit 0만으로 의미·화면 pass를 만들지 않는다.

브라우저/PDF QA는 모든 필요한 화면을 직접 확인한다. 화면·페이지 목록, 테마/폭, 실제 검사 결과, HTML/PDF/overlay 및 증거의 SHA-256을 보고 파일에 남긴다. 공용 브라우저만 있으면 순차 단독 사용하거나 메인에 구체적인 작업 요청을 인계한다. 브라우저가 없는 에이전트가 검사한 것으로 보고하지 않는다.

## 메인의 상태와 발행 경계

- 실행기가 관리하는 `RUN/run-status.json`에는 현재 단계, 역할별 상태/agent ID/브리프/산출/보고 경로, 최초 백업 경로, 현재 manifest·snapshot·노트 해시, 내용 수정 횟수와 **기계/브라우저 공통 수정 횟수**, EXPLAIN_RUN·발행 결과·복구 경로를 저장한다. 긴 내용 대신 경로로 이어진다.
- 명령의 장문 stdout/stderr는 `RUN/work/<역할ID>/` 로그에 저장하고 메인에는 종료 코드·검사 요약·오류 위치만 출력한다. 실패 시 해당 오류 부분을 읽는다. 원본/증거 전체를 터미널에 출력해 인계하지 않는다.
- 메인만 최초 백업·정리, 표시 제목 맵 반영, assemble/MD 변환, 복습노트로의 epe publish/답안 publish, 전체 복구와 최종 검사를 실행한다. RUN 내부 후보/렌더/의미/화면 검토는 위임한다. `RUN/repo`는 쓰기 권한의 예외가 아니다.
- source/manifest/HTML/명세 변경은 관련 작성·감사·화면 검토를 무효화한다. 자식 extract 후 고정 입력이 바뀌면 부모 재검토와 새 EXPLAIN_RUN이다. 스냅샷 교체나 오래된 pass로 통과시키지 않는다.
- 컨텍스트가 압축되거나 담당자가 바뀌면 `status/next`와 필요한 현재 인계/검사 파일을 읽고 이어간다. 이미 끝난 원문 독해·작성·검토 대화를 다시 펼치지 않는다. 최종 완료 여부는 메인이 실제 발행 게이트/최종 검사와 복구 상태로 판정한다.

작업 수락·수정·release·기계 실행·복구는 [runner 명령](runner-contract.md)으로만 기록한다. run-status를 수기 갱신하지 않는다. 실제 audit_output은 브리프 경로를 따르고 이전 작성자의 감사를 덮지 않는다.

MD 변환 뒤 `standalone-svg-qa`는 brief.targets의 SVG 절대 경로를 각각 독립 문서로 연다. 실제 폰트 face와 회로 화면을 검사한 경로만 counts.targets로 제출하고 모든 지정 svg_screenshots PNG와 report.json/report.md를 남긴다. 부모 HTML 브라우저 검토와 별도 필수 단계이며, 실제 변환이 SVG 0개인 경우만 runner가 생략한다.
