# 전자회로2 PDF 문제풀이 영상 설계

상태: 2026-10-07 사용자가 이전 채팅의 추천안을 모두 채택했다. 결정 #9는 **문제별 MP4 한 개씩**으로 확정했다. Native 방식의 스킬 구현과 개발 검증을 완료했다. 실제 Aoede 음성은 미검증이다.

## 목적과 호출

프로젝트 로컬 스킬 `ec2-solution-video`는 복습문제의 문제지·답안 PDF를 화면 원본으로 사용한다. 답안에 등장하는 풀이를 중앙 풀이공간의 원래 위치에서 한 글자씩 공개하고, 한국어 음성으로 풀이의 판단 이유를 설명한다. 완성 화면은 답안 원본과 같아야 한다.

호출: `/ec2-solution-video 1002`, `/ec2-solution-video 1002 --problems E10.11,P10.62`, `/ec2-solution-video 0923-1002 --review`. 날짜/범위를 주면 포함된 문항 전체를 원래 순서로 제작한다. 문제 ID를 주면 그 문항만 제작한다. 동일 문항이 여러 날짜에 있으면 범위 내 최초 등장 순서를 유지해 한 번만 제작하고 모든 원자료 대응을 기록한다. 동일 ID의 PDF 풀이가 다르면 자동 중복 제거 대신 충돌을 보고한다.

## 화면과 내용의 필수 원칙

> 문제지·답안 PDF를 화면 원본으로 사용한다. 답안에 등장하는 풀이의 문장·기호·수치·순서·줄바꿈을 보존하며, 중앙 풀이공간의 원래 위치에서 한 글자씩 공개한다.

- 문제지로 문제·조건·구할 것을 확인한다. 이어서 중앙 풀이를 숨긴 답안 페이지로 전환한다. 단계별 판단·작성·확인 후 최종 답을 공개하고, 커서와 가림을 제거해 답안 전체를 보여 준다.
- PDF의 흰 배경·색상·회로도·점 격자를 보존한다. 기존 복습 영상의 다크모드 원칙은 이 스킬에 적용하지 않는다.
- 문제지와 답안지의 회로도 크기와 풀이공간 좌표를 독립적으로 읽는다. 페이지 번호만으로 대응하지 않는다. Hint 부록은 풀이 문항으로 세지 않는다.
- 답안의 완성 배치를 처음부터 고정한다. 타이핑 중 줄바꿈·수식 위치가 움직이지 않는다. 작성한 내용은 계속 남는다.
- 중앙 위 회로도·왼쪽 조건·오른쪽 Hint는 작성 대상에서 제외한다. 긴 풀이와 2단 풀이는 페이지를 확대·이동하며 원래 위치에서 이어 간다.
- 화면의 한글은 완성된 음절 단위로, 수식은 조판된 기호 단위로 나타난다. 분수선·근호선·단계 번호 배경·답 상자는 별도 표시 이벤트로 처리한다. LaTeX 소스를 타이핑하지 않는다.
- 기본 글자 속도는 초당 7글자(권장 조절 범위 6–8글자)다. 문장·수식 끝에는 읽을 시간을 둔다. 공간 문자는 시간이 지나도 새 그림을 만들지 않는다.
- 현재 작성 위치의 커서는 완료 후 사라진다. 타이핑 효과음과 배경음은 기본으로 넣지 않는다.
- 임의 시점으로 이동해도 동일한 화면이어야 한다. 실제 시간, 타이머, 무작위 입력에 의존하지 않는다.

## 원자료와 음성

화면과 풀이 내용의 기준은 입력 답안 PDF, 조건의 기준은 문제 PDF다. 대응 workbook MD는 단계 구분과 의미 검토에 활용하고, 필요한 추가 설명만 수업 노트·교재에서 확인한다. MD와 PDF의 풀이가 다르면 최신 MD를 조용히 반영하지 않고 해당 문항을 중단한다. 비교는 수식의 읽기 순서와 의미를 포함하며 문자열 비교만으로 승인하지 않는다.

에이전트가 PDF를 읽고 단계별 대본·글자 순서·회로/계산 검토를 작성한다. 스크립트는 새로운 풀이를 창작하지 않는다. 음성은 판단 이유를 설명하지만 화면에는 답안의 풀이를 그대로 공개한다. 새 계산·새 풀이 경로·임의 오류 수정은 하지 않는다.

- 한국어 Aoede, 1920×1080, 30fps, PCM mono 24kHz를 기본으로 한다.
- 현행 참고 스킬의 기본 공급자 `vertex-ai-express`, 모델 `gemini-2.5-flash-tts`를 설정 스냅샷에 기록한다. 공급자·모델을 자동 대체하지 않는다.
- 영상 길이는 풀이에 맞추며 1–3분을 강제하지 않는다. 예산 상한은 기본 없음이다. 요청 전체의 사용량을 하나의 ledger에 기록하고, 명시적 예산이 있으면 기존 예산 규칙을 따른다.
- 음성은 짧은 판단·계산 단위로 생성하고 실제 샘플 수로 시간을 확정한다. 글자가 많으면 발화를 나누거나 작성·읽기 시간을 늘린다. 단어별 실제 타임스탬프를 얻었다고 주장하지 않는다.
- 하드 자막은 Pretendard Bold, 흰 글자와 검정 약 70% 불투명 박스를 사용한다. PDF 바깥 하단 여백에 배치한다.

## 구현 접근과 검증 게이트

채택 방식은 원본 PDF의 글자별 공개다. PDF를 SVG로 내보내고 원래 글자의 윤곽·좌표·클립·변환·그림을 유지한 채 개별 글자/풀이 도형의 표시만 제어한다. 원본 문장을 HTML·KaTeX로 재조판하지 않는다.

2026-10-07 읽기 전용 조사에서 시스템 Python의 PyMuPDF 1.27.2.3을 확인했다. `page.get_svg_image(text_as_path=True)`는 1002 답안 2/3/8쪽에 각각 602/701/1339개의 `data-text`가 있는 SVG `use` 요소를 내보냈다. 글자별 도형을 얻을 수 있음을 확인했지만, 표시 제어·원본 일치·HyperFrames 렌더는 아직 시험하지 않았다. 이 첫 게이트를 통과하기 전 유료 TTS를 실행하지 않는다.

SVG의 표시 전후 비교는 같은 브라우저·뷰포트·도구 버전에서 한다. 완성 상태는 수정하지 않은 원본 SVG 렌더와 픽셀 단위로 같아야 한다. 별도로 원본 PDF의 네이티브 렌더와 SVG의 시각적 충실도를 확인한다. 서로 다른 렌더러의 안티앨리어싱 차이를 원본 일치 실패나 완벽한 일치로 혼동하지 않는다.

전체 글자 공개를 끝낸 후 원본 그림으로 바꿔 결함을 감추지 않는다. 최종 교체 이전의 조립 결과 자체가 원본 비교를 통과해야 한다. 추출할 수 없는 글자·수식·풀이 이미지나 해석 불가능한 클립은 해당 문항을 미완료로 보고한다.

## 파이프라인과 실패 처리

원자료 동결 → 페이지/영역 대응 작성 → 글자/도형 추출 및 첫 게이트 → 대본·내용 검토 → TTS → 실측 타이밍 → HyperFrames 조립 → 장면별 렌더 → 하드 자막 → 최종 검증 → 게시 순으로 진행한다.

`--review`일 때만 전체 선정 문항과 장면·대본을 묶어 한 번 검토받는다. 기본 제작에서는 에이전트의 내용 검토 후 자동 진행한다. 스캔·글자 좌표 오류·문항 모호성·자료 충돌은 해당 문항만 중단하며, 성공한 음성·영상은 보존한다. 재개는 동결 입력·설정·도구 지문과 산출물 해시를 확인하고 처음 무효가 된 단계부터 수행한다.

기존 `ec2-review-video`의 TTS·cache·budget처럼 화면에 독립적인 기능만 명시적 adapter로 재사용한다. 기존 렌더·조립·검증·자막 함수는 다크모드 및 노트 템플릿에 묶여 있으므로 PDF 전용으로 구현한다. 기존 스킬·노트·PDF·영상은 수정하지 않는다.

## 수용 조건

- 시작 시 중앙 풀이가 미리 보이지 않고, 작성 대상 밖의 원본 내용과 점 격자가 보존된다.
- 다음 글자의 조각이 새어 나오지 않으며, 한글·수식의 표시 순서가 승인된 단계 순서와 같다.
- 완료 전 조립 결과와 수정하지 않은 원본 SVG가 같은 렌더 조건에서 픽셀 단위로 같다.
- 분수선·근호선·첨자·부호·단위 및 2단 풀이가 누락되지 않는다.
- 되감기와 임의 시점 이동에 따른 화면이 동일하다. 짧은 음성 때문에 글자 표시를 과속하지 않는다.
- 모든 장면의 편집 소스에 HyperFrames 검사를 수행한다. 최종 하드 자막 MP4의 가독성·자막 겹침·음성·전체 디코드·길이 동기화를 검사한다.
- 사용자에게 검증 범위를 구분해 보고한다. 최종 자막본까지 통과한 파일만 게시하고 전체 성공일 때만 요청의 latest를 갱신한다.

실제 대표 문항: 1002 E10.11(한글·수식), E10.13(문제/답안의 회로도 크기 변경), 2021-1_중간-Q3(긴 2단 풀이). fake API/로컬 PCM으로 개발 검증하고, 실제 음성 청취를 수행한 범위는 별도로 기록한다.

## 출력과 범위

문제별 MP4 한 개씩 제작한다. 자연스러운 한국어 제목에 문항 ID를 포함한다. 최종 파일은 하드 자막본이며 `_자막` 접미사를 쓰지 않는다.

```text
문제풀이영상/<날짜 또는 범위>/
├── <문항 ID — 자연스러운 제목>.mp4
└── <날짜 또는 범위>_제작자료/
    ├── latest.json
    └── 실행/<실행ID>/
        ├── 원본 PDF·출처·공용 사용량·batch.json
        └── videos/<안전한 문항 키>/
            └── 대본·글자·타이밍·SVG·HTML·음성·자막·검증
```

같은 요청의 이전 결과와 충돌 파일은 덮어쓰지 않는다. 검증 후 이전버전을 제작자료에 보존하고 새 파일을 게시한다. 게시 목록은 실제 남은 자막본의 경로·크기·SHA256을 기록한다. 캐시용 마스터는 제작자료 안에 보존하며 날짜 폴더에는 최종 MP4와 제작자료 폴더만 둔다.

이번 범위는 새 스킬과 실행 도우미다. 새 문제·풀이 창작, 손글씨/실제 키보드 녹화, 스캔 PDF의 완전 자동 처리, 목소리만 교체하는 전용 기능, 기존 영상 스킬의 리팩터링은 제외한다. 계획을 쓰는 이번 턴에는 실행 코드·의존성·영상·Git 커밋을 생성하지 않는다.
