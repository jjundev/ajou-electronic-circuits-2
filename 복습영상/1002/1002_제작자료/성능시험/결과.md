# 전자회로2 복습 영상 렌더링 설정 검증

현재 장비 Apple M5 / 물리 CPU10 / RAM16GiB. HyperFrames0.8.137, FFmpeg9.0.2 고정. workers6 / CPU 인코딩 / browser GPU auto / fast capture false / delivery1080p30 적용. 실제 Chrome 로그는 ANGLE Metal Apple M5 hardware GPU와 screenshot capture를 확인했다. 장면은 순서대로 실행한다. GPU 인코딩은 사용하지 않는다.

## 실측

60초/2장면/1800프레임의 기존 MOS 차동쌍 fixture를 복습 템플릿·Pretendard·KaTeX·GSAP으로 실제 조립/렌더했다. 음성은 220Hz 합성 PCM 시험 신호이며 유료 TTS는 호출하지 않았다. 시간은 render_parts + mux_with_receipt(전체 decode/dark 검사 포함), 추가 verify/프레임 비교/자막 굽기/소스 검사/브라우저 검사는 시간에서 제외했다.

| 장면 조건 | workers2 | workers6 | 변화 |
|---|---:|---:|---:|
| 24초 motion, 최종 실패 처리 코드 | 48.71s | 29.84s | 38.7% 단축 |
| 0.6초 motion + 대부분 정지, 글꼴 보정 후 | 26.73s | 28.80s | 7.7% 느림 |

동적 장면은 초기 코드에서도 빠르지만 수식 첫 프레임의 글꼴 차이로 엄격한 hash 비교에 실패했다. 그 실패 결과도 initial-motion.log/20261010-review-policy-motion24에 보존했다. document.fonts.ready 뒤에 타임라인을 등록하도록 보정한 뒤 동적 최종 비교는 1/2/6 모두 일치했고, 실패 처리 보정 후2/6을 다시 실행해 모두 일치했다. 초기 정지 시험6개 속도 저하 결과도 보존했다. 정지 프레임 재사용 로그가 원인을 뒷받침한다. 24초 motion은 stress 시험으로 연장한 조건이며 실제 수업 나레이션의 전체 제작 시간으로 일반화하지 않는다.

## 검증 결과

- 동적 최종 master SHA256: `65a98a57ffe04a1b52660674ec3f20cabbaed4cac3d709434dbc853254b03136` (2/6 동일).
- 1800개 모든 decoded frame hash, PCM WAV, AAC 및 MP4 byte hash 모두 동일. 1080p30/mono24k/전체 decode/자막 굽기/AV 동기화 통과.
- HF 실제 편집 소스 검사 통과. 브라우저2장면×OS light/dark×7시점=28개 검사씩 정지/동적 모두 통과(글꼴, 다크 토큰, 넘침, 수식, 최종 전류비).
- 자막 영상 정지 frame1/59, 동적 frame15/31 및 수식 확대를 직접 확인했다. 영상 내용/발화 의미에 대한 새 교육용 승인은 아니다.
- fixture110파일 hash 불변. 실제 workers 실행폴더도 정지1/2/6과 동적2/6 각각 원본110파일 hash를 수동 비교해 불변 확인(`worker-source-hashes-verification.json`).
- Python102 tests, 실패0. 실제 분리 세션 자식 프로세스 timeout, 장면/master 영수증 저장 실패, 교체 중단, 복구 실패/재시도 방지 포함. 글꼴 준비 전 등록 방지와 기존 RUN의 화면 코드 변경 감지도 테스트.

## 적용 및 재개

CLI render/revoice `--render-workers 1..6` > source/render-options.json > 장비 기본값. 이 M5는6, 미검증 장비는2. 짧고 정지 화면이 많은 RUN은 `--render-workers 2`로 비교한다. 옵션 변경은 render 이후만 다시 검사한다. 이번 글꼴 준비 보정 때문에 이전 코드의 RUN은 assemble을 한 번 다시 해야 하지만 TTS/음성 캐시는 유지한다.

실패 시 영상·영수증 쌍을 복구하며 실패한 복구 사본은 `.rollback`에 보존하고 재시도로 덮어쓰지 않는다. timeout/중단은 렌더 프로세스 트리를 종료하고 시도별 pending을 정리한다. Windows taskkill 경로는 현재 macOS에서 실행하지 않았다.

## 결정 및 보류

- 이미 승인한 같은 정책/Native 방법으로 진행했다. 재승인하지 않은 비용: 같은 정책을 적용하는 범위로 한정.
- 완성된 EC2 복습 RUN이 없어 기존 회로 fixture/합성 PCM으로 시험했다. 실제 강의/Aoede 전체 처리 속도와 음성 품질은 별도 시험이 필요하다.
- 비교를 위해 도구 버전을 고정했다. 다른 버전의 동작/개선은 검증하지 않았다.
- 모든 영상에서 빨라진다는 가설은 버리고 정지/동적 실측을 모두 보존했다. 실제 과제별 최적 작업자 수는 달라질 수 있다.
- 글꼴 초기화 문제를 보정하고 기존 RUN에 reassemble을 요구했다. 비용은 화면 재조립이며 음성은 유지한다. 두 번의 RAF 대기는 pinned runtime에서 지연되어 쓰지 않았다.
- 조건부 커밋 요청을 지키기 위해 staged diff로 한 번의 읽기 전용 리뷰를 진행하고, 최종 검증 후 커밋한다. 리뷰는 최종 영상 직접 확인을 맡지 않았고 작성자가 완료했다. 독립 시각 검토는 추가하지 않았다.
- 경미한 보류: 성능시험 스크립트 자체는 fixture hash만 자동 검사한다. 실제 worker 입력 hash는 이번 실행에서 수동 검증했고, 스크립트 자동화 확장은 보류했다.
