# 복습 영상 작업자 자동 선택 검증

전자회로2 복습 영상 기본을 schema2 workers=auto로 바꾸었다. 장면별 작성한 동작의 도착 속성 값이 시작값과 다른 구간을 시간상 합집합으로 센다. 겹친 동작은 중복 계산하지 않고, 시작값만 설정하는 속성은 지속적인 움직임으로 세지 않는다.

현재 검증된 Apple M5 / 물리 CPU10 / RAM16GiB 이상에서 장면900프레임(30초) 이상이고 동작 비중이50%를 넘으면6개, 그 외2개. 짧은 장면·정보 누락·미검증 장비는2개. 존재하지만 깨진 JSON은 다른 파일의 누락으로 숨기지 않는다. 이 기준은 작성된 동작 메타데이터에 따른 휴리스틱이며 픽셀 분석/모든 영상 최적값을 보장하지 않는다. CPU 인코딩·브라우저 GPUauto·fast capture false·delivery1080p30·순차 장면 처리는 유지한다.

## 실제 렌더링

기존60초/2장면 MOS 차동쌍 fixture를 재사용하고220Hz 합성PCM으로 시험했다. HyperFrames0.8.137, FFmpeg9.0.2 고정. 동작 비중2%→2개,80%→6개; 혼합은2/6이다. 실제 영수증/명령에서 선택을 확인했고 고정 설정 기준 MP4와 byte SHA가 모두 같다.

| 장면 조건 | 자동 선택 | 렌더·합성 시간 | 기준 영상 |
|---|---|---:|---|
| static | [2, 2] | 15.70s | 동일 |
| dynamic | [6, 6] | 29.19s | 동일 |
| mixed | [2, 6] | 22.10s | 동일 |

- 각 영상1800프레임,1080p30/mono24k/전체 decode/AVsync 통과. MP4 byte 동등하므로 영상/AAC도 기준과 동일하며 PCM hash도 동일하다.
- 실제 실행폴더의 원본111파일을 전후 자동 hash 비교해 불변. 원래 두 fixture110파일도 불변.
- 혼합 영상 HF실제 소스 검사·자막굽기·브라우저28시점 검사 통과. frame31을 직접 확인했다. 의미/발화 품질 승인이나 실제 Aoede 전체 제작 시간 검증은 아니다.
- 자동 모드 캐시 재호출: 두 장면 재사용, 실제 render호출0, MP4/영수증4파일 mtime 불변.
- Python112개 테스트, 실패0. 독립 리뷰가 발견한 partial-property 오판과 누락 파일이 손상 파일을 가리는 경우를 실패 테스트로 재현해 모두 보정한 뒤 실제 시험을 다시 진행했다. 보류한 발견 없음.

## 설정/재개

CLI --render-workers auto|1..6 > schema2 저장값 > auto 기본값. 새 숫자값은 수동 고정으로 유지한다. 이전 schema1은 자동 기본값과 수동 지정 출처를 구분할 수 없어 이번 자동 선택 요청에 맞춰 auto로 전환한다. 이전 숫자 고정이 필요하면 CLI에서 다시 지정한다. load/분석/resume은 파일을 쓰지 않으며 render/revoice가 선택 설정을 저장한다. 정책/설정 변경은 render 이후만 무효화하고 기존 TTS/화면 조립을 유지한다. 이전 글꼴 준비 보정 전 RUN만 예전 안내대로 reassemble이 필요하다.

판단 경계:50%/30초는 보수적 기준이며 중간 비중·다른 그래픽의 최적점을 실측한 것은 아니다. 더 정확한 최적화가 필요하면 별도 대표 수업으로 측정한다. 소스/compiled HTML 대응은 기존 composition 재개 검사가 책임지고, 다른 장비/다른 HF버전/실제 Aoede 품질/Windows 프로세스 종료는 이번에 새로 검증하지 않았다.
