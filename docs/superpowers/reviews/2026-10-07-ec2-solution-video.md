## 독립 리뷰와 수정

Critical 0, Important 4, Minor 2를 보고받았다. Minor 두 개는 실제 사용자 동작에 영향을 주므로 Important로 재평가했다. 재리뷰를 추가하지 않고 한 번의 수정 패스에서 각 결함을 재현하는 실패 테스트→구현→통과와 전체 회귀 검사를 수행했다.

## 검증 범위

- 원본 SVG와 공개 완료 결과: 1002 E10.11/E10.13/2021-1_중간-Q3의 pixel_diff=0, non_target_diff=0, hidden_leaks=0.
- actual glyph 공개 수 403/417/718, 작성 도형 12/13/18. 원본 한글·수식·그림·격자·2단 풀이 보존을 empty/partial/complete 및 native PNG와 대조했다.
- HyperFrames 0.8.72의 check와 전체 영상 렌더, 1920×1080/30fps/24kHz PCM provenance, 실제 자막본 전체 디코드·길이 동기화·자막 하단 영역을 검사했다.
- 수정된 확대의 세 문항 전체 자막 영상: 2167/2260/3765프레임, 약72.23/75.33/125.50초. 실제 최종 MP4 SHA256을 acceptance.json에 기록했다.
- 최종37개 테스트(실제 PDF 수용 포함), 스킬/YAML 유효성, 새 파일 공백 검사를 통과했다. 기존 81개 테스트는 설치된 ffmpeg-full을 명령 단위 PATH에 지정하여 통과했다. 기본 ffmpeg는 libass가 없어 기존 자막 테스트 하나가 실패하며, 새 스킬은 자막 필터 지원 바이너리를 확인해 설치된 ffmpeg-full을 선택한다. 전역 PATH를 바꾸지 않았다.
- 실제 `0923-1002` 발견 결과는31문항, 입력 오류0이었다. 검토 지문, 승인 변경, 부분 음성 실패/캐시, seek, overlapping subscript/clip/shared defs, 변조·게시 이동 실패/rollback을 검사했다.
- 테스트 음성은 로컬 PCM이며 유료 호출0. 실제 Aoede 품질·발음·청취와 실제 서비스 API 성공은 **미검증**이다. fake PCM을 production publish가 거부하는 것도 확인했다.

## 실행 중 판단과 남는 한계

1. 현재 checkout의 `codex/ec2-solution-video` 브랜치에서 새 파일만 작성했다. 별도 worktree 동의가 없었고 구현은 승인되어 있었기 때문이다. 동시에 다른 작업이 같은 checkout을 수정하면 파일 수준 격리는 없다.
2. 커밋 권한이 없어 git 기록을 대신할 scratch ledger와 검증 산출물을 보존했다. `.superpowers`를 명시적으로 청소하면 그 증거는 사라질 수 있다.
3. 기본 FFmpeg의 기존 자막 오류는 참고 스킬을 수정하지 않고 별도로 기록했다. ffmpeg-full이 없는 환경은 EC2_FFMPEG로 libass 지원 바이너리를 제공해야 한다.
4. 무료 PCM 수용 검사는 기술 미디어와 production 게시 거부를 확인한다. 실제 음성 청취 승인은 가짜로 생성하지 않으며 실제 제작 요청 전까지 live 통합은 미확인이다.
5. 확대의 26px 기준은 단계 본문의 대표 글자 높이에 적용했다. 등호의 얇은 잉크 높이가 지나친 확대를 유발했기 때문이다. 원래 비율을 유지한 작은 첨자는26px보다 작을 수 있고 명시적 카메라로 확인할 수 있다.
6. 리뷰어가 Minor로 표시한 상태/제목 문제도 기능 오류로 판단해 수정했다. 그렇지 않으면 성공한 게시가 계속 대기하거나 제목 설정이 모든 파일에서 무시됐을 것이다.
7. 리뷰어가 판단을 유보한 실제 음성은 미검증으로 유지했다. 최종 확대 영상의 시각 판단은 렌더 완료 후 구현자가 직접 수행했다. 독립 코드 리뷰와 최종 시각 검토의 주체는 다르다.

미룬 Minor 항목은 없다. 실제 음성 제작은 이번 스킬 구현 요청에 포함하지 않았다.
