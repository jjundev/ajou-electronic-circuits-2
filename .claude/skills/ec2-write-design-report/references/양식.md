출처: `from_the_past/설계+과제+1.pdf` (선배 제출본) 분석, `docs/superpowers/specs/2026-10-10-ec2-report-skills-design.md` §보고서 양식.

## 구성 순서

헤딩·목차·여백은 논회실 `.claude/보고서서식.md` §목차 블록·§헤딩·§여백 블록 을 따른다.

1. 제목 줄 `# 설계 과제 N: <회로 이름>` — 노션 업로드 때 떼어지고 페이지 제목(`전자회로2 설계과제N 보고서`, 판본 번호 없음)이 대신한다. 그 다음 줄에 `<table_of_contents color="gray"/>`, 빈 줄, `<empty-block/>` 하나를 두고 첫 대절을 시작한다 (노션은 본문 첫 블록이 `#` 헤딩이면 그 헤딩을 지우므로 목차 블록이 앞을 막는다).
2. 대절 `# 설계 조건`: 문제 조건을 과제 원문 그대로 옮긴다 (전원·L·µCox·λ·V_TH, "주어지지 않은 parameter …" 단서까지). 그 아래 `![](figs/01_<파일>.png)` — 과제 그림은 이미지 안에 이미 "그림 1. …" 캡션이 있으므로 alt 를 비운다 (노션이 alt 를 이미지 캡션으로 달아 캡션이 두 번 나온다, 2026-10-11 설계과제1) — 과제 폴더의 `figures/` 원본을 `report/figs/` 로 복사해 쓴다.
3. 대절 `# Design Problem` 과 `# Spice Problem`. 대절 헤딩에는 번호(`1.`·`2.`)도, 과제 원문의 "(설계과정 필수)" 같은 단서도 붙이지 않는다 (2026-10-11 설계과제1 v2 에서 사용자가 노션에서 직접 지웠다). 본문에서 다른 문항을 가리킬 때도 `2-(a)` 같은 번호 대신 `Spice Problem (a)`, `Design Problem (a)` 처럼 대절 이름으로 쓴다.
4. 소문항마다 소절 `## (a) <짧은 이름>` (예: `## (a) 회로도와 DC 동작점`). 그 아래 문제 문장을 원문 그대로 굵게 한 줄 `**(a) <문제 문장>**`, 빈 줄, 그 다음 풀이 문단을 표시 없이 바로 시작한다.
   - **이모지 기호 금지.** `▶`·`✔`·`⭐`·`↔` 처럼 PDF 에서 컬러 이모지로 보이는 문자는 쓰지 않는다 (2026-10-11 설계과제1: `**▶**` 와 `✔` 가 BB 에서 ▶️·✔️ 로 보였다). 만족 표시는 목록·문장 끝 ` (만족)`, 표 셀은 `saturation` 처럼 글만 쓴다. `→`, `①`, `−`, `°` 는 보통 글자라 쓸 수 있다. 검사기(`check.EMOJI`)가 error 로 막는다.
5. 헤딩은 `#`·`##` 두 단계뿐이다. 풀이 안의 단계 제목은 `**① 단계 이름**` 처럼 굵은 문단으로 쓴다.
6. 여백: 대절 앞 `<empty-block/>` 2개(목차 바로 뒤 첫 대절은 1개), 소절 앞 1개. 대절 헤딩 바로 다음 첫 소절은 여백 없이 붙인다. 대절 헤딩 뒤에 산문이 오면 그 뒤 첫 소절 앞에 1개.

## Design Problem 에 들어갈 것

- (a) 반쪽 회로 이득식 유도: $A_v = G_m R_{out}$, $R_{out}$ 의 각 성분, **$G_m$ 정확식을 직접 유도** (근사 $G_m \approx g_{m1}$ 만 쓰면 감점 이력 있음), 그 결과로 이득을 정하는 설계 변수.
- (a) 전력 조건으로 전류 배분, 전력 계산식에 숫자 대입.
- (a) 노드 전압(headroom) 분배 표.
- (a) 목표 이득을 만족하는 설계 변수 값과 소신호 파라미터 표.
- (b) $I_D$ 식을 W 로 푼 식 → MOSFET 별 W 계산식 표 (열: MOSFET · 식(숫자 대입) · W/L · W).
- (b) 요약 표: MOSFET 별 $\lvert V_{GS}\rvert$ · $\lvert V_{DS}\rvert$ · W/L · W, 바이어스 전압 표.
- (b) MOSFET 마다 saturation 부등식 ($\lvert V_{DS}\rvert \ge \lvert V_{GS}\rvert - V_{TH}$) 을 숫자로.

## Spice Problem 에 들어갈 것

- (a) `![LTspice 회로도 (.op 라벨, 학번·이름 표기)](figs/02_schematic.png)` 자리, 노드 전압 표, 전류·전력. 손계산과 다른 바이어스 조정이 있으면 이유와 함께.
- (b) SPICE 동작점으로 만든 saturation 표 (손계산 표와 **같은 MOSFET 순서**) + 부등식.
- (c) 입력 신호 식, 파형 그림, 파형에서 읽은 이득.
- (d) 주파수 응답 **크기·위상** 그림 (감점 이력 있음), 손계산·AC·Transient 비교 표, 오차 % 와 10 % 판정, 번호 매긴 원인.

## 서식 (노션 업로드 규칙, `scripts/ec2_report/check.py` 가 검사)

- 산문 문단은 줄바꿈 없이 한 줄. 문단 사이에는 빈 줄.
- 표는 11열 이하, 행마다 셀 수가 헤더와 같게. 셀 안 절댓값은 `|` 대신 `\lvert … \rvert`.
- 표 두 개를 빈 줄만 사이에 두고 붙이지 않는다. 사이에 문장을 한 줄 넣는다. 노션이 두 표를 하나로 합치고 가운데에 `---` 행을 남긴다 (2026-11-08 설계과제2 Spice (a) 노드 전압 표와 전류 표). 검사기가 error 로 막는다.
- 수식은 인라인 `$…$`, 블록은 단독 줄 `$$` 로 여닫는다. 신호 이름·수식을 백틱으로 감싸지 않는다.
- 헤딩은 `#`·`##` 만 쓰고, 헤딩 안에 백틱·수식을 넣지 않는다. 열 0 에 HTML 태그(노션 블록 태그 `table_of_contents`·`empty-block` 은 예외), 각주 금지.
- 그림은 상대경로 자리만 둔다. 이미지는 사용자가 노션에서 직접 넣는다.
- **그림은 전부 `report/figs/` 한 폴더에 모은다.** 본문의 그림 경로는 모두 `figs/<파일>` 이고, `figs/` 에는 본문이 쓰는 그림만 둔다 (2026-10-11 설계과제1 에서 그림이 `figures/` 와 `report/figs/` 로 흩어지고 쓰지 않는 `ac_gain.png` 까지 섞여, 노션에 넣을 때 사용자가 두 폴더를 뒤져야 했다). `figs/` 밖 경로는 검사기가 error, 쓰지 않는 그림은 warn 으로 잡는다. sim 스크립트가 보고서에 안 들어갈 그래프를 만들면 `figs/` 가 아닌 곳에 저장한다.
- **그림 파일 이름 앞에 순서 번호를 붙인다: `figs/NN_<이름>.png`.** `NN` 은 본문에 그림이 나오는 순서(= 노션에 넣는 순서)를 두 자리로 쓴 것이다 (`01_mos_diff_amp.png`, `02_schematic.png`, `03_tran_1MHz.png`, `04_ac_bode.png`). 그림을 끼워 넣거나 순서를 바꾸면 뒤 번호를 모두 다시 매기고 sim 스크립트의 저장 이름도 같이 고친다. 번호가 본문 순서와 어긋나면 검사기가 error 로 막는다.
- 모든 수치는 `sim/` 산출물(op.txt, ngspice 출력, post.py 출력)에서 가져온다.
- AI 관련 언급을 어디에도 쓰지 않는다.
